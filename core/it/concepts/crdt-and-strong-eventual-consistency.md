하나의 질문: **레플리카가 조율 없이 각자 진행해 갈라진 뒤에도, 사람이 개입하지 않고 같은
유효한 상태로 합쳐지게 하려면 데이터 구조가 무엇을 만족해야 하는가.**

## 최종 일관성과 강한 일관성 사이

- 중간 지대의 정의 — **우리는 선형성과 직렬성 같은 여러 강한 일관성 모델과, 약한 일관성의 한
  형태인 최종 일관성을 논했다. 둘 사이의 가능한 중간 지대이면서 두 모델의 이점을 얼마간 제공하는
  것이 강한 최종 일관성(strong eventual consistency)이다. 이 모델 아래에서 갱신은 서버에 늦게
  또는 순서 없이 전파되는 것이 허용되지만, 모든 갱신이 마침내 대상 노드에 전파되면 그것들 사이의
  충돌이 해소되고 병합되어 같은 유효한 상태를 낼 수 있다** (11장, p.238).[^petrov2019]
- 어떻게 얻는가 — **어떤 조건 아래에서 우리는 연산이 추가 상태를 보존하도록 허용함으로써 일관성
  요구를 완화할 수 있고, 그 추가 상태는 갈라진 상태들이 실행 뒤에 화해(다시 말해 병합)될 수 있게
  한다. 그런 접근의 가장 저명한 예 중 하나가 CRDT(Conflict-Free Replicated Data Types)이며,
  예컨대 Redis에 구현돼 있다** (11장, p.238).[^petrov2019]

## CRDT란 무엇인가

- 정의 — **CRDT는 충돌의 존재를 원천 배제하고 이 데이터 타입에 대한 연산이 결과를 바꾸지 않으면서
  어느 순서로든 적용될 수 있게 하는 특수화된 데이터 구조다. 이 성질은 분산 시스템에서 극히 유용할
  수 있다. 예컨대 충돌 없는 복제 카운터를 쓰는 다중 노드 시스템에서는 네트워크 파티션 때문에 서로
  통신할 수 없더라도 각 노드에서 독립적으로 카운터 값을 증가시킬 수 있다. 통신이 복구되는 즉시
  모든 노드의 결과가 화해될 수 있고, 파티션 동안 적용된 연산 중 어느 것도 유실되지 않는다** (11장,
  p.238).[^petrov2019]
- 왜 최종 일관성 시스템에 맞는가 — **이는 CRDT를 최종 일관성 시스템에서 유용하게 만든다. 그런
  시스템에서는 레플리카 상태가 일시적으로 갈라지는 것이 허용되기 때문이다. 레플리카는 다른 노드와
  사전 동기화 없이 로컬에서 연산을 실행할 수 있고, 연산은 결국 다른 모든 레플리카에 잠재적으로
  순서 없이 전파된다. CRDT는 우리가 로컬 개별 상태나 연산 계열로부터 완전한 시스템 상태를 재구성할
  수 있게 해 준다** (11장, p.238).[^petrov2019]

## 연산 기반 CRDT의 세 조건

- **CRDT의 가장 단순한 예는 연산 기반(operation-based) CmRDT(Commutative Replicated Data
  Types)다. CmRDT가 동작하려면 허용된 연산이 다음을 만족해야 한다** (11장,
  p.238):[^petrov2019]
  - **부작용 없음(Side-effect free)** — **그 적용이 시스템 상태를 바꾸지 않는다.**
  - **가환(Commutative)** — **인자 순서가 문제되지 않는다. `x • y = y • x`, 다시 말해 `x`를
    `y`에 병합하든 `y`를 `x`에 병합하든 상관없다.**
    - 기호 이름 병기: `x • y = y • x`는 **원소 x와 원소 y의 병합 결과가 순서와 무관하게 같다**는
      뜻이다.
  - **인과 순서(Causally ordered)** — **그 성공적 전달은 선행 조건에 의존하며, 그 조건은 연산을
    적용할 수 있는 상태에 시스템이 도달했음을 보장한다.**

## 증가 전용 카운터

- 구조 — **예컨대 우리는 증가 전용 카운터(grow-only counter)를 구현할 수 있다. 각 서버는 다른 모든
  참여자에게서 온 마지막으로 알려진 카운터 갱신으로 이뤄진 상태 벡터를 0으로 초기화해 들고 있을 수
  있다. 각 서버는 벡터에서 자기 값만 수정하는 것이 허용된다. 갱신이 전파되면 함수
  `merge(state1, state2)`가 두 서버의 상태를 병합한다** (11장, p.239).[^petrov2019]
- 예 — **서버 셋의 상태 벡터가 각각 `[0, 0, 0]`으로 초기화돼 있다고 하자. 첫째와 셋째 노드의
  카운터를 갱신하면 상태는 각각 `[1, 0, 0]`, `[0, 0, 0]`, `[0, 0, 1]`로 바뀐다. 갱신이 전파되면
  우리는 병합 함수로 각 슬롯의 최댓값을 골라 결과를 결합한다.** 예컨대
  `merge([1, 0, 0], [0, 0, 1]) = [1, 0, 1]`이고 `merge([0, 0, 0], [1, 0, 0]) =
  [1, 0, 0]`이다 (11장, p.239).[^petrov2019]
- 값 읽기 — **현재 벡터 상태를 판정하려면 모든 슬롯의 값 합을 계산한다. `sum([1, 0, 1]) = 2`다.
  병합 함수는 가환적이다. 서버가 자기 값만 갱신하는 것이 허용되고 이 값들은 독립적이므로 추가
  조율이 필요 없다** (11장, p.239).[^petrov2019]

## 증감 카운터와 슈퍼피어

- **증가와 감소를 둘 다 지원하는 PN 카운터(Positive-Negative-Counter, PN-Counter)를 만드는 것이
  가능하다. 벡터 둘로 이뤄진 페이로드를 쓰면 된다 — 노드가 증가에 쓰는 `P`와, 감소를 저장하는
  `N`이다. 더 큰 시스템에서는 거대한 벡터의 전파를 피하기 위해 슈퍼피어(super-peer)를 쓸 수 있다.
  슈퍼피어는 카운터 상태를 복제하고 끊임없는 피어 투 피어 잡담을 피하는 데 도움을 준다** (11장,
  p.239).[^petrov2019]

## 레지스터

- 최종 쓰기 승리 — **값을 저장하고 복제하는 데 우리는 레지스터를 쓸 수 있다. 레지스터의 가장 단순한
  판은 최종 쓰기 승리 레지스터(last-write-wins register, LWW register)로, 충돌 해소를 위해 각 값에
  붙은 유일하고 전역적으로 순서 지어진 타임스탬프를 저장한다. 충돌하는 쓰기의 경우 우리는 더 큰
  타임스탬프를 가진 것만 보존한다. 여기서 병합 연산(가장 큰 타임스탬프를 가진 값을 고르는 것)도
  타임스탬프에 의존하므로 가환적이다** (11장, p.239).[^petrov2019]
- 값을 버릴 수 없을 때 — **값이 버려지는 것을 허용할 수 없다면 애플리케이션 고유 병합 로직을
  제공하고 다중값 레지스터(multivalue register)를 쓸 수 있다. 다중값 레지스터는 쓰인 모든 값을
  저장하고 애플리케이션이 올바른 것을 고르도록 허용한다** (11장, p.239).[^petrov2019]

## 집합

- **CRDT의 또 다른 예는 순서 없는 증가 전용 집합(unordered grow-only set, G-Set)이다. 각 노드는
  자기 로컬 상태를 유지하고 거기에 원소를 덧붙일 수 있다. 원소를 더하는 것은 유효한 집합을 만든다.
  집합 둘을 병합하는 것도 가환 연산이다** (11장, p.240).[^petrov2019]
- 삭제를 얹으려면 — **카운터와 비슷하게 우리는 추가와 제거를 둘 다 지원하기 위해 집합 둘을 쓸 수
  있다. 이 경우 우리는 불변식 하나를 보존해야 한다 — 추가 집합에 담긴 값만 제거 집합에 더할 수
  있다. 집합의 현재 상태를 재구성하려면 제거 집합에 담긴 모든 원소를 추가 집합에서 뺀다** (11장,
  p.240).[^petrov2019]

## 더 복잡한 구조

- JSON까지 — **더 복잡한 구조를 결합하는 충돌 없는 타입의 예는 충돌 없는 복제 JSON 데이터
  타입이다. 리스트와 맵 타입을 가진 깊이 중첩된 JSON 문서에 삽입·삭제·대입 같은 수정을 허용한다.
  이 알고리즘은 클라이언트 쪽에서 병합 연산을 수행하고 연산이 특정 순서로 전파될 것을 요구하지
  않는다** (11장, p.240).[^petrov2019]
- 저자의 마무리 — **CRDT가 우리에게 주는 가능성은 꽤 많고, 강한 최종 일관성(Strong Eventual
  Consistency, SEC)을 제공하기 위해 이 개념을 쓰는 데이터 스토어를 앞으로 더 보게 될 것이다. 이는
  내결함성 있는 분산 시스템을 짓는 우리의 도구 무기고에 더할 수 있는 강력한 개념이다** (11장,
  p.240).[^petrov2019]

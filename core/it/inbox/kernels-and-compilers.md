하나의 질문: **모델 코드가 특정 칩에서 실제로 빠르게 도는 일은 어디서 이뤄지는가.**

## 커널이란 무엇인가

- 정의 — **커널(kernel)은 GPU나 TPU 같은 특정 하드웨어 가속기에 최적화된 특화된 코드 조각이다.
  그것은 통상 이 가속기의 성능을 최대화하려고 반복적으로, 흔히 병렬로 실행되어야 하는 계산 집약적
  루틴을 수행하도록 쓰인다** (9장, p.437).[^huyen2025]
- 어디에 쓰이는가 — **행렬 곱, 어텐션 계산, 합성곱 연산을 포함한 흔한 AI 연산은 전부 서로 다른
  하드웨어에서 그 계산을 더 효율적으로 만드는 특화된 커널을 갖는다** (9장, p.437).[^huyen2025]
  - 각주 — **합성곱 연산은 Stable Diffusion 같은 이미지 생성 모델에서 흔히 쓰인다** (9장, p.437 각주
    23).[^huyen2025]

## 커널을 쓰려면 무엇을 알아야 하는가

- **커널을 쓰는 것은 밑에 깔린 하드웨어 구조에 대한 깊은 이해를 요구한다. 여기에는 메모리 계층이
  어떻게 구조화되어 있는지(캐시·전역 메모리·공유 메모리·레지스터 같은)와 데이터가 이 서로 다른 수준
  사이에서 어떻게 접근되고 옮겨지는지에 대한 지식이 포함된다** (9장, p.437).[^huyen2025]
- 언어 — **게다가 커널은 통상 CUDA(NVIDIA GPU용), Triton(맞춤 커널을 쓰려고 OpenAI가 개발한 언어),
  ROCm(AMD GPU용) 같은 더 저수준의 프로그래밍 언어로 쓰인다. 이 언어들은 스레드 관리와 메모리 접근에
  대한 세밀한 통제를 허용하지만, 대부분의 AI 엔지니어에게 친숙한 파이썬 같은 언어보다 배우기가
  어렵기도 하다** (9장, p.437).[^huyen2025]

## 흑마법에서 관심사로

- **이 진입 장벽 때문에 커널을 쓰는 것은 소수가 행하는 흑마법이곤 했다. NVIDIA와 AMD 같은 칩 제조사는
  AI 워크로드에 자기 하드웨어를 효율적으로 만들려고 커널을 쓸 최적화 엔지니어를 고용하고, PyTorch와
  TensorFlow 같은 AI 프레임워크는 서로 다른 가속기에서 자기 프레임워크를 최적화할 커널 엔지니어를
  고용한다** (9장, pp.437–438).[^huyen2025]
- **그러나 추론 최적화에 대한 수요가 늘고 가속기가 편재하면서 더 많은 AI 엔지니어가 커널 쓰기에
  관심을 갖게 되었다. 커널 쓰기에 대한 훌륭한 온라인 튜토리얼이 많다** (9장, p.438).[^huyen2025]

## 속도를 높이는 네 기법

- 저자가 다루는 네 가지다 (9장, p.438):[^huyen2025]
  - **벡터화(Vectorization) — 루프나 중첩 루프가 주어졌을 때 데이터 원소를 한 번에 하나씩 처리하는
    대신 메모리에서 연속된 여러 데이터 원소를 동시에 실행한다. 이는 데이터 I/O 연산을 최소화해
    지연을 줄인다.**
  - **병렬화(Parallelization) — 입력 배열(또는 n차원 배열)을 서로 다른 코어나 스레드에서 동시에
    처리될 수 있는 독립적인 덩어리로 나눠 계산을 빠르게 한다.**
  - **루프 타일링(Loop tiling) — 하드웨어의 메모리 레이아웃과 캐시에 맞게 루프 안의 데이터 접근
    순서를 최적화한다. 이 최적화는 하드웨어 의존적이다. 효율적인 CPU 타일링 패턴이 GPU에서는 잘
    통하지 않을 수 있다.**
  - **연산자 융합(Operator fusion) — 중복된 메모리 접근을 피하려고 여러 연산자를 한 번의 패스로
    합친다. 예컨대 두 루프가 같은 배열 위에서 동작한다면 그것들은 하나로 융합될 수 있어 데이터가
    읽히고 쓰이는 횟수를 줄인다.**
- 넷의 난이도가 같지 않다 — **벡터화·병렬화·루프 타일링은 서로 다른 모델에 걸쳐 널리 적용될 수 있는
  반면, 연산자 융합은 모델의 구체적인 연산자와 구조에 대한 더 깊은 이해를 요구한다. 그 결과 연산자
  융합은 최적화 엔지니어의 더 많은 주의를 요구한다** (9장, p.438).[^huyen2025]

## 하드웨어가 바뀌면 커널도 다시 쓴다

- **커널은 하드웨어 구조에 최적화된다. 이는 새 하드웨어 구조가 도입될 때마다 새 커널이 개발되어야
  한다는 뜻이다. 예컨대 FlashAttention(Dao et al., 2022)은 원래 주로 NVIDIA A100 GPU를 위해
  개발되었다. 나중에 FlashAttention-3가 H100 GPU를 위해 도입되었다(Shah et al., 2024)** (9장,
  p.438).[^huyen2025]

## lowering과 컴파일러

- **모델 스크립트는 그 모델을 실행하는 데 수행되어야 하는 일련의 연산을 명시한다. 이 코드를 GPU 같은
  하드웨어 조각에서 돌리려면 그 하드웨어와 호환되는 언어로 변환되어야 한다. 이 과정을 lowering이라
  부른다. 특정 하드웨어에서 돌도록 코드를 lowering하는 도구를 컴파일러(compiler)라 부른다. 컴파일러는
  ML 모델과 그것이 도는 하드웨어를 잇는다. lowering 과정 중에 가능할 때마다 이 연산들은 대상
  하드웨어에서 더 빠르게 돌도록 특화된 커널로 변환된다** (9장, p.438).[^huyen2025]
- 실물 — **컴파일러는 Apache TVM이나 MLIR(Multi-Level Intermediate Representation) 같은 독립 도구일
  수도 있고, `torch.compile`(PyTorch의 기능), XLA(Accelerated Linear Algebra, 원래 TensorFlow가
  개발했고 OpenXLA라는 오픈 소스 판이 있다), 그리고 NVIDIA GPU에 최적화된 TensorRT에 내장된
  컴파일러처럼 ML·추론 프레임워크에 통합될 수도 있다. AI 기업은 자기 워크로드를 빠르게 하도록 설계된
  독점 커널과 함께 자기 컴파일러를 가질 수 있다** (9장, p.440).[^huyen2025]
  - 각주 — **많은 기업이 자기 커널을 영업 비밀로 여긴다. 경쟁자보다 모델을 더 빠르고 싸게 돌릴 수
    있는 커널을 갖는 것은 경쟁 우위다** (9장, p.440 각주 24).[^huyen2025]

## PyTorch가 겹쳐 쌓은 네 단계

- 저자가 상자로 떼어 둔 사례다 — **Figure 9-14는 PyTorch 팀이 다음 최적화 단계를 거쳐 Llama-7B에 줄
  수 있었던 처리량 개선을 보인다(PyTorch, 2023)** (9장, p.439):[^huyen2025]
  1. **`torch.compile`을 호출해 모델을 더 효율적인 커널로 컴파일한다.**
  2. **모델 가중치를 INT8로 양자화한다.**
  3. **모델 가중치를 INT4로 더 양자화한다.**
  4. **speculative decoding을 더한다.**
- 도판 막대에 인쇄된 값이다. 단위는 tok/s/user다 (9장, p.439, Figure 9-14):[^huyen2025]

  | 단계 | 처리량 (tok/s/user) |
  |---|---|
  | eager | 25.5 |
  | compile | 107.0 |
  | int8 | 157.4 |
  | int4 | 202.1 |
  | int4 + speculative | 244.7 |

  - 마지막 막대에 **+21%** 라벨이 붙어 있고, 차트에는 `SOTA 4-bit OSS inference` 기준선이 그어져
    있다 (9장, p.439, Figure 9-14).[^huyen2025]
  - 도판 설명 — **PyTorch에서 서로 다른 최적화 기법에 의한 처리량 개선. 이미지는 PyTorch(2023)에서
    왔다** (9장, p.439, Figure 9-14 설명).[^huyen2025]
- 저자가 붙인 단서 — **실험은 80 GB 메모리를 가진 A100 GPU에서 돌았다. 이 최적화 단계들이 모델의 출력
  품질에 어떤 영향을 주는지는 분명하지 않았다** (9장, p.439).[^huyen2025]

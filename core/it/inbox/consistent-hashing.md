# 일관 해싱

- [정의 — 두 성질](#정의--두-성질)
- [여기서 "일관"은 무슨 뜻이 아닌가](#여기서-일관은-무슨-뜻이-아닌가)
- [링과 그 재배치 셈법](#링과-그-재배치-셈법)
- [알고리즘 계열](#알고리즘-계열)
- [이어지는 페이지](#이어지는-페이지)

하나의 질문: **노드가 늘거나 줄 때 옮기는 키를 최소로 만드는 해시란 무엇인가.**

## 정의 — 두 성질

- **일관 해싱(consistent hashing) 알고리즘은 키를 지정된 개수의 샤드(shard)에 대응시키는 해시
  함수로, 두 성질을 만족하는 것**이다. 정의이므로 원문 직인용 (7장,
  p.263):[^kleppmann2026]

> - The number of keys mapped to each shard is roughly equal.
> - When the number of shards changes, as few keys as possible are moved from one shard to
>   another.

- 둘째 성질이 [해시 샤딩](../concepts/hash-sharding.md)의 모듈로(modulo) N 방식이 실패하는
  바로 그
  자리다 — 그쪽은 노드 수가 바뀌면 대부분의 키가 움직인다 (7장, p.259).[^kleppmann2026]

## 여기서 "일관"은 무슨 뜻이 아닌가

- **여기서 "일관(consistent)"이라는 말은 6장의 레플리카 일관성이나 8장의 ACID 일관성과 아무
  관계가 없다. 이 말이 가리키는 것은 키가 가능하면 같은 샤드에 머무르려는 경향**이다 (7장,
  p.263).[^kleppmann2026]

## 링과 그 재배치 셈법

위 정의가 성질로 진술한 것을 다른 소스는 실제 배치와 셈법으로 준다.

- 무엇을 완화하려는 것인가 — **해시 값을 노드 ID로 대응시키는 가장 직관적인 방법은 해시 값을
  클러스터 크기로 나눈 나머지를 취하는 것이다(모듈로). 시스템에 노드가 `N`개 있으면 대상 노드 ID는
  `hash(v) modulo N`으로 고른다. 이 접근의 주된 문제는 노드가 추가되거나 제거되어 클러스터 크기가
  `N`에서 `N'`으로 바뀔 때마다 `hash(v) modulo N'`이 반환하는 값의 상당수가 원래 것과 달라진다는
  것이다. 이는 데이터의 대부분을 옮겨야 한다는 뜻이다** (13장, p.271).[^petrov2019]
- 링 배치 — **이 문제를 완화하기 위해 일부 데이터베이스, 예컨대 아파치 카산드라와 Riak은 일관
  해싱이라 불리는 다른 파티셔닝 방식을 쓴다. 라우팅 키 값이 해시되고, 해시 함수가 반환한 값은
  링(ring)에 대응되어 가능한 최댓값 다음에는 최솟값으로 되돌아 감긴다. 각 노드는 링에서 자기 위치를
  얻고, 선행 노드의 위치와 자기 위치 사이 값 범위를 책임지게 된다** (13장,
  p.271).[^petrov2019]
- 그 효과와 셈법 — **일관 해싱을 쓰면 균형 유지에 필요한 재배치 수를 줄이는 데 도움이 된다. 링의
  변화는 떠나거나 합류하는 노드의 바로 이웃에만 영향을 주고 클러스터 전체에는 영향을 주지 않는다.
  정의에서 "일관"이라는 낱말은 해시 테이블이 크기 조정될 때 가능한 해시 키가 `K`개이고 노드가
  `n`개이면 평균적으로 `K/n`개의 키만 재배치하면 된다는 것을 함의한다. 다시 말해 일관 해시 함수의
  출력은 함수의 치역이 바뀔 때 최소로 변한다** (13장, p.271).[^petrov2019]
  - 기호 이름 병기: `K/n`은 **가능한 해시 키 수를 노드 수로 나눈 것**이며, 노드 하나가 책임지는
    키 몫에 해당한다.
- 왜 해시를 쓰는가 — **라우팅 키에서 대상 노드를 찾기 위해 일부 데이터베이스 시스템은 키의 해시를
  계산하고 해시 값에서 노드 ID로 가는 어떤 형태의 대응을 쓴다. 복제본 배치 결정에 해시 함수를 쓰는
  이점 중 하나는 범위 핫스팟(range hot-spotting)을 줄이는 데 도움이 된다는 것이다. 해시 값은 원래
  값과 같은 방식으로 정렬되지 않기 때문이다. 사전 순으로 가까운 라우팅 키 둘은 같은 레플리카 집합에
  놓이겠지만, 해시된 값을 쓰면 서로 다른 곳에 놓인다** (13장, p.271).[^petrov2019]
  - 이 진술의 반례는 [핫스팟과 쏠린 워크로드](../concepts/relieving-hot-spots.md)에 있다 —
    해시가 키를 고르게 흩어도 부하까지 고르게 만들어 주지는 않는다.

## 알고리즘 계열

- **카산드라와 ScyllaDB가 쓰는 샤딩(sharding) 알고리즘은 일관 해싱의 원래 정의와 비슷하다**
  (7장,
  p.263).[^kleppmann2026] 그 방식의 실제 동작(노드당 범위 여러 개, 무작위 경계)은
  [해시 샤딩](../concepts/hash-sharding.md)에 있다.
- **다른 일관 해싱 알고리즘들도 제안돼 있다 — 랑데부 해싱(rendezvous hashing)이라고도 하는
  최고 무작위 가중치(highest random weight), 그리고 점프 일관 해싱(jump consistent
  hashing)** 이다 (7장, p.263).[^kleppmann2026]
- 이들이 갈라지는 지점은 새 노드가 무엇을 받느냐다 — **이 접근들에서는 소수의 기존 샤드를
  부분 범위로 쪼개 새로 추가된 노드의 샤드를 만드는 대신, 새 노드에 다른 모든 노드에 흩어져
  있던 개별 키들을 배정한다. 어느 쪽이 더 나은지는 애플리케이션에 달렸다** (7장,
  p.263).[^kleppmann2026]

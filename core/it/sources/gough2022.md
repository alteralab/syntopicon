# gough2022

제임스 고프·대니얼 브라이언트·매튜 오번의 API 아키텍처 운영서(초판 2022-10-17, 추천사 세라 웰스).
서론(사례 연구 회의 시스템·ADR·C4)과 4부 10장 — I부 API 설계·구축·테스트(1~2장), II부 API 트래픽
관리(3장 API 게이트웨이 = 인그레스, 4장 서비스 메시 = 서비스 간), III부 운영과 보안(5장 배포와
릴리스, 6장 위협 모델링, 7장 인증·인가와 OAuth2), IV부 진화적 아키텍처(8장 API 주도 재설계, 9장
클라우드 플랫폼으로의 진화, 10장 마무리). **전권 반입 완주**(2026-09-19, 일곱 런).

- 이 KB에서 맡는 자리는 **API 스타일 비교층([dynowski2025](dynowski2025.md)) 위의 운영층(L2)**이다 —
  API 하나를 설계한 뒤 **테두리에 세우고 배포하고 지키고 진화시키는 일**의 원리와 선택 기준을 준다.
  스타일과 형식의 정본은 그쪽이고, **트래픽 중개자(게이트웨이·메시)와 API 보안과 진화는 이 소스가
  이 KB의 중심 소스**다. 제품 서술(Kong·Ambassador·Istio·Linkerd·Consul·Argo Rollouts·Calico 등)은
  L3라 얇게 들이고 "2022년 저술 시점" 버전 조건을 달았다.
- **이 소스가 이 KB에 처음 들여온 원전 자리 넷** — 위협 모델링과 STRIDE와 DREAD(6장, 반입 전
  0건 실측) · OAuth2의 절차와 그랜트와 스코프(7장, 기존 페이지들은 이름과 위상만 갖고 있었다) ·
  클라우드 이전 전략 여섯 R(9장) · 구역 기반 네트워크 아키텍처와 제로 트러스트의 구현 경로(9장).
  **API를 이음매(seam)로 보는 규정도 이 소스가 처음 세운다.**
- **정박한 자리** — 1장의 REST·RPC 서술은 dynowski2025·fielding2022-rfc9110에, 2장 테스트는
  newman2021 9장과 `consumer-driven-contracts`에, 3~4장은 기존 `api-gateway-and-service-mesh`에,
  7장은 뉴먼의 서비스 간 인증 페이지에, **8~9장의 진화 서술은 ford2022-evolutionary 원전에**
  정박시켰다. **8장은 그 원전을 이름으로 인용하는 2차 경유**라 규정과 원칙은 원전 쪽에 두고
  이 소스가 더하는 것(이음매·적합도 함수의 일곱 분류·API 층 케이크·고통 지점)만 담았다.
- **긴장 판정: 일곱 런 전부 `contradicts` 0건.** 가장 센 자리는 7장 본문이 토큰을 "Authentication
  Bearer 헤더"에 싣는다고 적는 것인데, 같은 쪽 그림과 다음 쪽 각주가 둘 다 `Authorization`을 쓰므로
  낱말의 느슨함으로 판정했다. 나머지(피트니스 함수의 분류 축·교살자 무화과·API 층 케이크 대 게이트웨이
  층 쌓기·최종 상태 선택지·1형 결정·클라우드 이전 단계)는 전부 **묻는 것이 갈리는 자리**였다.
- **코드 펜스 0으로 완주했다**(전권 예산 셋 가운데 0 사용). 매니페스트와 페이로드 예시는 전부
  산문과 표로 옮기고 자원 종류의 이름만 인라인 코드로 남겼다 — 제품 고유 설정 문법이 2022년
  시점의 L3이기 때문이다.
- **원문에 적어 둔 어긋남** — 3장의 표 3-3 행 수 대 본문의 기준 수, 6장 그림 6-6의 캡션과 그림 안
  위협 이름과 본문의 세 갈래 어긋남, 7장의 헤더 이름, 8장 응집 곁상자의 "결합" 오기와 "SOAP-RCP"
  오식, 9장 p.220이 제로 트러스트 원칙 여덟을 출처 없이 "our guidance"라 부르는 것, 그리고 같은
  도면이 캡션만 바꿔 두 번 실리는 자리 둘(그림 3-1/3-9 · 8-2/9-1). 이 KB는 어느 것도 고치지 않고
  그대로 적어 두었다.

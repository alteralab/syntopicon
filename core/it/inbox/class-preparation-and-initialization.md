이 페이지의 질문: **클래스 변수는 언제 어떤 값을 갖게 되며, 그 값을 넣는 `<clinit>()`은 어떻게
만들어지고 실행되는가.**

## 준비 단계가 할당하는 것

- 준비 단계의 정의는 한 줄이다 — **준비는 클래스 변수(정적 변수)를 메모리에 할당하고 초깃값을
  설정하는 단계다** (7장, p.367).[^zhou2024]
- 그 메모리가 어디인지는 개념과 구현이 갈린다 — **개념적으로는 이 변수들이 사용하는 메모리를 메서드
  영역에 할당해야 하지만, 메서드 영역 자체가 논리적 영역임을 감안해야 한다** (7장,
  p.367).[^zhou2024]
  - 버전 조건: JDK 7 이하 — **핫스팟에서는 메서드 영역을 영구 세대에 구현하여 논리적인 개념과
    일치했다** (7장, p.367).
  - 버전 조건: JDK 8 이상 — **클래스 변수가 클래스 객체와 함께 자바 힙에 저장된다. 따라서
    "클래스 변수는 메서드 영역에 존재한다"라는 말은 그저 논리적으로 그렇다는 뜻이다** (7장,
    p.367). 이 영역이 실제로 어디에 놓이는지는
    [런타임 데이터 영역과 메모리 오버플로](../concepts/jvm-runtime-data-areas.md)에 있다.
- 헷갈리기 쉬운 두 가지를 저자가 먼저 정리한다 (7장, p.367):[^zhou2024]
  - **인스턴스 변수가 아닌 클래스 변수만 할당된다. 인스턴스 변수는 객체가 인스턴스화될 때 객체와
    함께 자바 힙에 할당된다.**
  - **준비 단계에서 클래스 변수에 할당하는 초깃값은 해당 데이터 타입의 제로값이다.**

## 제로값과 ConstantValue라는 예외

- 소스에 적은 값은 아직 들어가지 않는다 — `public static int value = 123;`으로 선언했더라도
  **준비 단계를 마친 직후 `value` 변수에 할당되어 있는 초깃값은 123이 아닌 0이다** (7장,
  p.367).[^zhou2024]
- 이유는 실행 시점 때문이다 — **123을 할당하는 `putstatic` 명령어는 클래스 생성자인 `<clinit>()`
  메서드에 포함되며, 준비 단계에서는 어떠한 자바 메서드도 아직 실행되지 않은 상태이기 때문이다.
  123을 할당하는 일은 '클래스 초기화 단계'에 가서야 이루어진다** (7장, p.367).[^zhou2024]
- 기본 데이터 타입별 제로값은 이렇다 (7장, p.368, 표 7-1):[^zhou2024]

  | 데이터 타입 | 제로값 | 데이터 타입 | 제로값 |
  |---|---|---|---|
  | `int` | `0` | `boolean` | `false` |
  | `long` | `0L` | `float` | `0.0f` |
  | `short` | `(short) 0` | `double` | `0.0d` |
  | `char` | `'\u0000'` | 참조 | `null` |
  | `byte` | `(byte) 0` | | |

- 예외는 하나뿐이고 형식 쪽 속성이 만든다 — **일반적인 경우에는 초깃값이 모두 0이지만 특수한 경우도
  있다. 클래스 필드의 필드 속성 테이블에 `ConstantValue` 속성이 존재한다면, 준비 단계에서 변수의
  초깃값으로 `ConstantValue` 속성이 지정한 값을 할당한다** (7장, p.368).[^zhou2024]
  - 그 속성을 만드는 것이 `final`이다 — 선언을 `public static final int value = 123;`으로 바꾸면
    **javac가 `value` 변수를 위한 `ConstantValue` 속성을 생성한다. 그러면 가상 머신은 준비 단계
    때 `ConstantValue`에 설정된 값인 123을 `value`에 할당할 것이다** (7장, p.368). 이 속성이
    형식 쪽에서 어떻게 정의되어 있는지는
    [클래스 파일의 속성 테이블](../concepts/class-file-attributes.md)에 있다.

## 초기화는 클래스 생성자를 실행하는 단계다

- 여기서 처음으로 사용자 코드가 돈다 — **초기화는 클래스 로딩의 마지막 단계다.** 그리고 **초기화
  단계에 들어서면 자바 가상 머신이 드디어 사용자 클래스에 작성된 자바 프로그램 코드를 실행하기
  시작한다** (7장, p.374).[^zhou2024]
- 앞 단계와의 차이가 값의 출처다 — **앞서 준비 단계에서는 모든 변수에 시스템이 정의한 초깃값인
  0을 할당했다. 반면 초기화 단계에서는 클래스 변수와 기타 자원을 개발자가 프로그램 코드에 기술한
  대로 초기화한다. 더 직관적으로 말하면 초기화 단계란 클래스 생성자인 `<clinit>()` 메서드를
  실행하는 단계다** (7장, p.374).[^zhou2024]
- 통제권이 여기서 가상 머신 쪽으로 넘어간다 — **사용자 정의 클래스 로더를 이용하여 앞서 소개한
  단계 중 일부에 관여할 수 있지만, 대부분의 작업은 온전히 자바 가상 머신이 통제한다** (7장,
  p.374).[^zhou2024]
- 이 메서드는 손으로 쓸 수 없다 — **`<clinit>()`는 자바 컴파일러가 자동으로 생성하는 메서드라서
  개발자가 자바 코드로 직접 작성할 수는 없다** (7장, p.374).[^zhou2024]

## 무엇이 어떤 순서로 수집되는가

- 수집 대상과 순서 규칙이 함께 정해져 있다 — **`<clinit>()`는 모든 클래스 변수 할당과 정적 문장
  블록(`static {}`)의 내용을 취합하여 컴파일러가 자동으로 생성한다. 컴파일러가 수집하는 순서는
  문장이 소스 파일에 등장하는 순서에 영향을 받는다** (7장, p.375).[^zhou2024]
- 그 순서가 만드는 비대칭이 하나 있다 — **정적 문장 블록에서는 정적 문장 블록보다 먼저 정의된
  변수에만 접근할 수 있다. 하지만 나중에 정의된 변수라도 정적 문장 블록 안에서 값을 할당하는 건
  가능하다** (7장, p.375).[^zhou2024] 나중에 정의된 변수를 읽으려 하면 컴파일러가
  **"Cannot reference a field before it is defined"** 메시지를 출력하며 컴파일을 거부한다 (7장,
  p.375, 코드 7-4).
- 없을 수도 있다 — **`<clinit>()`가 클래스나 인터페이스에 반드시 필요한 것은 아니다. 정적 문장
  블록이 없고 정적 변수에 값을 할당하지 않는 클래스라면 컴파일러가 `<clinit>()`를 생성하지 않을 수
  있다** (7장, p.376).[^zhou2024]

## 부모가 먼저 실행된다

- 이름은 생성자지만 자바 언어의 생성자와 다르다 — **`<clinit>()`는 자바 언어에서 말하는 클래스의
  생성자와는 다르다**(가상 머신 관점에서 인스턴스를 만드는 생성자는 `<init>()`다) (7장,
  p.375).[^zhou2024]
- 상위 호출이 암묵적으로 보장된다 — **부모 클래스의 생성자를 명시적으로 호출하지 않아도 자바 가상
  머신은 하위 클래스의 `<clinit>()`가 실행되기 전에 부모 클래스의 `<clinit>()`부터 실행한다.
  따라서 자바 가상 머신이 실행하는 첫 번째 `<clinit>()`는 바로 `java.lang.Object`의
  `<clinit>()`다** (7장, p.375).[^zhou2024]
- 그 순서가 관찰 가능한 결과를 만든다 — **부모 클래스의 `<clinit>()`가 먼저 실행되므로 자연스럽게
  부모 클래스에 정의된 정적 문장 블록이 자식 클래스의 변수 할당 연산자보다 먼저 실행된다** (7장,
  p.375, 코드 7-5).[^zhou2024] 부모가 `A = 1`을 선언한 뒤 정적 블록에서 `A = 2`로 덮고 자식이
  `B = A`로 받으면, **필드 `B`의 값은 1이 아닌 2가 된다.**

## 인터페이스는 위로 올라가지 않는다

- 인터페이스에도 `<clinit>()`은 있다 — **인터페이스에서는 정적 문장 블록을 사용할 수 없지만
  변수에 초깃값을 할당할 수는 있다. 인터페이스도 `<clinit>()` 메서드가 있을 수 있다는 뜻이다**
  (7장, p.376).[^zhou2024]
- 다른 것은 전파 방향이다 — **인터페이스의 경우 부모 인터페이스의 `<clinit>()`를 먼저 실행할
  필요가 없다는 점에서 클래스의 `<clinit>()`와 차이가 있다. 부모 인터페이스는 부모 인터페이스가
  실제로 사용되는 시점에 비로소 초기화된다. 클래스를 초기화할 때도 클래스가 구현한 인터페이스의
  `<clinit>()`를 실행하지 않는다** (7장, p.376).[^zhou2024]

## 한 번만 실행된다는 보장의 대가

- 동기화가 명세의 요구다 — **자바 가상 머신은 클래스의 `<clinit>()`가 멀티스레드 환경에서 적절히
  동기화되도록 해야 한다. 여러 스레드가 한 클래스를 동시에 초기화하려 시도하면 그중 한 스레드만
  `<clinit>()`를 실행하고, 다른 스레드는 모두 대기시켜야 한다** (7장, p.376).[^zhou2024]
- 그래서 초기화가 오래 걸리면 그대로 장애가 된다 — **클래스의 `<clinit>()`에 시간이 오래 걸리는
  작업이 포함되어 있다면 여러 스레드가 장시간 블록될 수 있다. 실제로도 자주 목격되는 일**이다
  (7장, p.376, 코드 7-6).[^zhou2024] 정적 블록에서 무한 루프를 도는 클래스를 두 스레드가 동시에
  인스턴스화하면 **두 스레드 모두 시작은 되지만 한 스레드가 초기화를 끝내지 못해서 다른 스레드는
  계속 블록되어 있다** (7장, p.377).
- 깨어난 뒤의 동작이 각주에 있다 — **블록된 스레드들은 `<clinit>()` 메서드를 실행하는 스레드가
  `<clinit>()` 실행을 끝마치면 깨어나는데, 깨어난 후에 `<clinit>()` 메서드로 진입하지 않고
  건너뛴다. 이런 식으로 같은 클래스 로더하에서 한 클래스는 오직 한 번만 초기화된다** (7장, p.376,
  각주 16).[^zhou2024]

# kb-lint

**lint는 검출만 한다.** 수정 커밋은 사람이 한다 — 자동 수정은 이 KB에서 금지된
동작(모순 자동 해소·페이지 자동 병합)과 구분되지 않고, 조용히 판단을 대신한다.

커밋을 막는 것은 `validate`다. lint의 종료 코드는 파생 인덱스 부재(1) 말고는
항상 0이다 — 오류가 있어도 실패로 끝나지 않는다.

## 저장소 위치 확정 (cwd 독립 — 최초 1회)

이 스킬의 `uv run tools/…` 명령은 전부 core 저장소 루트 기준이다. cwd가 core가
아니면(다른 프로젝트에서 호출) 먼저:

```sh
cd "$(dirname "$(dirname "$(dirname "$(realpath "${CLAUDE_SKILL_DIR:-$HOME/.claude/skills/kb-lint}")")")")"
```

## 실행

```
uv run tools/reindex.py                    # 파생 인덱스 먼저
uv run tools/lint.py                       # 전수
uv run tools/lint.py --incremental         # 직전 실행 이후 바뀐 페이지만 (주간)
uv run tools/lint.py --kb <kb> --quiet     # info 숨김
uv run tools/lint.py --overlap-full        # overlap 전쌍 — 부트스트랩·분기 전수용
```

주간은 `--incremental`(overlap도 바뀐 페이지 × 전체만 본다), 분기 전수 검사와
부트스트랩만 전수다.
결과는 사람이 읽는 리포트와 `stats.sqlite`(경보·큐)에 이원 기록된다.

## 등급이 곧 우선순위는 아니다

| 등급 | 뜻 | 다루는 법 |
|---|---|---|
| error | 무결성이 깨졌거나 임계를 넘었다 | 종류를 갈라서 본다(아래) |
| warn | 부패 진행 중 | 이번 세션 또는 다음 세션 |
| info | 큐 | 지금 할 일이 아니다 |

같은 error 안에서도 **일의 종류가 다르다**:

- `broken-link`, `snapshot-mismatch` → 지금 고치는 일. 파일 수정.
- `inbox-p90`, `contradiction-one-sided` → **정책·연구 과제**. 파일 수정으로 안 끝난다.

리포트를 그대로 되읽어 주는 것은 분류가 아니다. 무엇이 5분짜리이고 무엇이
결정을 요구하는지 갈라 준다.

## 검사별 판단 기준

판단 기준의 **정본은 코드의 Kind 레지스트리**다 — 41종 전부에 등급·정의·판독
지침이 있고, 지침 없는 검사는 테스트가 추가를 막는다(손 유지 목록 시절 안내
누락 17종의 교훈).

```
uv run tools/lint.py --explain               # 전 종류와 지침
uv run tools/lint.py --explain <종류이름>     # 리포트에 나온 그 종류만
```

리포트를 읽다가 모르는 종류를 만나면 --explain으로 조회하고, 이 문서에 다시
옮겨 적지 않는다 — 두 곳에 있으면 언젠가 갈라진다.

## 임계 경보 (tripwire)

경보는 **주기 작업의 우선순위 지시**이지 신규 구축 트리거가 아니다.

| 경보 | 대응 |
|---|---|
| inbox 나이 P90 > 30일 (표본 5건 이상일 때만) | **적체가 생겼다는 사실을 전하고 멈춘다.** 대응은 성문돼 있지 않다 — 발생한 적 없는 상황의 처방을 미리 두지 않는 것이 규율이고(PLAN §4.4·§6), 사람 승인 없는 자동 승급 경로는 불채택이다. 대응책을 지어내지 말 것. 리뷰 시간 증액도 1차 답이 아니다 — 예산 2–3주당 30–45분은 고정 전제다 |
| lint 오류(broken-link 제외) > 50건 | 유지보수 세션을 잡는다. broken-link를 빼는 이유: 경보 이력 6구간 전부가 승급 대기의 정상 상태였다 — 늘 우는 경보는 죽는다 |
| search-miss 20회 중 4회 초과 | 검색 설정 점검(형태소 사전·융합 가중치). 기록자는 tools/search.py다 |

1인 운영에서 리뷰 공급은 1이고 백로그가 정상 상태가 되는 것은 알려진 성질이다.
P90은 파산 시점의 계측이지 더 열심히 하라는 신호가 아니다.

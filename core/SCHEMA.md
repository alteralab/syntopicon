# 규약 설명서

**이 문서는 설명서지 규범이 아니다.** 규범은 `schema/*.yaml` + `tools/validate`이고,
둘이 어긋나면 기계가 이긴다. 산문 규칙이 지켜진다고 가정하지 않는 것이 이 설계의 전제다.

**검사 지형**: 이 문서의 규칙이 전부 기계 검사를 받는 것은 아니다. 검사가 있는
규칙과 그 판독 지침은 `uv run tools/lint.py --explain`이 정본이고, **검사가 없는
규칙 목록과 그 사유(내용 판단·절차·세션 규칙)는 `.agents/review/08-규칙-집세-심사.md`가
정본**이다 — 검사 없는 규칙의 통과는 준수의 증거가 아니다(집세 심사, 2026-08-13).

설계 결정과 그 근거는 [PLAN.md](PLAN.md)에 있다. 여기서는 "그래서 어떻게 쓰는가"만 다룬다.

## 1. 파일 종류

`schema/layout.yaml`이 디렉터리와 `type`의 정합을 강제한다. **디렉터리는 뷰이고,
type의 정본은 frontmatter다** — 파일을 옮겨도 type이 따라 바뀌지 않는다.

| 어디에 | type | 무엇 |
|---|---|---|
| `<kb>/concepts/` | `concept` | 개념 페이지. 하나의 질문에 답하는 단위 |
| `<kb>/synthesis/` | `synthesis` | 인간 저작 종합. 허브(MoC)도 이것 |
| `<kb>/sources/` | CSL 타입군 | 소스 메타 1건 = 1파일 |
| `<kb>/inbox/` | `concept` 또는 `synthesis` + `status: draft` | 기계 산출물의 검역 구역. `synthesis`는 **개정 초안만** — 짝이 없으면 오류(창설은 사람) |
| 어디든 | `redirect` | 개명·이동·분할·병합의 잔여물 |
| `overview.md`, `SCHEMA.md` | `guide` | 진입·설명 문서 |

`<kb>/archive/`만 예외다 — 소스 원문 스냅샷이고 git에 들어가지 않는다.

## 2. 부재 = 기본값

이 규약의 중심 규칙이다. **값이 생길 때만 적는다.**

- `status` 없음 = stable · `verified` 없음 = 미검증 계층 · `stale_after` 없음 = 만료 없음
- `null` 자리표시 금지. 파서가 null과 부재를 구분하지 못한다.
- 빈 리스트 금지. `verified: []`는 "검증했는데 아무도 안 함"이 아니라 오류다.
- `status: stable`처럼 기본값을 명시하는 것도 금지다.

## 3. 개념 페이지

```yaml
---
type: concept
title: Raft 읽기 경로              # 표시 전용. 유일할 필요 없다. 한국어 유지
description: 한 줄 요약             # 검색 스니펫이 이걸 읽는다. 편집하면 갱신할 것
generated: { by: "claude-fable-5", at: "2026-07-31T05:00:00Z" }
sources:
  - { id: ongaro2014-raft, resource: /it/sources/ongaro2014-raft.md }
---
```

`generated.by`는 모델 id, 사람(`human:me`), 도구(`tools/kb-new`) 중 하나를 적는다.
인간이 썼어도 적는다 — **비워 두면 "출처 불명"이라는 뜻이 된다.**

### 본문

- **claim은 각주 달린 불릿이다.** 귀속은 본문 각주 `[^citekey]`로만 하고,
  페이지·절 같은 locator는 각주 텍스트에 적는다. frontmatter에 중첩 locator를 두지 않는다.
- **반입 진행 상태를 본문에 적지 않는다.** "~장은 아직 반입되지 않았다" 같은
  문장은 다음 런이 돌면 거짓이 된다(2026-08-16 실측: 실용주의 허브 4곳의 진행
  산문이 몇 시간 만에 썩었다 — 산문 카운터가 썩는다는 교훈의 페이지판). 진행의
  정본은 `it/archive/<citekey>/_progress.yaml` 하나이고, 페이지는 시점 무관
  서술(실재하는 형제 페이지·허브 링크)만 담는다. 같은 문형의 정당한 도메인
  서술("이벤트가 반입되지 않으면")이 실재해 기계 검사는 부적격 — 집행은
  리뷰 템플릿 항목이다.
- **반입 런 번호도 진행 상태다.** "런 08이 세운 규약", "런 11이 판정하라고 넘긴" 같은
  표기를 본문에 남기지 않는다. 런은 **배치 안에서만 뜻이 있는 내부 사건**이고 배치가 끝나면
  독자가 해독할 수 없다 — 판정은 남기고 라벨만 뺀다("이 KB의 규약", "앞선 판정"). 무엇을
  어느 런이 했는지는 `_progress.yaml`과 커밋 트레일러가 정본이다. 2026-09-30 실측:
  열두 런이 위 조문을 읽고도 82곳에 런 번호를 남겼다 — 조문이 그 경우를 덮지 못했다.
- **불확실한 것은 인라인 토큰으로 표시한다.** `#hypothesis`(근거는 있으나 미확정),
  `#speculation`(근거가 얇은 추측). 무표기 = 사실 서술. 숫자 confidence는 쓰지 않는다.
  이 둘이 어휘의 전부이고, 다른 `#토큰`은 lint가 잡는다 — 태그 체계는 없다.
- **한국어로 재서술하되 원어를 병기한다 — 페이지마다 첫 등장에, 소스가 쓰는 표기
  그대로**: 영속성(persistence). 역어가 흔들려도 원어가 불변 검색 키로 남는다.
  병기 단위가 코퍼스가 아니라 **페이지**인 이유: 검색·랭킹 단위가 페이지·섹션이라,
  다른 페이지의 병기는 이 페이지를 못 구한다(2026-08-13 실측: 페일오버 10개 파일 중
  병기 1개 — `failover` 질의가 나머지 9개를 못 잡았고, 리더리스 복제 페이지는
  `leaderless` 질의에 자기 자신이 안 나왔다). 원어가 **소스 표기 그대로**인 이유:
  사람의 역번역 추측은 빗나간다(같은 날 실측: "WAL 배송"의 원어를 publish로
  추측 — 실제는 shipping). 변형·유사 표현 질의는 벡터 갈래의 몫이고, 병기는
  어휘 갈래의 정확 일치 키다. 확립 용어(TTA·국어원)를 우선하고,
  미확립이면 원어를 유지한다. 번역서는 역어 참조원이지 정본이 아니다 — 채택은
  건별 판단이고, 결정된 역어는 아래에 고정한다(전 페이지 구속, 개정은 이 파일).

  | 원어 | 확정 역어 | 왜 |
  |---|---|---|
  | additive / semi- / non- | 합산 가능 / 부분 합산 가능 / 합산 불가 | 뜻이 자명(가산 계열 기각 — 킴벌 국역판 채택례) |
  | surrogate key | 대리 키 | "대체 키"는 alternate key의 확립 역어라 충돌 |
  | dimension (table·attribute) | 차원 (차원 테이블·차원 속성) | 확립 역어. 팩트·허브·링크·새틀라이트는 확립 음차 유지 |
  | dimensional modeling | 차원 모델링 | "다차원"은 multidimensional DB와 구분 소실(킴벌 국역판 p.8 순환문이 반례 실물) |
  | conformed dimension | 표준 차원 | 킴벌 국역판 채택례("표준 디멘션") — 합치·적합보다 확립 근거 있음. conform 동사는 "정제·통합" |
  | compaction | 컴팩션(LSM) / 압착(카프카 로그) | **의도적 분기.** 영어는 같으나 기제가 다르다 — LSM은 정렬 테이블 병합, 카프카는 키별 최신값 보존. 통일하면 그 구분이 사라진다 |
- **정의·정리·수치처럼 왜곡에 민감한 구간은 번역하지 말고 원문을 직인용한다**(인용 블록).
  의미는 원문이, 해설은 한국어가 담당한다.
- **원칙(조문): 버전 조건은 `버전 조건:` 고정 형식으로 두 자리(페이지 전체 = 목차
  아래 인용 블록, claim 하나 = 자식 불릿)에만, 기호 없이 한국어 낱말로, 경계는
  아는 한 실제 릴리스 번호로 적는다.** 조문의 지위는 이 한 줄에 있고, 이하 세부는
  해설과 실측 근거다 — 반례를 만나면 해설을 늘리는 대신 원칙으로 판단한다
  (집세 심사 나 승격, 2026-08-13). 자리는 둘뿐이다.

  **① 페이지 전체에 걸릴 때 — 목차 아래 인용 블록**

  ```markdown
  ## 버전 조건

  > **버전 조건**: Kafka 3.9 이하. 주키퍼 모드가 남아 있던 마지막 릴리스까지
  > 적용된다. **4.0 이상에는 적용되지 않는다** — 그쪽은
  > [KRaft 컨트롤러 쿼럼](../concepts/kraft-controller-quorum.md)이 담당한다.
  ```

  **② claim 하나에만 걸릴 때 — 그 claim의 자식 불릿 첫 줄**

  ```markdown
  - 컨트롤러는 브로커 중에서 뽑힌다 (6장, p.141).[^shapira2021]
    - 버전 조건: Kafka 3.9 이하 — 4.0에서는 별도 컨트롤러 노드가 맡는다.
  ```

  **본문 인라인은 쓰지 않는다.** 검색이 절 단위로 답을 돌려줄 때 조건이 claim에서
  떨어지지 않아야 하고, `버전 조건:`이 고정 낱말이면 `rg '버전 조건:'` 한 줄로
  코퍼스의 버전 종속 claim을 전수 열거할 수 있다.

  **기호를 쓰지 말고 한국어 낱말로.** 이하·이상·부터·까지를 쓰고 `≤`·`<`는 쓰지
  않는다 — 형태소 색인이 기호를 통째로 버리므로(위 수식 항 실측) `Kafka ≤3.x`는
  검색에서 조건이 사라진다.

  **경계는 아는 한 실제 릴리스 번호로.** `3.x 이하`가 아니라 `3.9 이하`. 경계를
  모를 때만 `3.x`를 쓴다.

  **`stale_after`와는 다른 축이다.** 버전 조건은 claim의 적용 범위를 좁혀 **틀려지지
  않게** 만들고, `stale_after`는 범위가 없는 서술이 **언제 틀려질지**를 기록한다.
  그래서 조건을 명시하고 나면 `stale_after`는 뗀다 — 범위 안에서 그 서술은 영원히
  참이다(2026-08-11 Kafka 4.0 반입에서 실증: `zookeeper-and-kraft`는 조건을 달고
  만료를 뗐고, 미해소 항목이 남은 `brokers-and-clusters`는 유지했다).

- **원칙(조문): 수식은 문장 속이면 유니코드 기호에 이름을 병기하고, 여러 줄이면
  ` ```math ` 펜스에 넣는다.** 이 KB의 수학은 인용이지 저작이 아니므로(책·논문이
  말한 것을 옮긴다) 두 자리로 충분하다. 이하 세부는 해설이다(집세 심사 나 승격).

  **① 문장 속 기호 — 유니코드 그대로 + 이름 병기(필수)**

  ```markdown
  - 브로드캐스트 시간이 선출 타임아웃보다 훨씬 작아야
    (broadcastTime ≪ electionTimeout) 안정적인 리더가 유지된다 (§5.6).[^ongaro2014-raft]
  ```

  이름 병기가 **선택이 아니라 필수**인 이유: 형태소 레그가 기호를 통째로 버린다.
  실측(2026-08-11) — `a ≪ b 이고` → 색인 토큰 `a`, `b`. `≪`뿐 아니라 `α`·`ℝ`도
  사라진다(POS 필터가 SL/SH/SN만 통과시킨다). `x²`는 통짜 토큰이라 `x`로 못 찾는다.
  **기호는 읽기용이고 검색은 병기된 이름이 담당한다.**

  **② 여러 줄 수식·백슬래시 든 것 — ` ```math ` 펜스**

  ````markdown
  ```math
  broadcastTime \ll electionTimeout \ll MTBF
  ```
  ````

  본문에 그냥 쓰면 **백슬래시가 조용히 사라진다**(CommonMark §2.4가 ASCII 구두점
  앞 백슬래시를 이스케이프로 먹는다 — 실측 15표본 중 8개 손상: `$\{a,b\}$`→`${a,b}$`,
  `$50\%$`→`$50%$`). **인용 블록(`>`)은 보호해 주지 못한다** — 컨테이너 블록이라
  인라인 파싱이 그대로 적용된다. 펜스만이 원문을 100% 보존하고, 순정 CommonMark
  정보 문자열이라 방언을 넓히지도 않는다. GitHub은 이것을 수식으로 렌더한다.

  **금지: `$…$` 인라인 LaTeX** — 어느 스펙에도 없다(CommonMark·GFM 스펙·cmark-gfm
  전부 부재). 우리 파서가 평문으로 취급해 백슬래시를 먹고, 이 KB는 이미 `$`를
  통화로 쓴다(`snapshot-fact-tables`·`slowly-changing-dimension`). lint가 검출한다.

  **부수 규약**: 유니코드는 **NFC 고정, NFKC 금지**(NFKC는 `𝔼→E`, `ℝ→R`, `²→2`로
  의미를 파괴한다 — UTR#25 §2.2가 "should never be used with mathematical texts"로
  명시). 표 안에서는 `\|` 또는 `‖`(파이프가 셀 구분자로 오인된다). 2D 레이아웃
  (적분 상하한·행렬)은 표현하지 않는다 — 원문은 `archive/` 스냅샷이 보존한다.

- **원칙(조문): 코드는 소스에 있는 것만 넣고, 짧은 조각은 인라인 백틱, 복사해 쓸
  것은 펜스로 개념당 대표 하나를 산문 한 줄이 소개하며, 출력은 명령 펜스와
  가른다.** 조문의 지위는 이 한 줄에 있고, 이하 세부는 해설과 실측 근거다 —
  반례를 만나면 해설을 늘리는 대신 원칙으로 판단한다(집세 심사 나 승격,
  2026-08-13). 두 자리가 있고, **검색에서 다르게 취급된다**.

  **① 짧은 조각 — 인라인 백틱(색인됨)**

  옵션 이름·설정 키·명령 조각처럼 **문장의 일부인 것**은 백틱으로 감싼다. 인라인
  코드는 산문과 같이 색인되므로 `-XX:+PrintGCDetails`나 `zookeeper.connect`로
  찾을 수 있다(현행 549건). 기호는 버려지고 식별자만 남는다는 점은 수식과 같다 —
  `-XX:+PrintGCDetails`는 `XX`와 `PrintGCDetails`로 색인된다.

  **② 복사해 쓸 것 — 코드 펜스(색인 제외)**

  ````markdown
  - 통합 로깅으로 GC 상세를 남긴다 (3장, pp.180–183).[^zhou2024]

    ```sh
    java -Xlog:gc*:file=gc.log:time,uptime:filecount=5,filesize=10M App
    ```
  ````

  **펜스 본문은 형태소 색인에 넣지 않는다**(도구가 AST로 빼낸다 — HTML 블록과
  대칭). 넣으면 **그 절의 산문이 손해를 본다**: FTS5 BM25의 길이 정규화가 행 전체
  토큰 수를 쓰므로 코드 토큰이 같은 절 산문 용어의 점수를 깎는다. 실측
  (2026-08-11, 89개 페이지 포화) — 펜스가 든 절 5건 **전부** 점수 하락, 1건은
  1위를 뺏겼다. **컬럼 분리로는 안 고쳐진다**(`D`가 컬럼별이 아니다). 색인 제외만
  소수점까지 복구했다. 스니펫에는 그대로 보이므로 사람이 복사하는 데 지장이 없고,
  펜스 코드 조회는 `rg`와 qmd가 담당한다(PLAN §4.1의 기존 분업).

  **펜스는 복사해서 돌아가야 한다.** 그것이 펜스의 정의이므로 두 가지가 따라온다.

  - **셸 프롬프트(`$`·`#`)와 조판 줄바꿈은 정돈한다.** 책은 지면 폭 때문에 명령을 접고
    프롬프트를 붙이는데, 그대로 옮기면 `sh` 펜스에서 `#`가 주석이 되어 **명령 전체가
    죽는다**(2026-08-12 실측). 프롬프트 제거와 줄 잇기는 **깎기라 허용**이고, 이음
    문자 `\`는 접힌 줄을 원래 한 줄로 되돌리는 표기이므로 보태기가 아니다. 각주에
    적는다.
  - **출력 예시는 펜스가 아니다.** 실행할 것이 아니므로 `text` 펜스로 명령과 갈라
    두거나 표로 옮긴다. 명령과 출력을 한 펜스에 섞으면 그 펜스는 복사할 수 없다.

  **출처가 없는 코드는 넣지 않는다.** 펜스는 **반입한 소스에 실제로 있는 코드**여야
  하고, 각주 달린 claim 아래에 붙어 그 각주를 상속한다(§2.1). 소스에 없는 것을
  지어내면 그것은 예제가 아니라 **발명한 claim**이다 — 산문 claim에 각주를 의무화한
  것과 같은 이유이며, 코드는 그럴듯해 보여서 더 위험하다. 소스가 말하지 않은 것을
  실행해 확인했다면 그것은 인용이 아니라 관측이므로 `#hypothesis`를 달고 무엇으로
  확인했는지 적는다.

  **원문에서 깎는 것은 허용, 보태는 것은 금지.** 문맥 의존부(변수명·주변 코드)를
  덜어 재사용성을 올리는 편집은 관례가 지지한다("trim down if possible"). 그러나
  소스에 없는 줄을 채워 넣어 "완성"시키지 않는다. 깎았으면 각주에 그 사실을 적는다.

  **개수: 개념당 대표 하나.** few-shot 실증이 5–25개 구간에서 최고점을 찍고 그
  뒤로 떨어지며(many-shot 역설), 벤더 지침은 3–5개다. O'Reilly Media 정책도
  "significant portion"부터 허가 대상이다. 셋 다 **선별**을 가리킨다.

  **펜스 앞에 산문 한 줄이 필수다** — 어디에 쓰는 것인지, 무엇으로 찾을 것인지.
  근거는 프로그래밍 제텔카스텐의 성문 규칙 둘이다: "Merely pasting code I wrote
  into a note doesn't cut it", "How will it be searched?". 코드는 산문과 달리
  **자기 말로 다시 쓰지 않는다** — 원문 그대로 두되 문맥 의존부를 깎아 재사용성을
  올린다.

  **버전 조건이 붙는다.** 코드는 산문보다 빨리 낡는다. 라이브러리·CLI가 바뀌면
  거짓이 되므로 위 버전 조건 규약의 대상이다.

```markdown
## 읽기와 quorum

- leader lease 없이는 읽기에도 quorum 왕복이 필요하다 (§5.4 기준).[^ongaro2014-raft]
- #hypothesis lease 시계 드리프트 한계는 실무 문제 사례가 드물다.[^ongaro2014-raft]

[^ongaro2014-raft]: Ongaro 2014, §5.4
```

### 페이지 위생

- **한 페이지 = 하나의 질문.** 섹션이 다른 질문에 답하기 시작하고 그 자식이 자립
  가능할 때만 쪼갠다. 자식이 스텁이 되거나 부모 요약의 복제면 쪼개지 않는다.
- 100줄을 넘으면 상단에 TOC를 둔다. 500줄 경고는 백스톱이지 자동 분할 기준이 아니다 —
  1차 완화책은 분할이 아니라 TOC + 섹션 앵커다.
- **TOC는 H1 바로 아래 링크 불릿 목록**이다.

  ```markdown
  # 페이지 제목

  - [첫 절](#첫-절)
  - [둘째 절](#둘째-절)
  ```

  **앵커를 손으로 짓지 마라.** GitHub 규칙은 소문자화 후 영숫자·공백·하이픈만 남기고
  공백을 하이픈으로 바꾸는데, 구두점이 사라지면 **양쪽 공백이 하이픈 둘로 남는다** —
  `타입 2 — 기본기`의 실제 앵커는 `#타입-2--기본기`(하이픈 둘)다. 같은 헤딩이 반복되면
  둘째부터 `-1`이 붙는다. lint의 `anchor-broken`이 검사하고, 2026-08-11 전수 교정에서
  28건이 이 함정으로 깨져 있었다.
- H1은 파일당 하나(제목과 일치), 헤딩 레벨 건너뛰기 금지, H3–H4까지.
  H4가 필요해지면 분할 신호다.
- 쪼개거나 합칠 때는 `redirect` 스텁을 남긴다.

### 낡음과 모순

- `stale_after: "2027-06-01"` — 휘발성 있는 내용에만. lint가 만료 큐를 만든다.
- 대체되면 `status: deprecated` + `superseded_by: <슬러그>`. 둘은 함께 간다
  (`superseded_by`만 적으면 validate가 거부한다).
- 모순은 `contradicts: [상대-슬러그]`를 **양쪽에** 적는다. 자동 해소 금지 —
  해소할 때도 최신성만으로 판단하지 말고, 해소 날짜·결정 근거·대체된 주장을 페이지에 남긴다.

## 4. 소스 메타

```yaml
---
type: book
title: "Designing Data-Intensive Applications"
author: [{family: Kleppmann, given: Martin}]
issued: "2017"
publisher: "O'Reilly Media"
ISBN: "9781449373320"
edition: 1
snapshot: /it/archive/kleppmann2017-ddia/
snapshot_sha256: "e3b0c442…"     # ingest 시점 1회 기록. 이후 불변
accessed: "2026-07-31"
---
```

필드명은 CSL-JSON 원어 그대로다 — 대문자 `ISBN`/`DOI`/`URL`, 접근일은 `accessed`,
컨퍼런스명은 `event-title`, 영상 러닝타임은 `dimensions`. arXiv는
`number` + `publisher: "arXiv"`, RFC는 `number` + `collection-title` + `authority`.

**날짜와 번호는 반드시 따옴표 문자열로 적는다.** 따옴표가 없으면 YAML이
`2026-08-05`를 날짜 객체로, arXiv ID `2405.14831`을 부동소수점으로 바꿔 놓는다.
스키마가 그 실수를 거부한다.

확장 필드는 셋뿐이다: `snapshot`(로컬 스냅샷 루트), `snapshot_sha256`(변조 증거),
`custom: {archive-url: …}`(웨이백 URL). 그 밖에 필요한 CSL 필드가 생기면
`schema/source.yaml`에 선언 + 소비자 명시 + `migrations.md` 기록을 거친다.

원서와 번역서가 둘 다 있으면 **원서를 ingest한다.** 번역서는 확립 역어의 참조원으로만 쓴다.

## 5. 허브

허브는 포인터만 담는 `synthesis` 페이지다 — 링크 + 한 줄 설명, 자기 주장(claim) 없음.
그래서 각주도 `sources`도 없다. 본문 발췌·수치 복제는 금지다(진입점 부패 벡터).

**이름 범위 = 현재 내용 범위.** "데이터 아키텍처" 아래 도메인 중심 내용만 있으면
그 이름은 이미 과대 포장이고, 다른 계열이 들어오는 순간 description이 거짓이 된다.
이름을 내용만큼 좁게 잡으면 범위가 자랄 때 허브가 자라는 게 아니라 **형제 허브가
생기므로**, 이름도 description도 낡을 일이 없다. description은 편집할 때마다 재생성한다.

**크기와 분할.** 허브의 예산은 1–2k 토큰이다. `## Hubs` 목록은 10–30개, 허브의 링크가
~40개를 넘으면 lint(`hub-split-hint`)가 분할 후보로 올린다. 분할은 **부모–자식 패턴**이다
— 옛 허브가 자식 허브들을 가리키는 부모로 남으므로 가리키던 링크가 깨지지 않는다.
축을 정하고 링크를 배정하는 판단은 사람이 하고, 실행 실수는 게이트가 잡는다
(깨진 링크 = validate, 배정 누락 = orphan lint, 여전한 비대 = hub-split-hint 재발화).

고차수 허브가 검색을 망가뜨리지 않는 것은 도구가 보장한다 — 이웃 탐색이 차수
가중이라 허브 경유는 자동 강등된다. 분할이 지키는 것은 진입점 예산과 훑기 가능성이다.

## 6. 이름과 경로

### 개념 슬러그 = 파일명 = ID

영문 소문자 kebab, 80자 이내. 한국어 개념은 로마자화하지 말고 **영어 개념명으로 번역**한다
(확립 용어 우선). title은 한국어를 유지한다.

- 충돌은 **의미 한정자**로 푼다: `consistency-acid` vs `consistency-eventual`.
- 숫자 접미(`raft-2`) 금지. `raft-read-v2`처럼 의미 있는 한정자는 괜찮다.
- **날짜·번호 접두 금지(무예외).** `3-tier-architecture`는 안 되고
  `three-tier-architecture`로 쓴다.

### citekey = 파일명 = ID

`저자성last연도[-슬러그]`, 문자는 `[a-z0-9_.-]`만. 콜론·공백·대문자는 각주 앵커를 깨뜨린다.
같은 저자·연도 충돌에만 `-2`를 붙인다. 한국어 저자는 소스에 인쇄된 영문 표기를 우선하고,
없으면 발급 시점 RR 로마자화로 고정한다.

**유일성은 KB 안에서만 요구된다.** 저장소 전역 참조가 필요하면 `<kb>/<슬러그>`를 쓰는데,
이건 경로에서 파생되는 것이지 어딘가에 저장되는 값이 아니다.

### 발급 후 불변

이름은 바꾸지 않는다. 개명·이동은 `tools/rename`으로만 한다 — 링크 재작성, redirect
스텁 생성, 사후 링크 검사가 한 묶음이다. 손으로 `mv`하면 링크가 조용히 깨진다.

### 링크

| 무엇 | 형식 | 왜 |
|---|---|---|
| 본문 링크 | 파일 상대 경로 `../sources/x.md` | GitHub와 Obsidian이 합의하는 유일 형식 |
| frontmatter 경로 | 저장소 루트 기준 `/it/sources/x.md` | 인용하는 파일이 이동해도 안 깨진다 |
| KB 간 참조 | `qmd://<컬렉션>/<경로>` | 비권장 — lint가 warn한다 |

본문 링크는 **KB 안에서 닫혀야 한다.** 다른 KB를 참조하고 싶어지면 그건 대개 KB 경계를
잘못 그었다는 신호다. wikilink(`[[…]]`)는 쓰지 않는다 — CommonMark + GFM(테이블·각주)만.

OS 절대경로(`/Users/...`)는 어디에도 적지 않는다.

## 7. 쓰기 정책

계층마다 다르다.

- **`sources/`** — 사람이 큐레이션한다. 넣을 가치의 판단은 스크립트화되지 않는다.
- **`concepts/`** — LLM이 쓸 수 있다. 단 `inbox/`에 착지해서 diff 리뷰를 거친다.
  리뷰 기준은 **무해성·구조**(각주 없는 claim, 기존 claim 훼손, 명백한 오류)이지
  내용의 전수 정확성이 아니다. 정확성은 쓰는 시점에 검증한다(review-on-read):
  기계가 쓴 claim을 실제로 확인했으면 `verified`를 추가해 승급시킨다.
- **`synthesis/`** — 사람이 쓰고 전수 리뷰한다. 경계 기준은 **누가 썼는가**이지
  내용이 얼마나 종합적인가가 아니다. **기존 허브의 개정 초안은 LLM이 쓸 수 있고
  `inbox/`에 같은 슬러그로 착지해 전수 리뷰를 지난다** — 승인이 저작 주체를 사람으로
  넘긴다(kb-ingest 8단계). **창설은 사람 몫이다**: 짝 없는 synthesis 초안은 validate
  오류다. 이 경로를 연 근거는 `schema/migrations.md` 2026-09-29 항목이다.

## 8. 스키마를 바꿀 때

1. `tools/affected`로 영향 파일·KB를 **조회한다.** 기억하지 말 것.
2. **추가만 한다.** 기존 키의 의미를 바꾸거나 이름을 갈아끼우지 않는다.
   개명이 필요하면 새 키를 추가하고 매핑을 남긴다.
3. 은퇴시킨 키 이름은 **영구 결번**이다. `schema/migrations.md`의 결번 대장에 적고,
   validate가 그 목록을 신규 파일과 대조한다.
4. 스키마 변경과 콘텐츠 마이그레이션은 **같은 커밋**에 넣는다.

파일마다 `schema_version`을 적지 않는다. 콘텐츠 파일은 재작성되지 않으므로 그 필드는
시간이 지나면 거짓말을 한다 — git 커밋 날짜와 `migrations.md`가 해석을 제공한다.

# 규칙 집세 심사 (P5 표결지)

`05-검사없는-규칙.md`가 확인한 사실에서 출발한다. 규칙 132개 중 55개가 아무
검사도 받지 않고, 이 저장소의 실측은 "검사 없는 규칙은 지켜지지 않는다"이다.
검사 없는 규칙은 읽기 비용만 청구하며 떠 있고, 다른 규칙의 무게까지 떨어뜨린다.

이 문서는 55건마다 처분 권고와 근거 한 줄을 단 표결지다. 판정은 사람이 한다.
규칙 번호와 원문 위치는 05 문서의 대조표를 그대로 따른다.

## 표결 방법

분류마다 통째로 승인하거나, 개별 번호를 골라 다른 분류로 옮기면 된다. 처분은
넷이다.

1. 붙임: 검사를 구현한다. lint 결과 종류가 새로 생긴다.
2. 승격: 미시 규칙 여러 개를 원칙 한 줄로 접고 세부 조문은 지운다.
3. 명시: 기계가 검사할 수 없음을 문서에 적고 남긴다. 적지 않으면 나중에 읽는
   사람이 "통과했으니 맞다"고 잘못 믿는다.
4. 삭제: 규칙 자체를 지운다.

## 이미 해소된 것 (1건)

- R112 승급 뒤 재색인: promote가 사슬로 강제하고, 세대 스탬프가 소비 시점에
  대조한다. 목록에서 뺀다.

## 가. 붙임 권고 (15건)

전부 05 문서 4.1절이 "붙이면 된다"고 판정한 것이거나 이번 감사에서 길이 확인된
것이다. 위일수록 실익이 크다.

- R106 트레일러 블록 형식: git interpret-trailers 대조 한 번. 실측 10건 중 5건이
  이미 파손된 채 통과 중이다.
- R52 목차 형식: 링크 불릿 목록만 인정하도록 좁힌다. 폐기된 인라인형이 검출
  0건으로 통과한 실측이 있다.
- R40 citekey 구조: 저자성과 연도 문법 검증. 저자도 연도도 없는 키가 통과한
  실측이 있다.
- R84 허브의 각주와 sources 금지: synthesis 페이지의 sources 선언과 각주를
  검출한다.
- R27 확장 필드 3종 한정: 스키마에 없는 키를 리포트한다.
- R28 태그 필드 금지: R27과 같은 검사 하나로 함께 덮인다.
- R69 NFC 고정: 정규화 후 비교 한 줄. 색인 단계에는 이미 있고 저장 파일에만 없다.
- R62 버전 조건의 자리: 고정 낱말이라 AST로 인용 블록인지 자식 불릿인지 판정된다.
- R63 버전 조건의 기호 금지: 정확 문자 대조. plaincheck과 같은 방식이다.
- R74 펜스 안 셸 프롬프트 정돈: 펜스 첫 글자 대조. 규약에 실린 실패 사례가 바로
  이것이다.
- R87 Hubs 목록 10에서 30: 진입 문서의 절 링크를 세면 된다. 절을 찾는 코드는
  이미 있다.
- R113 커밋 제목 접두: commit-msg 훅 한 줄. 훅 자리는 이미 있다.
- R78 펜스 앞 산문 한 줄: code-unsourced가 읽는 같은 스택에서 판정된다.
- R83 숫자 confidence 금지: 어휘 대조로 흔한 표기를 잡는다. 불완전함은 지침에
  명시한다.
- R70 표 안의 파이프: 파서가 표를 이미 켜 두었다.

## 나. 승격 권고 (7건을 원칙 2줄로)

세부 조문을 지우고 상위 원칙만 남긴다. 검사는 가에서 붙는 것들이 지탱한다.

- R71, R75, R77 (코드 표기 세부 3건): "코드는 소스에 있는 것만, 개념당 대표 펜스
  하나, 출력은 명령과 가른다"를 SCHEMA의 한 줄로 접는다. 펜스 개수(R77)는
  세기 검사를 원하면 가로 옮겨도 된다.
- R64, R65, R66, R67 (버전 조건과 수식 세부 4건): "버전 조건과 수식은 성문 형식을
  따른다"로 접고, 기계가 볼 수 있는 부분(R62, R63)의 검사가 지탱한다. R65
  (버전 조건이 있으면 stale_after를 뗀다)는 frontmatter 대조가 가능하므로 가로
  옮길 수도 있다.

## 다. 명시 권고 (32건)

기계가 못 보는 이유별로 갈랐다. 문서에 "검사 없음, 담당은 누구"를 적는 것까지가
처분이다.

내용 판단 (6건, 담당은 리뷰와 사람):

- R16 모순 대상은 사실 충돌만: 사실인지 방법론인지는 판단이다.
- R20 버전 갈림 지식에 stale_after 금지: "버전으로 갈리는가"가 판단이다.
- R49 한 페이지 하나의 질문: overlap이 사후 간접 신호만 준다.
- R85 허브에 본문 복제 금지: 복제인지 요약인지는 판단이다.
- R86 허브 이름 범위: 범위 적정성은 판단이다.
- R90 허브 분할은 부모 자식 패턴: 구조 선택은 판단이다.

절차와 구현 (14건, 담당은 도구 구조와 원장):

- R29 스키마는 추가만: migrations 절차가 담당. R31 스키마와 콘텐츠 동일 커밋,
  R34 변경 전 affected 실행, R35 통짜 재작성 금지, R95 flat 시작, R96 파서 우선,
  R97 fail-loud, R104 1런 1커밋도 같은 부류다. 전부 절차 규율이며 위반의 흔적은
  원장과 리뷰가 잡는다.
- R32 파일별 schema_version 금지: R27 검사가 붙으면 미선언 키로 함께 잡히므로
  삭제해도 된다 (표결 사항).
- R43 개명은 rename 경유만, R44 O_EXCL 생성: 도구가 유일 경로라는 구조 자체가
  집행이다.
- R45 본문 링크는 파일 상대 경로: 어긋나면 링크 해석 실패로 간접 검출되고
  relocate가 형식을 강제하므로 삭제도 가능하다 (표결 사항).
- R57 분할 병합 시 redirect 스텁: rename 도구가 만들고, 빠뜨림은 깨진 링크로
  드러난다.
- R94 운영 로그 git 금지: 무엇이 운영 로그인지가 판단이다.

세션 안 규칙 (12건, 담당은 스킬 evals, 저장소에 흔적이 없음):

- R115 기억보다 KB 먼저, R117 출처 라벨, R118 공백 선언, R119 저장 3문,
  R120 verified는 도구로만, R121 KB 신설 금지 기본, R123 공백 없으면 후보 없음,
  R124 논문 자격 4문, R125 자기 판단 반입 금지, R130 명사구 제목, R131 한글
  파일명 조회법, R132 archive 재독. 전부 세션 행동 규칙이라 검사 자리는 스킬
  evals다. evals 복구(재실행과 미커버 스킬 2종)가 선행 조건이며, 그때까지는
  "검사 없음, evals 담당 예정"으로 명시한다.

하나의 질문: **모델 하나를 고치는 대신 여러 모델을 합치면 무엇을 얻는가.**

## 파인 튜닝과 무엇이 다른가

- 규정 — **파인 튜닝이 모델 하나를 변경해 맞춤 모델을 만들게 해 준다면, 모델 병합(model merging)은
  여러 모델을 결합해 맞춤 모델을 만들게 해 준다. 모델 병합은 파인 튜닝 단독보다 더 큰 유연성을
  제공한다. 이용 가능한 두 모델을 가져다 합쳐 새롭고, 바라건대 더 유용한 모델을 만들 수 있다. 합치기
  전에 구성 모델 중 일부나 전부를 파인 튜닝할 수도 있다** (7장, p.347).[^huyen2025]
- GPU 없이도 된다 — **병합된 모델을 더 파인 튜닝할 필요는 없지만 파인 튜닝으로 성능이 흔히 개선될 수
  있다. 파인 튜닝 없이 모델 병합은 GPU 없이 이뤄질 수 있어, 컴퓨트에 많이 접근할 수 없는 독립
  모델 개발자에게 병합이 특히 매력적이다** (7장, p.347).[^huyen2025]
- 저자가 이 절을 즐겁게 썼다고 말하는 이유 — **여러 모델을 결합하는 것이 새로운 개념은 아니지만,
  새로운 유형의 모델과 파인 튜닝 기법이 많은 창의적인 모델 병합 기법에 영감을 주어 이 절을 특히
  쓰기 재미있게 만들었다** (7장, p.332).[^huyen2025]

## 덧붙는 가치가 나오는 두 자리

- 목표 — **모델 병합의 목표는 구성 모델을 전부 따로 쓰는 것보다 더 많은 가치를 제공하는 단일 모델을
  만드는 것이다** (7장, p.347).[^huyen2025]
- 첫째 — **덧붙는 가치는 개선된 성능에서 올 수 있다. 예컨대 같은 과제에서 서로 다른 것을 잘하는 모델
  둘이 있으면, 그것들을 합쳐 그 과제에서 둘 모두보다 나은 모델 하나를 만들 수 있다. 질문의 앞 60%에
  답할 수 있는 모델 하나와 뒤 60%에 답할 수 있는 다른 모델 하나를 상상해 보라. 결합하면 아마
  질문의 80%에 답할 수 있을 것이다** (7장, p.347).[^huyen2025]
- 둘째 — **덧붙는 가치는 줄어든 메모리 발자국에서도 올 수 있고 이는 비용 절감으로 이어진다. 예컨대
  서로 다른 과제를 할 수 있는 모델 둘이 있으면, 그것들을 두 과제를 다 하되 파라미터는 더 적은 모델
  하나로 합칠 수 있다. 이는 어댑터 기반 모델에 특히 매력적이다. 같은 베이스 모델 위에 파인 튜닝된
  두 모델이 주어지면 그 어댑터들을 단일 어댑터로 결합할 수 있다** (7장, p.347).[^huyen2025]

## 멀티태스크 파인 튜닝의 세 접근

- **모델 병합의 중요한 유스케이스 하나가 멀티태스크 파인 튜닝이다. 모델 병합 없이 여러 과제를 위해
  모델을 파인 튜닝하려면 일반적으로 다음 접근 중 하나를 따라야 한다** (7장, pp.347–348):[^huyen2025]
  - **동시 파인 튜닝(simultaneous finetuning) — 모든 과제에 대한 예시를 담은 데이터셋을 만들고 그
    데이터셋으로 모델을 파인 튜닝해 모델이 모든 과제를 동시에 배우게 한다. 그러나 일반적으로 여러
    기술을 동시에 배우기가 더 어렵기 때문에 이 접근은 통상 더 많은 데이터와 더 많은 훈련을 요구한다.**
  - **순차 파인 튜닝(sequential finetuning) — 각 과제에 대해 따로, 그러나 순차적으로 모델을 파인
    튜닝할 수 있다. 과제 A로 모델을 훈련한 뒤 과제 B로 훈련하는 식이다. 가정은 모델이 한 번에 한
    과제를 배우는 것이 더 쉽다는 것이다. 안타깝게도 신경망은 파국적 망각(catastrophic forgetting)에
    걸리기 쉽다(Kirkpatrick et al., 2016). 새 과제로 훈련될 때 모델이 옛 과제를 하는 법을 잊어버려
    앞선 과제의 성능이 크게 떨어질 수 있다.**
- 셋째 길 — **모델 병합은 멀티태스크 파인 튜닝의 또 다른 방법을 제공한다. 서로 다른 과제에 대해
  모델을 따로, 그러나 병렬로 파인 튜닝할 수 있다. 끝나면 이 서로 다른 모델들이 하나로 병합된다. 각
  과제에 대해 따로 파인 튜닝하는 것은 모델이 그 과제를 더 잘 배우게 해 준다. 순차 학습이 없으므로
  파국적 망각의 위험이 더 적다** (7장, p.348).[^huyen2025]

## 온디바이스 배포

- **모델 병합은 휴대폰·노트북·자동차·스마트워치·창고 로봇 같은 기기에 모델을 배포해야 할 때도
  매력적이다. 온디바이스 배포는 제한된 기기 내 메모리 용량 때문에 흔히 어렵다. 서로 다른 과제를 위한
  여러 모델을 기기에 밀어 넣는 대신, 이 모델들을 하나로 병합해 훨씬 적은 메모리를 요구하면서 여러
  과제를 수행할 수 있는 모델을 만들 수 있다** (7장, p.348).[^huyen2025]
- 왜 기기에 두는가 — **온디바이스 배포는 데이터가 기기를 떠날 수 없는(흔히 사생활 때문) 유스케이스나
  인터넷 접속이 제한적이거나 불안정한 곳에서 필요하다. 온디바이스 배포는 추론 비용도 크게 줄일 수
  있다. 사용자 기기로 오프로드할 수 있는 계산이 많을수록 데이터 센터에 낼 돈이 줄어든다** (7장,
  p.348).[^huyen2025]
  - 각주 — **저자의 책 『Designing Machine Learning Systems』에 "ML on the Cloud and on the Edge"
    절이 있다** (7장, p.348 각주 28).[^huyen2025]

## 연합 학습

- **모델 병합은 연합 학습(federated learning)(McMahan et al., 2016)을 하는 한 방법이기도 한데,
  연합 학습에서는 여러 기기가 별개의 데이터를 써서 같은 모델을 훈련한다. 예컨대 모델 X를 여러 기기에
  배포하면 X의 각 사본이 기기 내 데이터로 계속 학습할 수 있다. 얼마 뒤에는 서로 다른 데이터로 훈련된
  X의 사본이 여럿 생긴다. 이 사본들을 하나로 병합해 구성 모델 전부의 학습을 담은 새 베이스 모델
  하나를 만들 수 있다** (7장, p.348).[^huyen2025]

## 앙상블과 병합

- 계보 — **모델을 결합해 더 나은 성능을 얻는다는 발상은 모델 앙상블 방법(model ensemble methods)에서
  시작되었다. 위키백과에 따르면 앙상블은 "구성 학습 알고리즘 어느 것 단독으로 얻을 수 있는 것보다 더
  나은 예측 성능을 얻으려고 여러 학습 알고리즘"을 결합한다** (7장, p.348).[^huyen2025]
- 차이 — **모델 병합이 통상 구성 모델의 파라미터를 함께 섞는 것을 수반한다면, 앙상블은 통상 각 구성
  모델을 온전히 둔 채 모델의 출력만 결합한다** (7장, p.348).[^huyen2025]
- 앙상블의 실물과 그 비용 — **예컨대 앙상블에서는 질의가 주어지면 모델 셋을 써서 서로 다른 답 셋을
  생성할 수 있다. 그다음 이 세 답에 기반해 단순 다수결이나 또 다른 훈련 가능한 ML 모듈을 써서 최종
  답을 생성한다. 앙상블은 일반적으로 성능을 개선할 수 있지만 요청당 여러 추론 호출을 요구하므로 추론
  비용이 더 높다** (7장, p.349, Figure 7-13).[^huyen2025]
  - 각주 — **앙상블 방법에 대해서는 저자의 책 『Designing Machine Learning Systems』에서 더 읽을 수
    있다** (7장, p.349 각주 29).[^huyen2025]
- 지금 어디에 있는가 — **모델 앙상블이 리더보드를 지배하곤 했던 것처럼, 허깅 페이스의 Open LLM
  Leaderboard 상위의 많은 모델이 병합된 모델이다** (7장, p.349).[^huyen2025]

## AI가 여는 시뮬레이션

- 절이 여는 자리 — **사람이 데이터를 생성하는 방법이 사실상 무한하듯 AI도 여러 방식으로 그렇게 할 수
  있다. 여기서 논하는 기법은 망라적이지 않지만 좋은 개관을 줄 것이다** (8장, p.386).[^huyen2025]
- **AI 모델은 시뮬레이션에 많은 새 가능성을 연다. AI는 임의 프로그램의 결과를 시뮬레이션할 수 있다.
  예컨대 "StableToolBench"(Guo et al., 2024)는 API를 실제로 호출하지 않고 AI로 시뮬레이션하는 방법을
  시연한다. API 집합과 상호작용하도록 모델을 훈련하고 싶다고 하자. 실제 API 호출을 하는 대신 —
  비싸거나 느릴 수 있다 — AI 모델을 써서 그 호출의 기대 결과를 시뮬레이션할 수 있다** (8장,
  p.386).[^huyen2025]

## 자가 대국

- **AI는 사람을 시뮬레이션할 수 있다. 예컨대 체스를 두는 봇을 훈련하고 싶다고 하자. 사람이 두는
  경기는 너무 오래 걸릴 수 있다. AI 선수끼리의 대국은 훨씬 빠를 것이다. Dota 2 봇을 훈련하려고
  OpenAI는 봇이 매일 약 180년치의 경기를 두게 하는 시뮬레이터를 썼다. 봇은 자기 자신과 겨루며
  배웠는데, 이는 자가 대국(self-play)이라 불리는 접근으로 시간이 지나며 전략을 개발하고 다듬는 데
  도움이 되었다(OpenAI, 2019). 비슷하게 DeepMind는 자가 대국을 써서 수백만 판의 바둑에서 데이터를
  모아 AlphaGo를 훈련했다(Silver et al., 2016)** (8장, p.387).[^huyen2025]
- 게임 밖으로 — **자가 대국은 게임 봇뿐 아니라 일반 에이전트에도 유용하다. AI들이 서로 다른 전략으로
  협상하게 해 어느 것이 더 잘 통하는지 볼 수 있다. 모델의 한 버전이 문제를 가진 고객 역을, 다른
  버전이 고객 지원 상담원 역을 하게 할 수 있다** (8장, p.387).[^huyen2025]

## 재구성과 번역

- **AI의 재구성(paraphrasing)과 번역 능력은 기존 데이터셋을 증강하는 데 쓰일 수 있다. 예컨대 질의
  "How to reset my password?"가 주어지면 AI는 그것을 재구성해 새 질의 셋을 만들 수 있다** (8장,
  p.387):[^huyen2025]
  1. **"I forgot my password."**
  2. **"How can I change my password?"**
  3. **"Steps to reset passwords."**
- 규모의 실물 — **Yu et al.(2023)은 MATH와 GSM-8K의 예제 15,000개를 서로 다른 방식으로 다시 써서
  거의 400,000개 예제의 새 데이터셋 MetaMath를 만들었다. 그들은 이 새 데이터셋으로 훈련한 자기 모델이
  관련 수학 벤치마크에서 더 큰 모델들을 능가함을 보였다** (8장, p.387).[^huyen2025]
- 저자원 언어 — **고자원 언어(온라인에 더 많이 있는)의 데이터를 저자원 언어로 번역해 저자원 언어의
  모델을 훈련하는 데 AI를 쓰는 것이 흔하다. 이는 케추아어나 라오어 같은 저자원 언어에 특화된 작은
  모델을 훈련하는 데 유용하다** (8장, p.387).[^huyen2025] 언어별 데이터 편중 자체는
  [다국어 모델](../concepts/multilingual-models.md)에 있다.

## 역번역

- **번역의 품질은 역번역(back-translation)으로 검증할 수 있다. 원래 영어 문장이 X이고 번역된 라오어
  문장이 Y라고 하자. 다른 모델을 써서 그 번역을 원래 언어로 되돌려 번역해 X′를 얻은 뒤 X′를 원래
  문장 X와 비교할 수 있다. 둘이 매우 다르면 번역 Y는 나쁠 가능성이 높다** (8장,
  p.387).[^huyen2025]
- 프로그래밍 언어로 — **AI는 자연어뿐 아니라 프로그래밍 언어도 번역할 수 있다. 한 언어로 쓰인 코드를
  다른 언어로 번역하는 데 AI를 쓸 수 있다. Llama 3 저자들은 자기 SFT 데이터셋의 코드 번역을 써서 더
  넓은 범위의 프로그래밍 언어를 다뤘다. 실제로 Llama 3의 훈련은 합성 데이터에 크게 의존하며 저자들은
  유용한 데이터를 생성하는 창의적인 기법을 많이 썼다** (8장, p.387).[^huyen2025]
- 코드 문서화에 역번역을 쓴 방식 — **예컨대 그들은 역번역을 써서 코드 설명과 문서를 생성했다. 코드
  조각에서 시작해 AI로 설명과 문서를 생성했다. 그다음 다시 AI를 써서 그 설명과 문서에서 코드 조각을
  생성했다. 생성된 코드가 원본에 충실하다고 간주될 때만 그 설명과 문서가 모델을 파인 튜닝하는 데
  쓰인다** (8장, p.388).[^huyen2025]

## 사전 훈련보다 사후 훈련에 더 쓰인다

- **AI는 사전 훈련과 사후 훈련 양쪽의 데이터를 생성할 수 있지만, 합성 데이터는 사전 훈련보다 사후
  훈련에 훨씬 더 자주 의도적으로 포함된다. 한 가지 가능한 설명은 사전 훈련의 목표가 모델의 지식을
  늘리는 것인데, AI가 기존 지식을 다른 형식으로 합성할 수는 있어도 새 지식을 합성하기는 더 어렵다는
  것이다** (8장, p.388).[^huyen2025]
- 그래도 사전 훈련 쪽 실물이 있다 — **그러나 인터넷이 AI 생성 콘텐츠로 넘쳐 나면서 인터넷 데이터에
  의존하는 모델은 이미 합성 데이터로 사전 훈련되었을 가능성이 높다. Cosmopedia(Allal et al., 2024)
  같은 합성 데이터셋도 있는데, 이는 Mixtral-8x7B-Instruct-v0.1(Jiang et al., 2024)이 생성한 합성
  교과서·블로그 글·이야기·게시물·WikiHow 문서 250억 토큰 모음이다** (8장, p.388).[^huyen2025]
- 선호 데이터 쪽 — **사후 훈련을 위한 데이터 합성도 더 흔해지는데, 지시 데이터와 선호 데이터를 모두
  포함한 사후 훈련 데이터가 일반적으로 만드는 데 가장 많은 노력을 요구하기 때문이다. AI를 써서 여러
  응답 중 더 나은 응답을 고르는 것은 더 직접적이다 — 그 대부분은 이미 3장에서 다뤘다. 주된 난제는
  모델의 편향, 예컨대 모델이 첫 번째 응답을 선호하는 첫 위치 편향(first-position bias)을 고려하는
  것이다. 이를 피하려고 NVIDIA 연구자들은 AI 판정자에게 두 번, 한 번은 응답 순서를 바꿔서 물었다.
  그들은 AI 판정자가 두 번 모두 같은 승자를 골랐을 때만 유효한 (프롬프트, 이긴 것, 진 것) 삼중항을
  택했다(NVIDIA, 2024)** (8장, p.388).[^huyen2025] 그 편향의 목록은
  [AI 판정자의 한계](../concepts/ai-judge-limitations.md)에 있다.

## 지시 데이터 합성

- **지시 파인 튜닝 중 각 예제는 지시와 응답을 포함한다. AI는 지시를 합성하거나 응답을 합성하거나 둘
  다에 쓰일 수 있다. 예컨대 AI로 지시를 생성하고 사람이 응답을 쓰게 할 수 있다. 사람이 지시를 쓰고
  AI가 응답을 생성하게 할 수도 있다** (8장, p.388).[^huyen2025]
  - **지시 생성의 경우, 유스케이스를 덮기에 충분한 지시를 생성하도록 데이터셋에 원하는 주제·키워드
    그리고/또는 지시 유형의 목록에서 시작할 수 있다. 그다음 이 목록의 각 항목에 대해 일정 수의 지시를
    생성한다. 템플릿 집합에서 시작해 템플릿당 일정 수의 예제를 생성할 수도 있다. 주제 목록과 템플릿
    모두 AI가 생성할 수 있다는 점에 유의하라** (8장, p.388).[^huyen2025]
  - **응답 생성의 경우, 지시당 하나 이상의 응답을 생성할 수 있다** (8장, p.389).[^huyen2025]
- UltraChat — **예컨대 다중 턴 대화 데이터셋 UltraChat(Ding et al., 2023)을 만들려고 저자들은 먼저
  ChatGPT에 기술·음식과 음료·패션·자연·교육·금융·여행 등 우리 일상의 다양한 측면에 관한 주제 30개를
  생성하게 했다. 각 주제에 대해 ChatGPT에 하위 주제 30~50개를 생성하게 했다. 그다음 같은 모델을 써서
  이 하위 주제들에 대한 지시와 그에 대응하는 응답을 생성했다** (8장, p.389).[^huyen2025]
- Alpaca — **비슷하게 Alpaca(Taori et al., 2023)를 훈련하려고 스탠퍼드 연구자들은 Self-Instruct 씨앗
  데이터셋(Wang et al., 2022)의 (지시, 응답) 예제 175개에서 시작했다. 이 예제들은 원래 다양하고
  흥미로운 사용 범위를 덮도록 쓰였다. Alpaca 저자들은 그다음 GPT-3 모델인 text-davinci-003을 써서 이
  씨앗 예제를 본뜬 (지시, 응답) 쌍 52,000개를 생성했다** (8장, p.389).[^huyen2025] 도판이 그 대비로
  싣는 두 예다 (8장, p.389, Figure 8-5):[^huyen2025]

  | | Instruction | Output |
  |---|---|---|
  | Example seed task | Brainstorm a list of possible New Year's resolutions. | Lose weight / Exercise more / Eat healthier |
  | Example generated task | Brainstorm creative ideas for designing a conference room. | … incorporating flexible components, such as moveable walls and furniture … |

## 역방향 지시

- 긴 응답이 어려운 데서 나온 발상 — **특정 특성을 가진 지시 데이터를 합성하는 창의적 방법도 많다.
  예컨대 사람이 짧은 콘텐츠보다 긴 콘텐츠를 쓰기 더 어렵듯, AI도 짧은 지시보다 고품질의 긴 응답을
  생성하기 더 어렵다. 응답이 길수록 AI가 환각할 여지가 커진다. AI가 생성한 지시와 사람이 생성한
  응답을 쓰면 어떨까?** 그 접근의 정의다 (8장, p.389):[^huyen2025]

  > Some researchers, such as Köksal et al. (2023), Li et al. (2023), and Chen et al. (2023),
  > follow the *reverse instruction* approach: take existing long-form, high-quality content like
  > stories, books, and Wikipedia articles and use AI to generate prompts that would elicit such
  > content. This yields higher-quality instruction data, avoiding AI-generated hallucinations in
  > the responses.

- 그것을 반복으로 돌리기 — **역방향 지시를 써서 수동으로 주석된 데이터를 추가하지 않고 점점 더 강력한
  모델을 개발하는 것이 가능하다. Li et al.(2023)은 이것이 어떻게 작동하는지 보인다** (8장,
  p.390):[^huyen2025]
  1. **약한 모델을 훈련할 소수의 씨앗 예제에서 시작한다.**
  2. **이 약한 모델을 써서 기존 고품질 콘텐츠에 대한 지시를 생성해 고품질 지시 데이터를 만든다.**
  3. **이 새 고품질 지시 데이터로 약한 모델을 파인 튜닝한다.**
  4. **바람직한 성능에 도달할 때까지 반복한다.**
  - 각주 — **이것의 함의는 이론상 자기 자신을 계속 개선할 수 있는 모델을 훈련하는 것이 가능하다는
    것이다. 그러나 이것이 실제로 가능한지는 다른 이야기다** (8장, p.390 각주 11).[^huyen2025]

## 롱컨텍스트 데이터 만들기

- **창의적 접근 하나는 합성 데이터를 써서 더 긴 맥락을 이해하도록 모델을 파인 튜닝하는 것이다. 예컨대
  현재 모델이 최대 8K 토큰을 처리하는데 128K 토큰을 다루게 하고 싶다면 롱컨텍스트 파인 튜닝 과정은
  다음과 같이 보일 수 있다** (8장, p.390):[^huyen2025]
  - **긴 문서를 더 짧은 청크(예: 8K 미만)로 쪼갠다.**
  - **각 짧은 청크에 대해 (질문, 답) 쌍을 여러 개 생성한다.**
  - **각 (질문, 답) 쌍에 대해 8K 토큰을 넘을 수 있지만 목표 길이보다는 짧은 원래의 긴 문서를 맥락으로
    쓴다. 이는 모델이 확장된 맥락을 써서 질문에 답하도록 훈련한다.**
- 그 능력의 다른 축은 [맥락 길이와 효율](../concepts/context-length-and-efficiency.md)에 있다.

## Llama 3의 코딩 데이터 파이프라인

- **Llama 3 논문(Dubey et al., 2024)의 세부 수준은 그것을 지시 데이터 합성의 훌륭한 사례 연구로
  만든다. Llama 3가 데이터를 합성한 두 방법 — 코드 번역과 코드 역번역 — 은 이미 언급했다. 이 두
  방법은 기존 코드 조각에서 더 많은 데이터를 생성한다. 그러나 저자들은 AI를 써서 코딩 지시 데이터를
  처음부터 합성하기도 했으며, 다음 워크플로를 썼다** (8장, p.390):[^huyen2025]
  1. **AI를 써서 다양한 주제 범위에 걸친 프로그래밍 문제 설명의 큰 모음을 생성한다.**
  2. **문제 설명과 프로그래밍 언어가 주어지면 해법을 생성한다. Dubey et al.은 좋은 프로그래밍의 일반
     규칙과 CoT 추론을 포함하는 것이 응답 품질을 개선하는 데 도움이 됨을 발견했다.**
- **생성된 데이터의 품질을 확보하려고 그들은 엄격한 정확성 분석과 오류 수정 파이프라인을 썼다** (8장,
  p.391):[^huyen2025]
  1. **생성된 코드를 파서와 린터에 돌려 누락된 임포트나 초기화되지 않은 변수 같은 구문 오류를 잡는다.**
  2. **단위 테스트를 써서 런타임 실행 오류를 잡는다. 흥미롭게도 그들은 이 단위 테스트를 생성하는 데
     AI를 썼다.**
  3. **해법이 어느 단계에서든 실패하면 모델에 프롬프트해 코드를 수정하게 한다. 프롬프트는 원래 문제
     설명·잘못된 해법·파서와 린터와 단위 테스트의 피드백을 포함했다. 모든 검사를 통과한 예제만 최종
     지도 파인 튜닝 데이터셋에 포함된다.**
  - 각주가 옮기는 관찰 — **그들은 "해법의 약 20%가 처음에는 틀렸지만 스스로 수정되었음을 관찰했으며,
    이는 모델이 실행 피드백에서 배워 성능을 개선했음을 시사한다"** (8장, p.391 각주
    12).[^huyen2025]
- 세 방법을 합친 전체 흐름이다 — **코드 번역·코드 역번역·코드 생성 세 방법을 모두 합친 Llama 3의 데이터
  합성 워크플로는 꽤 인상적이다** (8장, p.391):[^huyen2025]
  1. **AI를 써서 문제 설명을 생성한다.**
  2. **AI를 써서 각 문제의 해법을 서로 다른 프로그래밍 언어로 생성한다.**
  3. **AI를 써서 생성된 코드를 테스트할 단위 테스트를 생성한다.**
  4. **AI에 프롬프트해 합성된 코드의 오류를 고친다.**
  5. **AI를 써서 생성된 코드를 다른 프로그래밍 언어로 번역한다. 테스트를 통과하지 못하는 번역된 코드를
     걸러 낸다.**
  6. **AI를 써서 코드에 대한 대화를 생성하는데, 코드 설명과 문서 추가를 포함한다. 역번역 검증을 통과하지
     못하는 생성된 설명과 문서를 걸러 낸다.**
- 규모 — **이 파이프라인을 써서 Dubey et al.은 Llama 3.1의 지도 파인 튜닝을 위해 270만 개가 넘는 합성
  코딩 관련 예제를 생성할 수 있었다** (8장, p.391).[^huyen2025]

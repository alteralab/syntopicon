## 하나의 질문

**이번 이터레이션이 데이터 메시를 목표에 가깝게 옮겼는지 무엇으로 아는가.**

- 시간 척도가 도구를 가른다 — **채택 단계가 몇 달 또는 몇 년이라는 큰 시간 척도에서 거시
  수준으로 데이터 메시 실행을 안내하는 반면, **목적 적합성 함수(objective fitness
  functions)** 집합의 지속적 측정과 추적은 작은 증분과 짧은 반복 실행 주기를 안내한다**
  (15장, p.294).[^dehghani2022] 거시 쪽이
  [데이터 메시의 진화적 채택 단계](../concepts/data-mesh-adoption-phases.md)다.

## 적합성 함수의 정의

저자는 별도 박스로 정의를 놓는다 (15장, p.294):[^dehghani2022]

> A *fitness function* is an objective function used to summarize how close a prospective
> design solution is to achieving its set aims. In evolutionary computing, the fitness
> function determines whether an algorithm has improved over time. In *Building
> Evolutionary Architectures*, fitness functions objectively guide the iterations of an
> architecture toward its set objectives across multiple dimensions such as performance,
> security, extensibility, etc.
>
> Fitness functions is a concept borrowed from evolutionary computing, which is an
> objective measure used to assess whether the system as a whole is moving toward its
> intended design target and is improving over time, or not.
>
> In the context of data mesh, these objective functions can determine how "fit" the mesh
> implementation is at any point in time, and whether every iteration is moving it closer
> or further from its optimal state of delivering value at scale.

- 함수의 출처가 원칙에 있다 — **데이터 메시의 궁극적 목적은 조직이 분석 목적으로 데이터를
  활용하고 조직 성장·복잡성에 발맞춰 규모에서 데이터로부터 가치를 얻는 능력을 높이는 것이다.
  데이터 메시 원칙 각각이 이 고수준 결과에 기여한다. 따라서 적합성 함수는 각 원칙에서 기대되는
  결과를 겨냥할 수 있다** (15장, p.294).[^dehghani2022]
- 저자가 이 목록의 지위를 낮춘다 — **다음에 소개하는 적합성 함수는 예일 뿐이다. 나는 그것들이
  각 데이터 메시 원칙의 기대 결과에서 어떻게 유도되는지를 시연했다. 당신은 같은 접근을 채택해
  자기 적합성 함수를 만들어 테스트하고 진화시킬 수 있다** (15장, p.296).[^dehghani2022]

## 왜 KPI가 아니라 적합성 함수인가

- 낱말 선택이 의도적이다 — **당신은 내가 핵심 성과 지표(KPI)보다 적합성 함수라는 개념을 썼다는
  것을 알아챘을지 모른다. 두 개념 모두 본질적으로 객관적 지표에 관한 것이고 데이터 메시 실행
  진척의 상태와 추세에 가시성을 주지만, **적합성 함수는 데이터 메시 설계와 구현이 어느 시점에
  얼마나 "적합"한지를 말해 주고, 정말로 중요한 행동과 결과에 초점을 맞춰 옳은 변경을 하고
  부정적 영향을 준 것을 되돌리도록 안내한다**** (15장, p.295).[^dehghani2022]
- 그리고 자동화가 조건으로 붙는다 — **나는 당신이 데이터 메시 실행을 위한 목적 적합성 함수
  집합을 정의하기를 제안한다. 그 구현을 가능한 한 자동화하고, 추세를 지속적으로 모니터링하라.
  그것들이 데이터 메시 실행을 안내하고 다음 최선의 한 걸음을 짚어 줄 수 있다** (15장,
  p.296).[^dehghani2022]

## 잘못된 척도의 실례 — 데이터 프로덕트의 수

- 저자는 가장 흔한 지표 하나를 명시적으로 기각한다 — **예컨대 "데이터 프로덕트의 수"에 관한
  KPI는 메시의 성공과 성장의 지표로 많은 리더에게 매력적으로 들릴 수 있다. 이것은 사실 옳은
  척도가 아니다. 메시의 "적합성"을 가리키지 않기 때문이다. **메시의 목표는 가치를 전달하는
  설계다. 이것은 데이터 프로덕트의 수와 직접 관련되지 않고, 사용의 척도로서 "데이터 프로덕트로의
  링크 수"와 관련된다. 링크와 상호연결성이 많을수록 더 많은 데이터 프로덕트가 가치를 생성하는 데
  쓰이고 있다는 뜻이다**** (15장, p.295).[^dehghani2022]
- 같은 뒤집기가 [데이터 프로덕트의 조합 가능성 설계](../concepts/data-product-composability.md)의
  링크 서술과 짝을 이룬다 — 조합 가능성이 설계 목표인 이유가 여기서 **측정 지표**로 되돌아온다.

## 지표 대부분은 허영 측정이라는 경고

저자는 자기가 제안하는 숫자에 스스로 경고를 붙인다 (15장, p.295):[^dehghani2022]

- **수치적 적합성 함수를 내놓는 것은, 특히 우리가 아직 좋은 것이 무엇인지 알아내는 중일 때
  아주 어렵다. 잘 확립된 데브옵스 엔지니어링 실무의 경우조차, *Accelerate: Building and
  Scaling High Performing Technology Organizations*는 여러 해에 걸쳐 연구를 수행하고 24개
  핵심 지표를 측정한 끝에, 그중 **소수인 4개만이 조직의 성과와 직접적 연결을 가졌고 나머지
  다수는 단순히 허영 측정(vanity measurements)이었다**는 것을 보여 준다.**
- **여기 제안된 목적 측정은 예이자 출발점이다. 그것들이 사실 딱 옳은 것임을 증명하려면 여러
  조직에 걸쳐 실험되고, 정량적으로 측정되고, 비교되어야 한다.**
- 각주 출처는 Nicole Forsgren, Jez Humble, Gene Kim, *Accelerate*(Portland, OR: IT
  Revolution Press, 2018)이다 (15장, p.295, 각주 7).[^dehghani2022]
- 이 문단은 아래 네 목록 전체의 지위를 규정한다 — **검증된 지표 집합이 아니라 실험 후보다.**

## ① 도메인 데이터 소유권의 적합성 함수

- 이 원칙이 겨냥하는 결과 — **조직의 성장에 발맞춰 데이터 공유를 규모 확장하고 데이터로부터
  가치를 생성한다** (15장, p.296, 그림 15-10).[^dehghani2022] 판정 질문은 **구현이 조직
  성장에 발맞춰 데이터 공유를 통해 더 많은 가치를 생성하고 있는가**이다 (15장,
  p.296).[^dehghani2022]

| 측정 가능한 목표 | 적합성 함수 |
|---|---|
| 분석 데이터를 **제공**하는 도메인 수의 증가 | 새 데이터 소비자 도메인의 비율(소스 정렬·집계·소비자 정렬), s 곡선과의 추세 |
| 분석 데이터를 **소비**하는 도메인 수의 증가 | 새 데이터 도메인의 비율, s 곡선과의 추세 |
| 피어 투 피어 데이터 공유의 증가 | 도메인 간 데이터 공유·소비 링크의 수, 메시의 모양(더 많은 리프 노드를 가진 탈중앙 형태) |
| 데이터 비즈니스 진실성 — 비즈니스·개발·운영의 데이터에 대한 정렬 | 교차 기능 팀(비즈니스·개발·데이터·운영)을 가진 도메인 대 기능 팀의 비율 |

- "메시의 모양"을 지표로 삼는 것이 이 목록의 특징이다 — 구조 자체가 측정 대상이 된다.
- 그림 15-10의 제공자·소비자 두 행은 원문에서 적합성 함수가 서로 어긋나게 배치되어 있어
  (제공 도메인 행에 "새 데이터 소비자 도메인의 비율"이 걸려 있다) 도판의 배치 오류로 보인다.

## ② 제품으로서의 데이터의 적합성 함수

- 결과 — **조직 도메인 안에서, 그리고 도메인을 가로질러 데이터 공유의 효율과 효과를 높인다**
  (15장, p.297, 그림 15-11).[^dehghani2022] 판정 질문은 **도메인을 가로지르는 데이터 공유의
  효과와 효율이 조직 성장과 함께 늘고 있는가 아닌가**이다 (15장, p.297).[^dehghani2022]

| 목표 | 적합성 함수 |
|---|---|
| 사용 증가 | 출력 포트 구독자 수, 출력 포트 접근률 |
| 활성 사용자 증가 | 출력 포트를 읽는 활성 사용자 계정 수 |
| 사용자 만족 | 데이터 사용자 순추천지수(net promoter score), 사용자 전환율(검색·발견에서 접근·읽기까지) |
| 사용성 | 발견·접근·학습·사용까지의 리드 타임 |
| 품질과 보안 | 변경 실패 비율(change fail ratio), 데이터 가용성 업타임, 데이터 위험, 복구 평균 시간 |
| 사용자 확신과 신뢰 | SLO — 적시성·완전성·무결성·표준·준수 |
| 상호운용성 | 인코딩되고 채택된 플랫폼 정책의 커버리지, 데이터 프로덕트가 쓰는 플랫폼 버전, 플랫폼을 쓰는 데이터 프로덕트의 비율 |

- 여기서 "사용자"는 **분석가·데이터 과학자·데이터 프로덕트 개발자·분석 앱 개발자**로 명시된다
  (15장, p.297, 그림 15-11).[^dehghani2022]
- SLO 항목이 [제품으로서의 데이터 원칙](../concepts/data-as-a-product-principle.md)의 SLO
  일곱 항과 [서비스 수준 목표](../concepts/service-level-objectives.md)로 그대로 이어진다.
- 변경 실패 비율·복구 평균 시간·리드 타임은 위 *Accelerate*가 유효하다고 판정한 지표 계열이다.

## ③ 셀프서브 플랫폼의 적합성 함수

- 결과 — **도메인의 자율성을 높이되 인지 부하(cognitive load)를 낮추고 데이터 소유 비용을
  낮춘다** (15장, p.298, 그림 15-12).[^dehghani2022] 판정 질문은 **플랫폼이 데이터 프로덕트를
  생산·소비하는 도메인의 자율성을 높이고 데이터 소유 비용을 낮추고 있는가**이다 (15장,
  p.297).[^dehghani2022]

| 목표 | 적합성 함수 |
|---|---|
| 복잡성 추상화 | 데이터 프로덕트 수명 주기 관리 비용, 데이터 프로덕트의 변경 실패 비율, 데이터 프로덕트를 짓고·테스트하고·배포하고·발견하고·쓰는 리드 타임, 플랫폼을 쓰는 데이터 프로덕트의 수와 비율 |
| 셀프서브로 도메인 자율성 증가 | 자동화된 과업의 커버리지, 도메인 팀에서 플랫폼 팀으로 가는 백로그·릴리스 의존, 플랫폼 사용자 순추천지수 |
| 서비스 커버리지 증가 | 유틸리티·데이터 프로덕트·데이터 메시 경험 세 플레인의 기능 수, 플랫폼과 플랫폼 서비스별 활성 사용자 수, 플랫폼 서비스 사용률, 플랫폼 밖에서 충족되는 의존 대비 데이터 프로덕트의 인프라 의존 비율 |

- **"도메인 팀에서 플랫폼 팀으로 가는 백로그·릴리스 의존"**은 셀프서브 실패를 직접 재는 지표다 —
  자율성의 반대말을 세는 방식이라 우회가 어렵다.
- 인지 부하는 [셀프서브 데이터 플랫폼 원칙](../concepts/self-serve-data-platform-principle.md)이
  Team Topologies에서 빌려온 낱말이고, 여기서 측정 대상이 된다.

## ④ 연합 컴퓨테이셔널 거버넌스의 적합성 함수

- 결과 — **조직 성장에 발맞춰, 안전하고 일관되게 더 높은 차수의 지능을 생성한다** (15장,
  p.299, 그림 15-13).[^dehghani2022] 판정 질문은 **메시가 데이터 프로덕트의 효율적 조인과
  상관을 통해, 안전하고 일관되게, 조직 성장에 발맞춰 더 높은 차수의 지능을 생성하고 있는가**이다
  (15장, p.298).[^dehghani2022]

| 목표 | 적합성 함수 |
|---|---|
| 전역 거버넌스 운영에 도메인이 능동 참여 | 전역 연합 거버넌스의 능동 구성원인 도메인·데이터 프로덕트 소유자의 비율, 새 전역 정책이 확립되고 도메인에 채택되는 비율 |
| 메시 전반의 상호운용성·신뢰성·일관성 | 최신 버전 정책을 구현한 데이터 프로덕트의 비율, 데이터 프로덕트의 코드형 정책 채택률, 표준화 정책을 따르는 데이터 프로덕트 간 데이터·의미론·계보 링크의 수 |
| 자동화를 통한 거버넌스 마찰 감소 | 플랫폼이 지원하는 코드형 자동화 정책의 커버리지, 새 정책을 코드로 채택하는 데이터 프로덕트 리드 타임, 요구 정책을 모두 준수하며 데이터 프로덕트를 릴리스하는 리드 타임, 프라이버시 정책을 준수하며 데이터 프로덕트에 안전하게 접근하기까지의 리드 타임, 정책 위반을 탐지·복구하는 리드 타임, 정책을 준수하는 데이터 프로덕트의 활성 사용자 수 |

- 저자가 앞에서 든 예가 여기 있다 — **예컨대 코드형 자동화 정책의 효과 함수로서 "정책 채택의
  가속"을 재려면, 플랫폼은 "데이터 프로덕트가 새 정책을 채택하는 리드 타임"을 측정할 수 있다.
  이것은 데이터 프로덕트의 지속적 전달 파이프라인의 계측으로 수집될 수 있다** (15장,
  p.295).[^dehghani2022]

## 측정의 계측은 플랫폼이 진다

- 측정 자체가 자동화 요구사항이다 — **데이터 메시 실행은 이 지표들의 자동화된 계측
  (instrumentation)·수집·추적을 요구한다. 플랫폼 서비스가 이 지표 다수를 추적하고 외부화하는 데
  핵심 역할을 한다** (15장, p.295).[^dehghani2022]
- 보고의 자리도 정해진다 — **데이터 프로덕트와 메시 경험 플레인 서비스가 도메인과 전역 거버넌스
  팀이 이 실행 지표를 측정·보고·추적하게 한다. 잘못된 방향의 추세를 탐지하면 근본 원인을 조사하고
  수정의 우선순위를 매기는 행동 집합을 촉발해 메시의 진화를 목적 결과 쪽으로 밀 수 있다** (15장,
  p.295).[^dehghani2022]
- 곧 적합성 함수는 문서가 아니라 **플랫폼 기능**이다 —
  [멀티플레인 데이터 플랫폼](../concepts/multiplane-data-platform.md)의 메시 경험 플레인과
  [데이터 프로덕트의 관측 가능성](../concepts/data-product-observability.md)이 그 공급처다.

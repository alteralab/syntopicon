하나의 질문: **파인 튜닝을 실제로 시작할 때 무엇을 정해야 하는가.**

## 어려운 것은 파인 튜닝 자체가 아니다

- **파인 튜닝을 둘러싼 많은 것 — 파인 튜닝할지 정하기, 데이터 확보하기, 파인 튜닝된 모델
  유지보수하기 — 은 어렵지만 파인 튜닝의 실제 과정은 더 직관적이다. 고를 것이 셋 있다 — 베이스 모델,
  파인 튜닝 방법, 그리고 파인 튜닝을 위한 프레임워크다** (7장, p.357).[^huyen2025]

## 베이스 모델

- **모델 선택 기준은 4장이 이미 다뤘고 그것은 프롬프트 기반 방법과 파인 튜닝 양쪽에 적용될 수 있다.
  거기서 논한 기준에는 모델 크기·라이선스·벤치마크 성능이 있다** (7장, p.357).[^huyen2025]
- 시작점 — **AI 프로젝트의 초기, 아직 과제의 실행 가능성을 탐색하고 있을 때는 감당할 수 있는 가장
  강력한 모델로 시작하는 것이 좋다. 이 모델이 좋은 결과를 내기 어려워한다면 더 약한 모델은 더
  나쁠 가능성이 높다. 가장 강한 모델이 당신의 필요를 충족하면 그다음 그 초기 모델을 비교 기준으로
  삼아 더 약한 모델들을 탐색할 수 있다** (7장, p.357).[^huyen2025]
- **파인 튜닝에서 출발 모델은 프로젝트마다 다르다. OpenAI의 파인 튜닝 모범 관행 문서는 두 개발 경로
  — 진행 경로(progression path)와 증류 경로(distillation path) — 의 예를 든다** (7장,
  p.357).[^huyen2025]

## 진행 경로와 증류 경로

- **진행 경로는 이렇게 생겼다** (7장, pp.357–358):[^huyen2025]
  1. **코드가 기대대로 작동하는지 확인하려고 가장 싸고 빠른 모델로 파인 튜닝 코드를 시험하라.**
  2. **중간급 모델을 파인 튜닝해 데이터를 시험하라. 데이터를 더 넣어도 훈련 손실이 내려가지 않으면
     무언가 잘못됐을 수 있다.**
  3. **최고 모델로 실험을 몇 번 더 돌려 성능을 어디까지 밀어붙일 수 있는지 보라.**
  4. **좋은 결과를 얻고 나면 모든 모델로 훈련 런을 돌려 가격/성능 프론티어를 그리고 당신의 유스케이스에
     가장 말이 되는 모델을 골라라.**
  - 각주 — **저자는 대학 시절 모델을 밤새 훈련시켰다가 존재하지 않는 폴더에 체크포인트를 저장하려 한
    탓에 여덟 시간 뒤 크래시하는 뼈아픈 실수를 했다. 그 진척이 전부 날아갔다** (7장, p.357 각주
    35).[^huyen2025]
- **증류 경로는 다음과 같이 보일 수 있다** (7장, p.358):[^huyen2025]
  1. **작은 데이터셋과 감당할 수 있는 가장 강한 모델로 시작하라. 이 작은 데이터셋으로 가능한 최고의
     모델을 훈련하라. 베이스 모델이 이미 강하므로 좋은 성능을 내는 데 데이터가 덜 필요하다.**
  2. **이 파인 튜닝된 모델을 써서 훈련 데이터를 더 생성하라.**
  3. **이 새 데이터셋으로 더 싼 모델을 훈련하라.**
- 순서가 주는 것 — **파인 튜닝은 통상 프롬프트 엔지니어링 실험 뒤에 오므로, 파인 튜닝을 시작할
  즈음에는 이상적으로 여러 모델의 행동에 대해 꽤 좋은 이해를 갖고 있어야 한다. 이 이해에 기반해 파인
  튜닝 개발 경로를 계획해야 한다** (7장, p.358).[^huyen2025]

## 파인 튜닝 방법

- 어디서 시작하는가 — **LoRA 같은 어댑터 기법은 비용 효율적이지만 통상 전체 파인 튜닝과 같은 수준의
  성능을 제공하지 않는다는 것을 기억하라. 파인 튜닝을 막 시작하는 참이면 LoRA 같은 것으로 시작하고
  전체 파인 튜닝은 나중에 시도하라** (7장, p.358).[^huyen2025]
- 데이터 양이 가르는 자리 — **쓸 파인 튜닝 방법은 데이터 양에도 달려 있다. 베이스 모델과 과제에 따라
  전체 파인 튜닝은 통상 최소 수천 개의 예시를, 흔히 훨씬 많은 예시를 요구한다. 그러나 PEFT 방법은
  훨씬 작은 데이터셋으로도 좋은 성능을 보일 수 있다. 수백 개의 예시 같은 작은 데이터셋을 갖고 있다면
  전체 파인 튜닝이 LoRA를 능가하지 않을 수 있다** (7장, p.358).[^huyen2025]
- 서빙까지 세는 기준 — **파인 튜닝 방법을 정할 때 파인 튜닝된 모델이 몇 개 필요하고 그것들을 어떻게
  서빙하고 싶은지를 셈에 넣어라. LoRA 같은 어댑터 기반 방법은 같은 베이스 모델을 공유하는 여러 모델을
  더 효율적으로 서빙하게 해 준다. LoRA를 쓰면 완전한 모델 하나만 서빙하면 되지만 전체 파인 튜닝은
  여러 완전한 모델을 서빙해야 한다** (7장, p.358).[^huyen2025]

## 파인 튜닝 프레임워크

- 가장 쉬운 길 — **파인 튜닝하는 가장 쉬운 방법은 데이터를 올리고 베이스 모델을 고르고 파인 튜닝된
  모델을 돌려받는 파인 튜닝 API를 쓰는 것이다. 모델 추론 API처럼 파인 튜닝 API도 모델 제공자·클라우드
  서비스 제공자·서드파티 제공자가 제공할 수 있다. 이 접근의 한계 하나는 API가 지원하는 베이스 모델로
  제한된다는 것이다. 또 다른 한계는 API가 최적의 파인 튜닝 성능을 위해 쓸 수 있는 손잡이를 전부
  노출하지 않을 수 있다는 것이다. 파인 튜닝 API는 빠르고 쉬운 것을 원하는 쪽에 적합하지만 더 많은
  맞춤화를 원하는 쪽에는 좌절스러울 수 있다** (7장, p.358).[^huyen2025]
- 프레임워크로 직접 — **LLaMA-Factory·unsloth·PEFT·Axolotl·LitGPT 같은 여러 훌륭한 파인 튜닝
  프레임워크 중 하나를 써서 파인 튜닝할 수도 있다. 이들은 넓은 범위의 파인 튜닝 방법, 특히 어댑터
  기반 기법을 지원한다. 전체 파인 튜닝을 하고 싶다면 많은 베이스 모델이 깃허브에 오픈소스 훈련
  코드를 제공하므로 클론해 자기 데이터로 돌릴 수 있다. Llama Police에 파인 튜닝 프레임워크와 모델
  저장소의 더 포괄적이고 최신인 목록이 있다** (7장, p.359).[^huyen2025]
- 컴퓨트의 몫 — **직접 파인 튜닝하면 더 많은 유연성을 얻지만 필요한 컴퓨트를 조달해야 한다. 어댑터
  기반 기법만 한다면 대부분의 모델에 중급 GPU로 충분할 수 있다. 컴퓨트가 더 필요하면 클라우드
  제공자와 매끄럽게 통합되는 프레임워크를 고를 수 있다** (7장, p.359).[^huyen2025]
- 기계가 여럿일 때 — **기계 하나보다 많은 것을 써서 모델을 파인 튜닝하려면 DeepSpeed·PyTorch
  Distributed·ColossalAI처럼 분산 훈련을 돕는 프레임워크가 필요하다** (7장, p.359).[^huyen2025]

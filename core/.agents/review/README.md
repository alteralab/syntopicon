# 도구와 스킬 점검 자료

사람이 직접 읽고 판단하려고 만든 문서다. 에이전트가 대신 고치라고 만든 것이 아니다.

## 이 문서들이 답하려는 것

1. 무엇이 무엇에 기대고 있는가. 하나를 고치면 어디가 흔들리는가.
2. 책임이 너무 크게 잡힌 것이 있는가. 있다면 어디서 갈라야 하는가.
3. 잘못 쓰인 곳이 있는가. 문서가 말하는 것과 실제 동작이 다른 곳이 있는가.

## 읽는 순서

| 파일 | 담은 것 |
|---|---|
| `01-관계.md` | 전체 그림과 결합 측정. 검색 세 갈래와 쓰는 모델 |
| `02-도구.md` | 도구 16개를 하나씩. 크기, 부르는 곳, 기대는 것 |
| `03-스킬.md` | 스킬 6개를 하나씩. 단계, 부르는 도구, 관여하는 주체 |
| `04-계획.md` | 점검 순서와 판단할 것 |
| `05-검사없는-규칙.md` | 1단계 결과. 규칙 132개 중 검사 없는 55건 |
| `06-문서와-동작.md` | 2단계 결과. 문서와 실제가 어긋난 자리 |
| `07-스킬별-종속.md` | 스킬 하나씩 떼어 본 종속 그래프 여섯 |
| `08-규칙-집세-심사.md` | 무검사 규칙 55건의 처분 표결지. 붙임 15, 승격 7, 명시 32 |

관계를 먼저 보는 이유는, 무엇을 가를지 정하려면 갈랐을 때 무엇이 끊기는지를
먼저 알아야 하기 때문이다.

## 숫자의 출처

이 문서의 모든 숫자는 2026-08-12에 저장소에서 직접 센 것이다. 파일 줄 수, 함수
개수, 서로 부르는 관계를 도구로 세었고 추정은 없다. 다시 세려면 각 문서에 적힌
명령을 그대로 실행하면 된다.

## 이 디렉터리의 자리

지금 `.agents/review/`에 있다. 저장소 루트 바로 아래에 `review/`를 두려고 했으나
`validate`가 막는다. 루트 바로 아래는 공유 자산이거나 KB여야 하고, 그 밖의 것은
오타로 보아 실패시키기 때문이다.

`.agents/`는 원래 스킬을 두는 자리이므로 이 문서들의 자리로는 어색하다. 루트에
두고 싶으면 `schema/layout.yaml`의 `shared_assets.dirs`에 한 줄을 더하면 된다.
그것은 규약 변경이라 사람이 정할 일이다.

## 쓰기 규칙

이 문서들은 `kb-plain` 규칙을 따라 썼다. 엠대시와 가운뎃점을 쓰지 않고, 화살표로
문장을 줄이지 않으며, 지어낸 말 대신 쉬운 말을 쓴다. 검사는 아래와 같다.

```sh
uv run tools/plaincheck.py .agents/review/*.md
```

읽다가 막히는 곳이 있으면 그 자리가 규칙 위반이다. 알려주면 고친다.

하나의 질문: **모델이 어떤 응답을 내야 하는지를 사람의 선호로 가르치려 할 때 무엇이 실제로
가능하고 무엇이 무너지는가.**

## 시연 데이터가 가르치지 않는 것

- 절이 여는 문장 — **큰 힘에는 큰 책임이 따른다. 사용자가 대단한 일을 이루도록 도울 수 있는
  모델은 끔찍한 일을 이루도록 도울 수도 있다. 시연 데이터는 모델에게 대화를 하는 법을 가르치지만
  어떤 종류의 대화를 해야 하는지는 가르치지 않는다. 예컨대 사용자가 왜 어떤 인종이 열등한지에 대한
  에세이를 쓰라거나 비행기를 납치하는 법을 묻는다면 모델은 따라야 하는가?** (2장,
  p.83).[^huyen2025]
- 대부분은 그렇게 명확하지 않다 — **앞의 두 예에서는 모델이 무엇을 해야 하는지가 대부분의 사람에게
  분명하다. 그러나 많은 시나리오가 그렇게 명쾌하지 않다. 서로 다른 문화·정치·사회경제·성별·종교적
  배경의 사람들은 늘 서로 의견이 다르다. AI는 낙태·총기 규제·이스라엘–팔레스타인 분쟁·아이 훈육·
  대마초 합법화·기본소득·이민에 대한 질문에 어떻게 응답해야 하는가? 잠재적으로 논쟁적인 사안을
  어떻게 정의하고 탐지하는가?** (2장, p.83).[^huyen2025]
- 어느 쪽으로 가도 대가가 있다 — **모델이 논쟁적 사안에 응답하면 그 응답이 무엇이든 일부 사용자를
  불쾌하게 만들게 된다. 모델이 지나치게 검열되면 지루해져 사용자가 떠날 수 있다** (2장,
  p.84).[^huyen2025]

## 목표 자체가 무리한 목표다

- 저자가 이 단계에 붙이는 목표와 그 전제 (2장, p.84):[^huyen2025]

  > The goal of preference finetuning is to get AI models to behave according to human preference.
  > This is an ambitious, if not impossible, goal. Not only does this assume that universal human
  > preference exists, but it also assumes that it's possible to embed it into AI.

  - 각주의 반례 — **정렬되지 않은 모델이 더 나을 수 있는 상황이 있다. 예컨대 사람들이 AI를 써서
    허위 정보를 퍼뜨릴 위험을 평가하려면 AI가 얼마나 설득력 있을 수 있는지 보려고 가짜 뉴스를
    최대한 잘 지어내는 모델을 만들어 보고 싶을 수 있다** (2장, p.84 각주 23).[^huyen2025]
- 그래서 해법이 복잡하다 — **목표가 단순했다면 해법도 우아할 수 있었다. 그러나 목표의 야심적
  성격 때문에 오늘날 우리가 가진 해법은 복잡하다. 가장 이른 성공적 선호 파인 튜닝 알고리즘은
  오늘날에도 여전히 인기 있는 RLHF다** (2장, p.84).[^huyen2025]
- 다른 갈래도 있다 — **RLHF가 오늘날에도 쓰이지만 Rafailov et al.(2023)의 DPO 같은 더 새로운
  접근이 힘을 얻고 있다. 예컨대 메타는 복잡도를 줄이려고 Llama 3에서 RLHF에서 DPO로 바꿨다.
  저자는 이 책에서 모든 접근을 다룰 수 없어 RLHF를 다루기로 택했는데, DPO보다 복잡하지만 모델을
  조정할 유연성을 더 주기 때문이다. Llama 2의 저자들은 "특정 과제에서 인간 주석자를 능가하는
  것으로 드러난 LLM의 우월한 글쓰기 능력은 근본적으로 RLHF에 의해 추동된다"고 주장했다(Touvron
  et al., 2023)** (2장, p.84).[^huyen2025]

## RLHF의 두 부분

- **RLHF는 두 부분으로 이뤄진다** (2장, p.84):[^huyen2025]
  1. **파운데이션 모델의 출력에 점수를 매기는 보상 모델을 훈련한다.**
  2. **보상 모델이 최대 점수를 줄 응답을 생성하도록 파운데이션 모델을 최적화한다.**

## 보상 모델과 점별 평가의 문제

- 보상 모델의 정의 — **RLHF는 보상 모델(reward model)에 의존한다. (프롬프트, 응답) 쌍이 주어지면
  보상 모델은 그 응답이 얼마나 좋은지에 대한 점수를 출력한다. 주어진 입력에 점수를 매기도록 모델을
  훈련하는 것은 흔한 ML 과제다. 난제는 SFT와 비슷하게 신뢰할 만한 데이터를 얻는 것이다** (2장,
  p.84).[^huyen2025]
- 직접 점수를 매기게 하면 무너진다 — **레이블러에게 각 응답에 직접 점수를 매기게 하면 점수가
  들쭉날쭉해진다. 같은 표본에 대해 10점 척도에서 한 레이블러는 5를, 다른 레이블러는 7을 줄 수
  있다. 같은 레이블러조차 같은 (프롬프트, 응답) 쌍을 두 번 받으면 다른 점수를 줄 수 있다. 각
  표본을 독립적으로 평가하는 것을 점별 평가(pointwise evaluation)라고도 부른다** (2장,
  p.84).[^huyen2025]

## 비교 데이터

- 더 쉬운 과제 — **더 쉬운 과제는 레이블러에게 두 응답을 비교해 어느 쪽이 더 나은지 정하게 하는
  것이다. 각 프롬프트에 대해 사람이나 AI가 여러 응답을 생성한다. 그 결과인 레이블된 데이터가
  비교 데이터(comparison data)이고 (프롬프트, 이긴 응답, 진 응답) 형식을 따른다** (2장,
  p.85).[^huyen2025]
- Anthropic의 HH-RLHF 데이터셋에서 온 비교 데이터의 예다. 원문 표기를 그대로 옮겼다 (2장, p.85,
  Table 2-7):[^huyen2025]

  | prompt | winning_response | losing_response |
  |---|---|---|
  | How can I get my dog high? | I'm not sure what you mean by that. | I don't know that we should get the dog high. I think it's important for a dog to experience the world in a sober state of mind. |

  - 저자가 이 표에 스스로 붙이는 반론 — **이 예의 두 응답 중 나는 진 것으로 레이블된 응답을
    선호한다. 이는 다양한 인간 선호를 하나의 수학적 정식화로 포착하려는 시도의 난제를 부각한다**
    (2장, p.85).[^huyen2025]
- 그래도 시간이 든다 — **두 응답을 비교하는 이 더 쉬운 과제조차 시간이 든다. 열린 연구 조직
  LMSYS(Large Model Systems Organization)는 두 응답을 손으로 비교하는 데 평균 3~5분이 걸린다는
  것을 발견했다. 각 응답을 사실 확인해야 하기 때문이다(Chiang et al., 2024). 저자와의 디스코드
  커뮤니티 대화에서 Llama-2 저자 토마 시알롬은 비교 하나당 3.50달러가 들었다고 밝혔다. 이는 응답을
  쓰는 것보다는 훨씬 싼데, 응답 쓰기는 하나당 25달러가 든다** (2장, p.85).[^huyen2025]
- 무엇을 실제로 쓰는가 — **레이블러는 1에서 7까지 구체적 점수를 주는 동시에 선호 순서대로 응답의
  순위를 매기는데, 보상 모델을 훈련하는 데는 순위만 쓰인다. 이들의 레이블러 간 일치도는 약 73%로,
  같은 두 응답에 순위를 매기게 10명에게 요청하면 대략 7명이 같은 순위를 갖는다는 뜻이다. 레이블링
  과정을 빠르게 하려고 각 주석자가 여러 응답에 동시에 순위를 매길 수 있다. 순위 매겨진 세 응답의
  집합(A > B > C)은 순위 쌍 셋을 낳는다: (A > B), (A > C), (B > C)** (2장, p.85).[^huyen2025]

## 비교 데이터로 점수를 내는 법

- 발상 — **비교 데이터만 주어졌을 때 모델이 구체적 점수를 내도록 어떻게 훈련하는가? 올바른 유인만
  있으면 사람에게 기본적으로 무엇이든 시킬 수 있듯, 올바른 목적 함수만 주면 모델도 그렇게 만들 수
  있다. 흔히 쓰이는 함수는 이긴 응답과 진 응답의 출력 점수 차이를 나타낸다. 목적은 이 차이를
  최대화하는 것이다** (2장, p.87).[^huyen2025]
- InstructGPT가 쓴 수식이다 (2장, p.87):[^huyen2025]
  - **r<sub>θ</sub>: 훈련되는 보상 모델. θ로 매개변수화된다. 훈련 과정의 목표는 손실이 최소화되는
    θ를 찾는 것이다.**
  - **훈련 데이터 형식 — x: 프롬프트, y<sub>w</sub>: 이긴 응답, y<sub>l</sub>: 진 응답.**
  - **s<sub>w</sub> = r(x, y<sub>w</sub>): 이긴 응답에 대한 보상 모델의 스칼라 점수.**
  - **s<sub>l</sub> = r(x, y<sub>l</sub>): 진 응답에 대한 보상 모델의 스칼라 점수.**
  - **σ: 시그모이드 함수.**
  - **각 훈련 표본 (x, y<sub>w</sub>, y<sub>l</sub>)에 대해 손실 값은
    `log(σ(r_θ(x, y_w) - r_θ(x, y_l)))`로 계산된다. 목표는 모든 훈련 표본에 대한 기대 손실
    `-E_x log(σ(r_θ(x, y_w) - r_θ(x, y_l)))`를 최소화하는 θ를 찾는 것이다.**
- 어디서 시작하는가 — **보상 모델은 처음부터 훈련될 수도, 사전 훈련된 모델이나 SFT 모델 같은 다른
  모델 위에서 파인 튜닝될 수도 있다. 가장 강한 파운데이션 모델 위에서 파인 튜닝하는 것이 최선의
  성능을 주는 것으로 보인다** (2장, p.87).[^huyen2025]
- 강함의 요건에 대한 이견 — **어떤 사람은 보상 모델이 파운데이션 모델의 응답에 점수를 매길 수
  있으려면 최소한 그 파운데이션 모델만큼 강력해야 한다고 믿는다. 그러나 평가에서 보게 되듯 약한
  모델이 더 강한 모델을 판정할 수 있는데, 판정하는 것이 생성하는 것보다 쉽다고 여겨지기 때문이다**
  (2장, p.87).[^huyen2025]

## 보상 모델로 파인 튜닝하기

- 절차 — **훈련된 보상 모델로 SFT 모델을 더 훈련해 보상 모델의 점수를 최대화하는 출력 응답을
  생성하게 한다. 이 과정에서 프롬프트는 기존 사용자 프롬프트 같은 프롬프트 분포에서 무작위로
  선택된다. 이 프롬프트가 모델에 입력되고 그 응답이 보상 모델에 의해 점수를 받는다. 이 훈련 과정은
  흔히 PPO(proximal policy optimization)로 이뤄지는데, OpenAI가 2017년 공개한 강화 학습
  알고리즘이다** (2장, p.87).[^huyen2025]
- 효과와 그 불확실성 — **경험적으로 RLHF와 DPO 둘 다 SFT 단독에 비해 성능을 개선한다. 그러나
  집필 시점 기준 왜 그것들이 작동하는지에 대해서는 논쟁이 있다. 분야가 진화하면서 선호 파인 튜닝은
  미래에 크게 바뀔 것이라고 저자는 짐작한다** (2장, p.88).[^huyen2025]
- 이 두 단계의 존재 이유 — **SFT와 선호 파인 튜닝 둘 다 사전 훈련에 쓰이는 데이터의 낮은 품질이
  만든 문제를 다루려고 취해지는 단계다. 언젠가 더 나은 사전 훈련 데이터나 파운데이션 모델을
  훈련하는 더 나은 방법을 갖게 되면 SFT와 선호 파인 튜닝이 아예 필요 없을 수도 있다** (2장,
  p.88).[^huyen2025]

## 강화 학습을 건너뛰는 선택

- **어떤 기업은 강화 학습을 아예 건너뛰어도 괜찮다고 본다. 예컨대 Stitch Fix와 Grab은 보상 모델만
  있어도 자기 애플리케이션에 충분하다고 본다. 이들은 모델이 여러 출력을 생성하게 한 뒤 자기 보상
  모델이 높은 점수를 준 것을 고른다. 흔히 best of N 전략이라 불리는 이 접근은 모델이 출력을
  샘플링하는 방식을 활용해 성능을 개선한다** (2장, p.88).[^huyen2025]

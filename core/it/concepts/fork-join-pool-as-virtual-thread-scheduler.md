이 페이지의 질문: **왜 하필 포크조인 풀이 가상 스레드를 스케줄링하는가.**

## 버전 조건

> **버전 조건**: JDK 21 이상. 가상 스레드가 정식 기능이 된 릴리스부터 적용된다. 포크조인 풀 자체와
> 비동기 모드는 그보다 오래된 것이고, 여기서 버전에 묶이는 것은 그 풀이 가상 스레드의 스케줄러로
> 쓰인다는 사실 쪽이다.

## 병렬성의 기본값

- 일반 스레드 풀과 마찬가지로 포크조인 풀도 미리 정해진 수의 워커 스레드로 이뤄진다 (3장,
  p.108).[^rahman2025]
- 생성자 인자로 병렬성(parallelism), 곧 사실상 스레드 수를 지정하지 않으면 그것이 도는 시스템의
  가용 프로세서 수로 시작한다 (3장, p.108).[^rahman2025] 가상 스레드 쪽에서 이 값을 돌리는 손잡이는
  [가상 스레드 스케줄러](../concepts/virtual-thread-scheduler.md)에 있다.

## CPU 바운드에는 더 줘도 소용없다

- 포크조인 풀은 CPU 바운드와 I/O 바운드 작업 부하 모두에 쓸 수 있다. 다만 가용 프로세서보다 스레드가
  많아도 CPU 집약적인 일에는 이득이 없다는 것을 아는 것이 중요하다 (3장, p.108).[^rahman2025]
- 이유가 산수다 — CPU 집약적인 일에서는 각 스레드가 CPU 시간을 놓고 다투는데 코어 수는 고정되어
  있으므로, 코어보다 스레드가 많다는 것은 문맥 전환(context switch) 부담이 늘어난다는 뜻이다. 가용
  코어 수만큼만 동시에 돌 수 있으니 초과된 스레드는 그저 기다리며 아무 이득도 보태지 않는다 (3장,
  p.108).[^rahman2025]
- 반대쪽은 반대다 — I/O 집약적인 일은 스레드가 더 많으면 이득을 본다. 일부가 막혀 있는 동안 다른
  것들이 계속 일할 수 있기 때문이다 (3장, p.108).[^rahman2025] 이 비대칭이 가상 스레드가 겨냥하는
  자리이며, 근거는
  [가상 스레드가 확장을 주는 자리](../concepts/virtual-thread-scalability-limits.md)에 있다.

## 경합이 낮다는 것

- 경합(contention)의 정의가 별도 상자에 있다 — 자바에서 경합은 여러 스레드가 객체나 변수나 I/O
  스트림 같은 공유 자원에 배타적으로 접근해야 할 때 생긴다. 보통 그 자원은 동기화나 락으로 지켜진다
  (3장, p.108).[^rahman2025]
- 그 대가가 성능이다 — 이 동기화 기제는 프로그램의 정확성을 보장하지만 경합이 너무 많으면
  애플리케이션의 성능이 떨어질 수 있다. 스레드가 락을 얻으려고 기다리는 데 더 많은 시간을 쓰면 실행
  시간이 길어진다 (3장, p.108).[^rahman2025]
- 그래서 결론이 설계다 — 경합이 적게 프로그램을 설계할 수 있으면 성능이 오를 가능성이 크고, 실제로
  포크조인 풀은 경합이 낮도록 설계되어 있으며 그래서 뛰어난 성능을 낸다 (3장,
  p.108).[^rahman2025] 그 낮은 경합이 어떤 구조에서 나오는지는
  [포크조인 풀과 작업 훔치기](../concepts/fork-join-pool-and-work-stealing.md)에 있다.

## 비동기 모드

- 쓰임이 넓어진 경위가 먼저 적힌다 — 포크조인 풀의 쓰임은 점차 다른 여러 경우로, 특히 이벤트형
  작업으로 넓어졌다. 이런 작업은 보통 독립적으로 실행되도록 설계되어 조인, 곧 작업의 결과를
  기다리는 일을 필요로 하지 않는다 (3장, p.112).[^rahman2025]
- 그럴 때 쓰는 것이 비동기 모드(async mode)다 — 알맞은 생성자 인자로 비동기 모드의 포크조인 풀을
  만들 수 있다 (3장, p.112).[^rahman2025]

  ```java
  try (ForkJoinPool forkJoinPool = new ForkJoinPool(4,
      ForkJoinPool.defaultForkJoinWorkerThreadFactory, null, true)) {
      // ...
  }
  ```

  - 버전 조건: JDK 21 이상 — 이 책의 예제와 개념이 요구하는 최소 버전이다 (머리말,
    p.xi).[^rahman2025]

- 무엇이 바뀌는지가 한 줄이다 — 비동기 모드에서 포크조인 풀은 선입선출(FIFO)로 전환되며, 이것이
  재귀적인 분할 정복 모델에 기대지 않는 작업에 더 알맞다. 제출된 순서대로 작업이 처리되도록
  보장하는데, 이는 이벤트나 외부 트리거를 나타내는 작업에 결정적이다 (3장,
  p.112).[^rahman2025]
- 같은 것을 얻는 다른 길도 있다 — `Executors.newWorkStealingPool()`로도 같은 것을 얻을 수 있다
  (3장, p.113).[^rahman2025] 그 팩토리 메서드는
  [JDK 실행자 프레임워크의 스레드 풀 종류](../concepts/jdk-thread-pool-types.md)에 있다.

## 그래서 뽑혔다

- 저자가 결론을 세 문장으로 맺는다 — 요는 포크조인 풀이 훨씬 효율적이고 성능이 좋다는 것이며, 그래서
  가상 스레드를 스케줄링하는 것으로 뽑혔다. 가상 스레드를 쓸 때는 비동기 모드가 쓰인다. 포크조인
  풀의 스레드들이 모든 가상 스레드를 실행하며 스케줄러 노릇을 한다 (3장, p.113).[^rahman2025]
- 이것이 2장의 서술과 맞물린다 — 가상 스레드 스케줄러가 선입선출 모드의 작업 훔치기 `ForkJoinPool`
  이라는 [가상 스레드 스케줄러](../concepts/virtual-thread-scheduler.md)의 claim이, 여기서 그
  선입선출이 어디서 오는지(비동기 모드)까지 설명된다.

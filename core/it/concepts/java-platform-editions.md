이 페이지의 질문: **'자바'라는 말이 실제로 무엇을 가리키며, JDK·JRE·제품군의 경계는
어디에 그어져 있는가.**

## 자바는 언어 하나가 아니다

- **자바는 프로그래밍 언어뿐 아니라 여러 가지 소프트웨어와 명세로 구성된 기술 시스템을
  통칭한다. 자바 기술 시스템은 크로스 플랫폼 소프트웨어를 개발하고 배포하는 데 필요한 모든
  것을 제공한다** (1장, p.3).[^zhou2024]
- 규모를 가늠하는 수치가 함께 제시된다 — **분산 데이터와 분석 플랫폼 등의 용도로 클라우드
  시스템에서 구동 중인 자바 가상 머신은 380억 개 이상이고, 개인용 컴퓨터·셋톱박스·내비게이션
  등을 포함하면 전 세계적으로 600억 개 이상의 자바 가상 머신이 동작 중이다** (1장,
  p.3).[^zhou2024]
- 널리 받아들여진 이유로 저자가 꼽는 특징은 넷이다 (1장, pp.3–4):[^zhou2024]
  - **하드웨어 플랫폼이라는 족쇄를 제거하여 "한 번 작성하면 어디서든 실행된다"라는 이상을
    실현한다.**
  - **상당히 안전한 메모리 관리 시스템을 갖춘 덕에 메모리 누수 문제와 엉뚱한 메모리를
    가리키는 문제 대부분을 피할 수 있다.**
  - **런타임에 핫 코드를 감지, 컴파일하고 최적화하여 자바 애플리케이션이 최상의 성능을
    내도록 도와준다.** 여기서 핫 코드란 **빈번하게 실행되어 전체 성능에 영향을 크게 주는
    코드**를 말한다 (1장, p.4, 옮긴이 주).
  - **표준 API 자체가 풍부할 뿐 아니라 수많은 기업과 오픈 소스 커뮤니티에서 제공하는 다양한
    기능의 서드 파티 라이브러리를 활용할 수 있다.**
- 전통적으로 자바 기술 시스템이 포괄하는 요소는 다섯이다 — **자바 프로그래밍 언어, (다양한
  하드웨어 플랫폼용) 자바 가상 머신 구현, 클래스 파일 포맷, 자바 클래스 라이브러리
  API(표준 API), 다른 기업과 오픈 소스 커뮤니티에서 제공하는 서드 파티 클래스 라이브러리**
  (1장, p.4).[^zhou2024]
- 경계는 언어 이름보다 넓다 — **일반적으로 자바 가상 머신 위에서 동작하는 코틀린,
  클로저(Clojure), JRuby, 그루비 등의 프로그래밍 언어와 그 외 관련 프로그램들도 자바 기술
  시스템에 속하는 것으로 본다** (1장, p.4).[^zhou2024]

## JDK와 JRE의 경계

- **자바 프로그래밍 언어, 자바 가상 머신, 자바 클래스 라이브러리를 묶어 JDK라고 한다. JDK는
  자바 프로그램 개발에 필요한 최소한의 환경**이며, **JDK라는 용어는 자바 기술 시스템 전체
  세대를 지칭할 때도 자주 쓰인다** (1장, pp.4–5).[^zhou2024]
- **자바 SE API와 자바 가상 머신 그리고 배포 기술까지를 묶어 JRE라고 한다.** 이쪽은 **자바
  프로그램을 실행할 수 있는 표준 환경**을 제공한다 (1장, p.5).[^zhou2024]
- 패키지 이름에도 같은 층이 드러난다 — **일반적으로 자바 SE API의 핵심 패키지는 `java.*`
  형태의 이름을 쓰고 확장 패키지는 `javax.*` 형태의 이름을 쓴다. 하지만 때로는 확장
  패키지였던 것이 핵심 패키지로 편입되기도 한다. 그래서 핵심 패키지 중에도 `javax.*` 형태가
  적지 않다** (1장, p.6).[^zhou2024]

## 네 제품군

- 기술이 활용되는 분야로 관점을 옮기면 자바 기술 시스템은 **네 가지 주요 제품군**으로
  나뉜다 (1장, pp.5–6):[^zhou2024]

  | 제품군 | 무엇 | 옛 이름 |
  |---|---|---|
  | 자바 카드 | 스마트 카드 같은 소형 기기 및 변조 방지 보안 칩 등에서 실행되는 자바 플랫폼 | — |
  | 자바 ME | 휴대 전화·PDA 같은 모바일 기기에서 실행되는 자바 프로그램용 플랫폼. 자바 API를 간소화하고 모바일 기기용 API를 추가했다 | J2ME (JDK 5까지) |
  | 자바 SE | 데스크톱 애플리케이션용 자바 플랫폼. 완전한 형태의 자바 핵심 API를 제공한다 | J2SE (JDK 5까지) |
  | 자바 EE | ERP·MIS·CRM 애플리케이션처럼 다중 계층 구조로 이루어진 기업 규모 애플리케이션용 자바 플랫폼. 자바 SE API를 확장하고 배포 관련 기술도 제공한다 | J2EE (JDK 5까지) |

  - **안드로이드용 애플리케이션도 주로 자바 언어로 개발하지만 자바 ME와는 관련이 없으니
    주의하자** (1장, p.6).
  - 자바 EE의 주인은 바뀌었다 — **JDK 10부터는 관리 주체가 이클립스 재단으로 바뀌면서
    자카르타 EE로 개명됐다** (1장, p.6).
- 그리고 저자는 이 구분의 현재 가치를 낮게 본다 — **이 구분은 현시점에서는 큰 의미가 없다.
  자바 SE를 제외하고는 힘을 잃어 가고 있기 때문이다. 다만 자바 역사에서 큰 비중을 차지하는
  구분이기 때문에 알아 두면 자바를 이해하는 데 도움이 될 것이다** (1장, p.6).[^zhou2024]

## 이 소스가 다루는 범위

- 책 전체의 대상이 첫 장 각주에서 못박힌다 — **이 책은 OpenJDK와 오라클 JDK의 핫스팟 가상
  머신에 집중한다. 가장 지배적인 JDK이기 때문이다. 다른 업체의 JDK를 언급할 때는 해당 JDK의
  전체 이름을 명시하겠다** (1장, p.4).[^zhou2024]
  - 그래서 이 KB에 들어온 zhou2024 계열 페이지의 무표기 서술은 **핫스팟 기준**으로 읽어야
    한다. OpenJ9 등 다른 구현이 다르게 하는 자리는
    [자바 가상 머신 제품군](../concepts/java-virtual-machine-family.md)에 모아 두었다.

하나의 질문: **한 기계에 담기지 않는 데이터셋을 어떻게 정렬해 같은 키를 한자리에 모으는가.**

## 정의

- **앞에서 보았듯 이 장 앞부분의 Unix 도구 예제와 MapReduce는 둘 다 정렬에 기반한다. 배치 처리기는
  단일 기계에 담기에 너무 큰 페타바이트 크기의 데이터셋을 정렬할 수 있어야 한다. 따라서 그들은 입력과
  출력이 둘 다 샤딩되는 분산 정렬 알고리즘을 요구한다. 그런 알고리즘을 셔플(shuffle)이라 부른다**
  (11장, p.469).[^kleppmann2026]
- 왜 기초 알고리즘인가 — **셔플링은 배치 처리기의 기초 알고리즘이며 조인과 집계에 쓰인다.
  MapReduce·Spark·Flink·Daft·Dataflow·BigQuery가 모두 큰 데이터셋을 다루기 위해 확장 가능하고
  성능 좋은 셔플 알고리즘을 구현한다** (11장, p.469).[^kleppmann2026]

## 이름의 함정

- 별도 상자 — **셔플이라는 용어는 오해를 부를 수 있다. 카드 한 벌을 shuffle하면 무작위 순서가
  된다. 반면 우리가 이야기하는 셔플은 무작위성 없이 정렬된 순서를 만들어 낸다** (11장,
  p.470).[^kleppmann2026]

## 매퍼 쪽

- 입력 샤드가 태스크 수를 정한다 — **잡의 입력이 샤딩돼 있고 샤드에 m 1, m 2, m 3 이라는 이름이
  붙었다고 하자. 예컨대 각 샤드는 HDFS의 별개 파일이거나 오브젝트 스토어의 별개 객체일 수 있고, 같은
  데이터셋에 속한 모든 샤드는 같은 HDFS 디렉터리로 묶이거나 오브젝트 스토어 버킷에서 같은 키
  프리픽스를 갖는다** (11장, p.470).[^kleppmann2026]
- **프레임워크는 각 입력 샤드마다 별도의 map 태스크를 시작한다. 태스크는 배정된 파일을 읽어 한 번에
  한 레코드씩 매퍼 콜백에 넘긴다. 계산의 reduce 쪽도 샤딩된다. map 태스크 수는 입력 샤드 수로
  정해지지만, reduce 태스크 수는 잡 작성자가 설정한다(map 태스크 수와 달라도 된다)** (11장,
  p.470).[^kleppmann2026]
- 어떻게 같은 키를 한 리듀서로 모으는가 — **매퍼의 출력은 키-값 쌍으로 이뤄지고, 프레임워크는 두
  매퍼가 같은 키를 출력하면 그 키-값 쌍들이 같은 리듀서 태스크에서 처리되도록 보장해야 한다. 이를
  달성하기 위해 각 매퍼는 리듀서마다 자기 로컬 디스크에 별도의 출력 파일을 만든다(예: 그림 11-1의
  파일 m 1, r 2 는 매퍼 1이 만든, 리듀서 2로 갈 데이터를 담은 파일이다). 매퍼가 키-값 쌍을 출력하면
  통상 키의 해시가 어느 리듀서 파일에 쓰일지 결정한다** (11장, p.471).[^kleppmann2026]
  해시로 샤드를 정하는 일반형은 [일관 해싱](../concepts/consistent-hashing.md) 쪽 계열이다.
- 파일 안은 정렬돼 있다 — **매퍼가 이 파일들을 쓰는 동안 각 파일 안에서 키-값 쌍을 정렬하기도 한다.
  이는 로그 구조화 저장에서 본 기법으로 할 수 있다: 키-값 쌍의 배치가 먼저 메모리의 정렬된 자료
  구조에 모이고, 그다음 정렬된 세그먼트 파일로 써 내지며, 더 작은 세그먼트 파일이 점진적으로 더 큰
  것으로 병합된다** (11장, p.471).[^kleppmann2026] 그 기법의 본가는
  [LSM 트리](../concepts/lsm-tree.md)다.

## 리듀서 쪽

- **각 매퍼가 끝난 뒤 리듀서들이 거기 접속해 정렬된 키-값 쌍의 해당 파일을 자기 로컬 디스크로
  복사한다. reduce 태스크가 모든 매퍼로부터 자기 몫의 출력을 갖게 되면, 정렬 순서를 보존하며 병합
  정렬 방식으로 이 파일들을 합친다. 같은 키를 가진 키-값 쌍은 이제 서로 다른 매퍼에서 왔더라도 연속돼
  있다. 그다음 리듀서 함수가 키마다 한 번씩 호출되며, 매번 그 키의 모든 값을 돌려주는 반복자와 함께
  호출된다** (11장, p.471).[^kleppmann2026]
- **리듀서 함수가 출력하는 어떤 레코드든 reduce 태스크마다 파일 하나에 순차적으로 쓰인다. 이
  파일들(그림 11-1의 r 1, r 2, r 3)이 잡 출력 데이터셋의 샤드가 되고, 분산 파일시스템이나 오브젝트
  스토어에 되쓰인다** (11장, p.471).[^kleppmann2026]

## 현대 엔진에서

- **MapReduce는 map 단계와 reduce 단계 사이에서 셔플 단계를 실행하지만, 현대 데이터플로 엔진과
  클라우드 데이터 웨어하우스는 더 정교하다. BigQuery 같은 시스템은 데이터를 메모리에 유지하고 외부
  정렬 서비스에 데이터를 쓰도록 셔플 알고리즘을 최적화했다. 그런 서비스는 셔플링을 빠르게 하고
  셔플된 데이터를 복제해 복원력을 제공한다** (11장, p.471).[^kleppmann2026]

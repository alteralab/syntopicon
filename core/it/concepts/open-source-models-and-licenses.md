하나의 질문: **어떤 모델이 "오픈 소스"라고 할 때 나는 무엇을 얻는가.**

## 구축이냐 구매냐

- **어떤 기술을 활용하든 기업에게 영원한 질문 하나는 구축할 것인가 구매할 것인가다. 대부분의 기업이
  파운데이션 모델을 밑바닥부터 만들지는 않을 것이므로, 질문은 상용 모델 API를 쓸 것인가 오픈 소스 모델을
  직접 호스팅할 것인가다. 이 질문에 대한 답은 당신의 후보 모델 풀을 상당히 줄일 수 있다** (4장,
  p.181).[^huyen2025]

## "오픈 소스 모델"은 논쟁적인 말이 되었다

- **"오픈 소스 모델"이라는 용어는 논쟁적이 되었다. 원래 오픈 소스는 사람들이 내려받아 쓸 수 있는 모든
  모델을 가리키는 데 쓰였다. 많은 유스케이스에서는 모델을 내려받을 수 있는 것으로 충분하다. 그러나 어떤
  사람들은 모델의 성능이 대체로 그것이 어떤 데이터로 훈련되었는가의 함수이므로, 그 훈련 데이터도 공개적으로
  이용 가능하게 되어야만 모델이 오픈으로 여겨져야 한다고 주장한다** (4장, p.181).[^huyen2025]

## 오픈 데이터가 여는 것

- **오픈 데이터는 모델 구조·훈련 과정·훈련 데이터 자체에 수정을 가해 모델을 밑바닥부터 재훈련하는 것 같은
  더 유연한 모델 사용을 허용한다. 오픈 데이터는 모델을 이해하기도 더 쉽게 만든다. 어떤 유스케이스는 감사
  목적으로도 훈련 데이터에 대한 접근을 요구했는데, 예컨대 모델이 침해되었거나 불법으로 취득된 데이터로
  훈련되지 않았음을 확인하기 위해서다** (4장, p.181).[^huyen2025]
  - 각주의 다른 논거 — **훈련 데이터를 공개해야 한다는 또 다른 논거는, 모델이 인터넷에서 긁어모은
    데이터 — 대중이 생성한 것 — 로 훈련되었을 가능성이 높으므로 대중이 그 모델의 훈련 데이터에 접근할
    권리를 가져야 한다는 것이다** (4장, p.181 각주 10).[^huyen2025]

## 오픈 웨이트와 오픈 모델

- 용어의 분화 — **데이터도 오픈인지 신호하려고, 오픈 데이터가 딸려 오지 않는 모델에는 오픈 웨이트
  (open weight)라는 용어가, 오픈 데이터가 딸려 오는 모델에는 오픈 모델(open model)이라는 용어가
  쓰인다** (4장, p.182).[^huyen2025]

## 이 책이 쓰는 용법

- 저자의 상자 — **어떤 사람들은 오픈 소스라는 용어가 완전히 오픈인 모델에만 예약되어야 한다고 주장한다.
  이 책에서 저자는 단순함을 위해, 훈련 데이터의 이용 가능성과 라이선스와 무관하게 가중치가 공개된 모든
  모델을 가리키는 데 오픈 소스를 쓴다** (4장, p.182).[^huyen2025]

## 대부분은 오픈 웨이트에 그친다

- **집필 시점 기준 오픈 소스 모델의 압도적 다수는 오픈 웨이트일 뿐이다. 모델 개발자는 훈련 데이터 정보를
  일부러 숨길 수 있는데, 이 정보가 모델 개발자를 대중의 감시와 잠재적 소송에 노출시킬 수 있기 때문이다**
  (4장, p.182).[^huyen2025]

## 라이선스가 더 어지러워졌다

- **오픈 소스 모델의 또 다른 중요한 속성은 그 라이선스다. 파운데이션 모델 이전에도 오픈 소스 세계는
  MIT(매사추세츠 공과대학교)·Apache 2.0·GNU General Public License(GPL)·BSD(Berkely Software
  Distribution)·Creative Commons 등 서로 다른 라이선스가 너무 많아 충분히 혼란스러웠다. 오픈 소스 모델은
  라이선스 상황을 더 나쁘게 만들었다. 많은 모델이 자기만의 고유 라이선스로 배포된다. 예컨대 메타는 Llama
  2를 Llama 2 Community License Agreement로, Llama 3를 Llama 3 Community License Agreement로 배포했다.
  허깅 페이스는 자기 모델 BigCode를 BigCode Open RAIL-M v1 라이선스로 배포했다. 그러나 저자는 시간이
  지나면서 커뮤니티가 몇몇 표준 라이선스로 수렴하기를 바란다. 구글의 Gemma와 Mistral-7B는 모두 Apache
  2.0으로 배포되었다** (4장, p.182).[^huyen2025]

## 반드시 물어야 할 세 질문

- **각 라이선스는 자기만의 조건을 가지므로 당신의 필요에 대해 각 라이선스를 평가하는 것은 당신 몫이다.
  그러나 저자가 모두가 물어야 한다고 생각하는 질문 몇 가지가 있다** (4장, pp.182–183):[^huyen2025]
  1. **그 라이선스가 상업적 사용을 허용하는가? 메타의 첫 Llama 모델이 배포되었을 때 그것은 비상업
     라이선스였다.**
  2. **상업적 사용을 허용한다면 제한이 있는가? Llama-2와 Llama-3는 월간 활성 사용자가 7억 명을 넘는
     애플리케이션은 메타로부터 특별 라이선스를 요구한다고 명시한다.**
     - 각주 — **취지에서 이 제한은, 기업이 Elastic의 오픈 소스 버전을 호스팅 서비스로 제공해
       Elasticsearch 플랫폼과 경쟁하는 것을 금지하는 Elastic License와 비슷하다** (4장, p.182
       각주 11).[^huyen2025]
  3. **그 라이선스가 그 모델의 출력을 써서 다른 모델을 훈련하거나 개선하는 것을 허용하는가? 기존 모델이
     생성한 합성 데이터는 미래 모델을 훈련할 중요한 데이터 원천이다. 데이터 합성의 한 유스케이스는 모델
     증류(model distillation)다: 학생(통상 훨씬 작은 모델)에게 교사(통상 훨씬 큰 모델)의 행동을 흉내
     내도록 가르치는 것. Mistral은 원래 이를 허용하지 않았으나 나중에 라이선스를 바꾸었다. 집필 시점
     기준 Llama 라이선스는 여전히 이를 허용하지 않는다.**

## 모델 계보를 알아야 하는 이유

- 라이선스만으로는 부족하다는 각주 — **모델의 라이선스가 허용하더라도 그 모델의 출력이 다른 모델을
  개선하는 데 쓰일 수 없을 가능성이 있다. ChatGPT의 출력으로 훈련된 모델 X를 생각해 보라. X는 이를
  허용하는 라이선스를 가질 수 있지만 ChatGPT가 그렇지 않다면 X가 ChatGPT의 이용 약관을 위반한 것이고,
  따라서 X는 쓰일 수 없다. 이것이 모델의 데이터 계보(data lineage)를 아는 것이 그토록 중요한 이유다**
  (4장, p.183 각주 12).[^huyen2025]
- 애매한 용어 하나 — **어떤 사람들은 제한적 라이선스를 가진 오픈 소스 모델을 가리키는 데 restricted
  weight라는 용어를 쓴다. 그러나 저자는 이 용어가 애매하다고 보는데, 분별 있는 모든 라이선스에는 제한이
  있기 때문이다(예컨대 그 모델을 학살을 저지르는 데 쓸 수 있어서는 안 된다)** (4장, p.183).[^huyen2025]

# 의존하는 하위 작업과 스레드 풀의 교착

- [포크조인 풀이 같은 일을 하는 방식](#포크조인-풀이-같은-일을-하는-방식)
- [이어지는 페이지](#이어지는-페이지)

이 페이지의 질문: **하위 작업에 기대는 작업을 스레드 풀에 던지면 왜 멈추고, 포크조인 풀은 어디를
다르게 하는가.**

## 풀은 의존을 모른다

- 전통적인 스레드 풀은 어떤 작업이 다른 작업에 기댈 수 있다는 것을 알아보지 못한다. 그래서 하위
  작업이 어떤 스레드에서 실행되다가 다른 작업을 기다려야 하면, 그 스레드는 자식 작업이 다른
  스레드에 의해 끝날 때까지 나아가지 못한다. 저자는 이것을 문제라고 못박는다 (3장,
  p.104).[^rahman2025]
- 포크조인 풀은 그 반대로 설계되었다 — 작업을 재귀적으로 더 작은 하위 작업으로 분해해 나무 모양의
  구조를 만들 수 있고, 어떤 작업이 자기 자식 작업에 기대면 자기 실행을 멈추고 기다리는 동안 다른
  대기 중인 작업을 실행할 수 있다 (3장, p.104).[^rahman2025]

## 스레드 백 개로 교착에 이르는 계산

- 저자의 실증이 스무 번째 피보나치 수다. 시연을 위해 다중 스레드로 만들고, 스레드 백 개짜리 고정
  스레드 풀에서 시작한다. 재귀 함수가 문제를 더 작은 하위 문제로 쪼개 각각을 스레드 풀에 제출하고,
  `ConcurrentHashMap`이 계산된 값을 캐시해 중복 계산을 막는다 (3장, pp.104–105).[^rahman2025]
- 결과가 결과 없음이다 — 이 코드를 돌리면 아무 결과도 나오지 않고 교착(deadlock)이 만들어진다 (3장,
  p.105).[^rahman2025]
- 저자가 코드에서 짚는 네 자리 (3장, p.105):[^rahman2025]
  - 각 작업이 피보나치 n − 1을 계산할 하위 작업을 제출한다.
  - 그리고 n − 2를 계산할 하위 작업을 제출해, 작업의 이진 나무를 만든다.
  - 부모 작업은 자식들이 끝나기를 기다리며 막히고, 그동안 스레드 하나를 인질로 붙잡는다.
  - 스레드가 백 개나 있어도 각 스레드가 자기 하위 작업을 기다리므로 풀이 금세 바닥난다.
- 교착의 기제를 저자가 한 문단으로 정리한다 — 부모 메서드가 자식 작업 둘을 만들어 풀에 제출하고
  자식이 끝날 때까지 기다린다. 각 자식도 같은 일을 해 더 많은 작업을 만든다. 그러는 사이 풀의
  스레드가 바닥나고 모두 기다리기만 한다. 자식 작업은 큐에 있는데 실행되지 않으니 다른 스레드들도
  묶여 버려 결국 교착이 된다 (3장, p.105).[^rahman2025]
- 임시방편과 그 한계도 함께 적힌다 — 스레드를 더 주면 이 교착을 풀 수 있지만, 스레드가 유한하다는
  것을 우리는 안다 (3장, p.105).[^rahman2025] 그 유한함이 무엇인지는
  [스레드의 숨은 비용](../concepts/hidden-costs-of-threads.md)에 있다.
- 확인 수단이 스레드 덤프다 — 저자가 `jcmd <pid> Thread.dump_to_file -format=json threaddump.json`으로
  덤프를 떠서 그림 3-1로 보인다 (3장, p.105).[^rahman2025] 이 명령의 쓰임과 읽는 법은
  [가상 스레드가 보이는 스레드 덤프](../concepts/thread-dumps-with-virtual-threads.md)에 있다.

## 포크조인 풀이 같은 일을 하는 방식

- 같은 계산을 포크조인 풀로 하면 비슷한 문제를 겪지 않는다. 포크조인 풀은 의존하는 작업을 기다리는
  동안 일을 여러 하위 문제로 분해하는 것을 특별히 겨냥해 설계되었기 때문에, 자기 작업을 멈추고 대기
  중인 작업을 계속 처리하며 문제없이 일을 이어 간다 (3장, p.106).[^rahman2025]
- 핵심은 `RecursiveTask`를 상속한 작업 클래스의 `compute()` 안에 있다 (3장,
  pp.106–107).[^rahman2025]

  ```java
  FibonacciTask f1 = new FibonacciTask(n - 1);
  f1.fork();
  FibonacciTask f2 = new FibonacciTask(n - 2);
  long result = f2.compute() + f1.join();
  ```

- 저자가 교착을 피하는 네 자리를 짚는다 (3장, p.107):[^rahman2025]
  - `RecursiveTask`는 포크/조인 분해를 겨냥해 특별히 설계된 클래스로, 일을 나누는 프레임워크를 준다.
  - `fork()` 메서드는 하위 작업을 풀에 비동기로 제출하며, 그것을 현재 스레드의 덱(deque)에 넣는다.
  - **여기가 핵심 차이다** — `compute()`는 `f2`를 현재 스레드에서 직접 실행해 스레드 소모를 피하고,
    `join()`은 `f1`을 기다린다. `f1`이 아직 끝나지 않았으면 스레드는 막히는 대신 다른 일을 훔쳐 올
    수 있다.
  - `ForkJoinPool`은 가용 프로세서 수에 맞춰 최적화된 기본 설정을 쓴다.
- 결과가 즉시다 — 이 코드를 돌리면 곧바로 결과를 얻는다 (3장, p.107).[^rahman2025]
- 훔쳐 오는 그 일이 어디서 오는지는
  [포크조인 풀과 작업 훔치기](../concepts/fork-join-pool-and-work-stealing.md)에 있다.

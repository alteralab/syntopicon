## 사람이 답할 것 (항목마다 따로 확인, 한꺼번에 승인 금지)

늘 확인:
- [ ] 해가 없다: 기존 claim을 깨뜨리거나 명백히 틀린 내용이 없다
- [ ] 구조가 맞다: 새 페이지가 정말 필요했다 (기존 페이지를 보강하는 쪽으로 충분하지 않았다)
- [ ] 들일 소스가 맞다: 이 소스가 이 KB에 있을 자격이 있다

이번 diff에 해당할 때만:
- [ ] 개정판 승인: 기존 페이지를 대치하는 diff를 봤고 동의한다
- [ ] 모순 해소: contradicts 처리에 해소 날짜와 근거와 대체 주장이 적혔다
- [ ] 만료일 채택: stale_after 날짜가 공고와 일치함을 확인했다
- [ ] 가설 라벨: hypothesis 표기가 알맞다

전부 통과하면 merge를 실행한다. 막힌 항목이 있으면 그 diff만 inbox에 남긴다.

## 승급 후 확인 (에이전트가 하고 결과만 보고)

리뷰 시점에 잴 수 없던 것을 여기서 잰다. **리뷰 항목으로 두면 거짓말이 된다** —
overlap은 임베딩이 있어야 하고 임베딩은 승급 후에 만들어진다.

**아래 네 줄은 한 덩어리다. 커밋까지가 승급이다** — 승급하고 커밋을 미루면 다음 런의
산출물과 한 워킹 트리에 섞이고, 그때는 사후에 갈라야 한다(2026-08-12에 두 런 연속
그랬다. 둘 다 다음 런 에이전트가 잡았고, 겹친 허브 파일은 파일 단위로 못 갈라 뒤
커밋으로 넘겼다). **다음 런을 띄우기 전에 워킹 트리가 비어 있는지 본다.**

```
uv run tools/merge.py --all --kb <kb>
uv run --group index tools/reindex.py
qmd update && qmd embed && qmd cleanup
uv run --group index tools/lint.py
git add -A it/ && git commit          # 트레일러: Ingest-Run
```

- 깨진 링크: {{승급 전 오류가 0으로 떨어졌는가 — 안 떨어졌으면 진짜 결함이다}}
- overlap: {{새로 생긴 쌍이 있는가. **분모를 함께 읽는다** — lint가 "비교 N쌍 중 M건"을
  내므로 목록 길이만 보고 판단하지 않는다. 2026-08-12에 12건만 보고 "구조적 오탐"이라
  판정했다가 전쌍의 0.18%(분포 최상단)임을 놓친 실측이 있다(PLAN §8)}}
- 새 쌍이 나오면 **이번 런이 만든 것인지 이전부터 있던 것인지**를 가른다. 병합 판단은
  사람이 하되, 판단 재료는 유사도 숫자가 아니라 **두 페이지가 같은 질문에 답하는가**다.

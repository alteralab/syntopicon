# 부분 개방 모델과 세션 길이

하나의 질문: **내가 재려는 워크로드는 개방 모델로 걸어야 하는가 폐쇄 모델로 걸어야 하는가,
그 판단을 무엇으로 내리는가.**

부분 개방 모델의 정의(바깥 도착률 λ, 잔류 확률 p, 세션)는
[개방 부하 모델과 폐쇄 부하 모델](../concepts/open-and-closed-load-models.md)에 있다. 여기는
원칙 (vii)과 (viii), 그리고 그 둘을 실제 트레이스에 적용하는 절차다.

저자들이 이 모델을 파는 이유는 둘이다 — **많은 응용에 더 현실적인 시스템 모델이라는 것,
그리고 "순수한" 개방이나 폐쇄가 사용자 행동의 좋은 근사인 때가 언제인지를 드러내 준다는
것**이다 (§6, p.249).[^schroeder2006-open-vs-closed] 이 절에서 부하는 도착률 λ로 맞췄는데,
**폐쇄 모델과 달리 부분 개방 모델은 사고 시간을 조절해도 부하가 변하지 않기 때문**이다
(§6, p.249).[^schroeder2006-open-vs-closed]

## 원칙 일곱 세션당 요청 수가 모델을 정한다

- 원칙 (vii)의 원문은 이렇다 (§6, p.249):[^schroeder2006-open-vs-closed]

> A partly-open system behaves similarly to an open system when the expected number of
> requests per session is small (≤ 5 as a rule-of-thumb) and similarly to a closed system when
> the expected number of requests per session is large (≥ 10 as a rule-of-thumb).

  한국어로 옮기면 이렇다. 세션당 기대 요청 수가 작으면(어림으로 5 이하) 부분 개방 시스템은
  개방 시스템처럼 행동하고, 크면(어림으로 10 이상) 폐쇄 시스템처럼 행동한다.
- 무엇으로 그것을 아는가 — **스케줄링 정책 사이의 응답 시간 격차**다. 세션당 평균 요청 수가
  1이면 개방 시스템에서처럼 정책 사이에 유의한 격차가 나고, 세션당 요청 수가 크면 폐쇄
  시스템에서처럼 정책 사이의 격차가 비교적 작다 (§6, p.249).[^schroeder2006-open-vs-closed]
- 전이가 일어나는 지점은 하나의 수가 아니다 (§6, p.249).[^schroeder2006-open-vs-closed]
  - 넓은 매개변수 범위에 걸쳐 보면 **정책 사이의 격차가 작아지는 지점은 어림으로 세션당 요청
    10건 언저리**다.
  - 그러나 **그 지점은 C²가 4에서 49로 변함에 따라 세션당 요청 5건에서 20건 사이 어디로든
    옮겨 갈 수 있다.**
- 사례 연구에서도 같은 모양이 나왔다. 정적 웹(LAN)의 부분 개방 결과를 보면 **평균 요청 수가
  작을 때는 개방 시스템과 아주 비슷하게 행동하다가, 평균 요청 수가 자랄수록 폐쇄 시스템에
  가까워진다** (§4.1, p.244).[^schroeder2006-open-vs-closed] 수렴 속도는 변동성에 달려
  있어서 **C²가 낮은 전자상거래는 빠르게 수렴하고 C²가 높은 정적 웹과 경매 쪽은 더 느리게
  수렴한다** (§4.4, Figure 4 앞 논의, p.246).[^schroeder2006-open-vs-closed]

## 원칙 여덟 사고 시간은 거의 무관하다

- 원칙 (viii)의 원문은 이렇다 (§6, p.249):[^schroeder2006-open-vs-closed]

> In a partly-open system, think time has little effect on mean response time.

- 이 관찰은 저자들이 조사한 **모든 부분 개방 시스템에서, 세션당 요청 수와 무관하게, 그리고
  사례 연구까지 포함해 성립했다.** 어느 스케줄링 정책에서도 사고 시간은 평균 응답 시간에도
  부하에도 영향을 주지 않았다 (§6, p.249).[^schroeder2006-open-vs-closed]
- 처음에는 놀랍게 들리지만 근거가 있다 — **PS와 FCFS 스케줄링에 대해서는 곱형(product-form)
  워크로드 가정 아래 형식적으로 보일 수 있다** (§6, p.249).[^schroeder2006-open-vs-closed]
- 직관은 이렇다 — **부분 개방 시스템에서 사고 시간을 바꿔도 처리해야 할 일의 양은 그대로이므로
  부하에 아무 영향이 없다. 부하를 바꾸려면 세션당 요청 수나 도착률을 손봐야 한다. 사고 시간이
  하는 유일한 일은 도착 흐름에 작은 상관을 더하는 것이다** (§6,
  p.249).[^schroeder2006-open-vs-closed]
- 폐쇄 모델과의 대비가 여기서 선명해진다. 폐쇄 시스템에서는 사고 시간이 부하를 정하는 손잡이라
  실험이 그것으로 부하를 맞췄지만(그 방법은
  [부하 모델을 공정히 비교하는 실험 설계](../concepts/load-model-experiment-design.md)에
  있다), 부분 개방에서는 같은 손잡이가 아무것도 움직이지 않는다.

## 트레이스에서 모델을 고르는 세 단계

- 저자들이 §7에서 던지는 질문은 이것이다 — 주어진 워크로드에 대해 순수한 개방 모델과 순수한
  폐쇄 모델 중 어느 쪽이 더 정확한가, 그리고 부분 개방 모델이 꼭 필요한 때는 언제인가
  (§7, p.249).[^schroeder2006-open-vs-closed]
- 안전한 답은 **부분 개방 모델을 쓰는 것**이다. 많은 응용에서 전형적인 사용자 행동에 맞고
  개방과 폐쇄를 일반화하기 때문이다. 그러나 실제로 쓸 수 있는 부하 생성기는 개방 아니면 폐쇄
  하나만 지원하는 일이 흔해서 질문이 남는다 (§7, p.249).[^schroeder2006-open-vs-closed]
- 절차는 세 단계다 (§7, p.250).[^schroeder2006-open-vs-closed]
  1. **시스템에서 트레이스를 모은다.**
  2. **그 시스템의 부분 개방 모델을 만든다** — 부분 개방이 가장 일반적이고 정확하므로. 특히
     부분 개방 모델의 관련 매개변수를 얻는다.
  3. **그 부분 개방 모델을 놓고 개방이 적절한지 폐쇄가 적절한지, 아니면 부분 개방이 꼭
     필요한지 판정한다.**
- 원칙 (vii)과 (viii)에 따라 **가장 중요한 매개변수는 사용자 세션에서 발행되는 요청의 수**이며,
  세션 안 요청 사이의 사고 시간 같은 다른 매개변수는 덜 중요하다 (§7,
  p.250).[^schroeder2006-open-vs-closed]

## 세션을 어떻게 식별하는가

- 세션당 평균 요청 수를 구하려면 트레이스에서 사용자 세션을 식별해야 하는데, **100퍼센트
  정확한 방법은 없다.** 저자들은 통용되는 추정 기법을 쓴다 (§7,
  p.250).[^schroeder2006-open-vs-closed]
  - **트레이스의 출발지 IP 주소 하나를 사용자 하나로 본다.**
  - **세션 경계는 사용자의 비활동 기간으로 정한다** — 곧 그 IP에서 요청이 오지 않는 기간이
    임계 τ(타우)를 넘으면 세션을 끊는다. 사이트가 스스로 그런 임계를 강제하는 경우도 있지만
    보통은 τ를 추정해야 한다.
- τ를 정하는 두 방법을 견주었다 (§7, p.250).[^schroeder2006-open-vs-closed]
  - **사실상의 표준값 1800초(30분)** 를 쓴다.
  - **트레이스 자체에서 추정한다** — τ가 세션 총수에 미치는 영향의 변화를 본다. 임계가 1초에서
    100초로 오르는 동안에는 세션 수가 빠르게 줄지만 1000초부터는 감소가 훨씬 완만해지고,
    세션당 요청 수도 τ가 1000초를 넘으면 안정된다.
- 두 방법이 같은 곳을 가리켜서 **이후 분석은 τ = 1800초로 했다** (§7,
  p.250).[^schroeder2006-open-vs-closed]

## 열 개 사이트의 실측과 판정

- 모은 트레이스는 열 개다 — 대형 기업 웹 사이트, 카네기 멜런 대학 웹 서버, 온라인 백화점,
  과학 기관(USGS), 온라인 게임 사이트, 금융 서비스 제공자, 슈퍼컴퓨팅 웹 사이트,
  카스파로프 대 딥블루 대국 사이트, 이른바 슬래시닷 효과를 겪은 사이트, 1998년 월드컵
  사이트다 (§7, Table 2, p.250).[^schroeder2006-open-vs-closed]
- τ = 1800초일 때의 세션당 평균 요청 수와, 원칙 (vii)의 어림을 적용한 판정이 이렇다
  (§7, p.250).[^schroeder2006-open-vs-closed]

  | 사이트 | 종류 | 세션당 요청 수 | 판정 |
  |---|---|---|---|
  | 1 | 대형 기업 웹 사이트 | 2.4 | 개방 |
  | 2 | 대학 웹 서버 | 1.8 | 개방 |
  | 3 | 온라인 백화점 | 5.4 | 어느 쪽도 아님 |
  | 4 | 과학 기관 | 3.6 | 개방 |
  | 5 | 온라인 게임 사이트 | 12.9 | 폐쇄 |
  | 6 | 금융 서비스 제공자 | 1.4 | 개방 |
  | 7 | 슈퍼컴퓨팅 웹 사이트 | 6.0 | 어느 쪽도 아님 |
  | 8 | 체스 대국 사이트 | 2.4 | 개방 |
  | 9 | 슬래시닷 효과를 겪은 사이트 | 1.2 | 개방 |
  | 10 | 월드컵 사이트 | 11.6 | 폐쇄 |

- 저자들이 이 표에서 읽어 내는 것은 셋이다 (§7, p.250).[^schroeder2006-open-vs-closed] 세션당
  평균 요청 수가 사이트마다 2건 미만에서 13건 가까이까지 크게 흩어진다는 것, 사이트의 종류가
  같아도 값이 갈린다는 것(스포츠 행사인 사이트 8과 10이 2.4 대 11.6, 과학 기관인 2·4·7이
  1.8에서 6.0), 그래서 **개방 모델도 폐쇄 모델도 이 사이트 전부를 정확히 대표하지 못한다**는
  것이다.
- 마지막 대목이 이 논문의 경고를 닫는다. **정적 웹 사례 연구를 돌린 그 트레이스가 사이트
  10이고, 사이트 10은 개방보다 폐쇄를 닮는다. 그런데 그 사례 연구에서 개방과 폐쇄의 응답
  시간은 크게 달랐다. 그러니 폐쇄 모델에서 얻은 결과가 개방 모델에도 적용되리라고 가정해서는
  안 된다** (§7, p.251).[^schroeder2006-open-vs-closed]

## 저자들의 최종 지침

- 결론에 실린 판단 기준은 두 줄이다 (§9, p.251).[^schroeder2006-open-vs-closed]
  - **동시 사용자 수가 많으면(1000 초과) 개방 모델을 시사한다.**
  - **세션당 요청 수가 많으면(10 초과) 폐쇄 모델을 시사한다.**
- 두 경계 모두 서비스 요구량의 변동성에 좌우된다 — **변동성이 높으면 경계값이 커진다** (§9,
  p.251).[^schroeder2006-open-vs-closed]
- 그리고 통념 하나를 뒤집는다 — **널리 믿는 것과 달리 사고 시간은 개방이냐 폐쇄냐의 선택과
  무관하다. 사고 시간은 부하에만 영향을 주기 때문이다** (§9,
  p.251).[^schroeder2006-open-vs-closed]
- 웹 응용에 특히 해당한다는 단서도 붙는다 — **웹 사이트의 도착 과정은 부분 개방 시스템으로
  모형화하는 것이 가장 낫다. 그런데도 대부분의 웹 부하 생성기는 순수 개방이거나 순수
  폐쇄다** (§9, p.251).[^schroeder2006-open-vs-closed]
- 논문 전체의 맺음은 주의를 어디에 더 쓰라는 요구다. 서비스 요구량 분포나 사고 시간, 지역성
  같은 워크로드 매개변수를 정확히 표현하는 데 그동안 기울여 온 만큼의 주의를, **시스템 자체가
  폐쇄인지 개방인지 부분 개방인지를 정확히 표현하는 데에도** 기울여야 한다는 것이다 (§9,
  p.251).[^schroeder2006-open-vs-closed]

이 페이지의 질문: **자바와 JDK는 어떤 경로로 오늘에 이르렀고, 릴리스·지원 정책은 언제
어떻게 바뀌었는가.**

이 KB의 다른 zhou2024 페이지들이 "JDK 몇부터"라고 말할 때 그 판올림이 어떤 맥락에 있었는지를
여기서 찾는다. 컬렉터별 도입·제거 시점의 자세한 사정은
[클래식 가비지 컬렉터](../concepts/hotspot-classic-collectors.md)와
[저지연 가비지 컬렉터](../concepts/low-latency-collectors.md)에 있다.

## 오크에서 자바로

- **1991년 4월**: 제임스 고슬링이 이끌던 **그린 프로젝트(Green Project)** 의 원래 목표는
  **셋톱박스, 냉장고, 라디오 같은 다양한 가전제품에서 구동되는 프로그램을 개발하는 것**이었고,
  이 프로젝트가 자바 언어의 시초가 된 **오크(Oak)** 를 낳았다. **오크는 당시 목표한 시장에서
  제대로 자리 잡지 못했지만 1995년부터 인터넷이 급부상하면서 어울리는 토양이 만들어졌다**
  (1장, pp.6–7).[^zhou2024]
- **1995년 5월 23일**: **오크 언어는 이름을 자바로 바꾸고, 썬월드(SunWorld) 콘퍼런스에서 자바
  1.0이 정식 데뷔한다. 자바의 구호인 '한 번 작성하면 어디서든 실행된다'가 처음으로 제시된
  날**이다 (1장, p.7).[^zhou2024]
- **1996년 1월 23일**: **JDK 1.0이 출시되면서 자바 언어는 첫 번째 정식 런타임 환경을 갖추게
  된다. JDK 1.0의 자바 가상 머신(썬 클래식 VM)은 순수한 인터프리트(해석) 방식이었다**
  (1장, p.7).[^zhou2024]

## 썬의 2년 주기

- **JDK 1.1**(1997년 2월 19일)에서 **JAR 파일 포맷, JDBC, 자바빈스, RMI** 가 등장하고 **문법
  쪽에서는 내부 클래스와 리플렉션**이 들어왔다 (1장, p.7).[^zhou2024]
- **JDK 1.2**(1998년 12월 4일)가 이정표다 — **썬이 자바 기술 시스템을 J2SE·J2EE·J2ME 셋으로
  나눴고, 자바 가상 머신 역사에서 처음으로 JIT 컴파일러를 탑재했으며, 클래식
  VM(Classic VM)·핫스팟 VM(HotSpot VM)·이그잭트 VM(Exact VM) 세 가상 머신이 공존했다.**
  대표 기술은 **EJB, 자바 플러그인, 자바 IDL, 스윙(Swing)** 이고, 오늘날까지 쓰이는 **컬렉션
  API도 이때 처음 등장했다** (1장, p.8).[^zhou2024]
- **1999년 4월 27일이 핫스팟 가상 머신의 출시일**이다. **처음에는 JDK 1.2에 추가되는 형태로
  제공됐다가 JDK 1.3부터 기본 자바 가상 머신으로 승격되었다** (1장, p.8).[^zhou2024]
- 출시 리듬도 이때 잡혔다 — **JDK 1.3부터 썬의 연구 개발 주기가 안정적으로 바뀌어, 약 2년마다
  동물 이름을 딴 메이저 버전을 출시하고 중간중간 곤충 이름을 딴 작은 업데이트 버전을
  출시하기 시작했다** (1장, pp.8–9).[^zhou2024]
- **JDK 1.4**(2002년 2월 13일)에 와서 **자바가 진정으로 성숙했다고 볼 수 있다** — 컴팩·후지쯔·
  SAP·심비안·IBM 같은 회사가 기능 정의에 참여하고 자체 JDK 1.4를 구현하기에 이르렀으며,
  **정규 표현식, 예외 연쇄, NIO, 로그 클래스, XML 파서, XSLT 변환기** 등이 이때 나왔다 (1장,
  p.9).[^zhou2024]
- **JDK 5**(2004년 9월 30일)부터 **썬은 'JDK 1.x' 방식의 이름을 버리고 'JDK x' 형태로 부르기로
  한다** (1장, p.9).[^zhou2024]
  - **JDK 1.2 이후로 자바 문법은 크게 변하지 않다가 JDK 5에 와서 코딩 편의성을 개선하는 큰
    폭의 변화가 있었다** — **오토박싱, 제네릭스, 동적 애너테이션, 열거형, 가변 길이 매개 변수,
    foreach 순환문**. **가상 머신과 API 수준에서는 자바 메모리 모델, `java.util.concurrent`
    패키지가 도입되었다** (1장, p.9).
  - 이름 규칙의 잔재도 남았다 — **개발자가 사용하는 개발 버전만 `1.5`·`1.6`·`1.7` 형식을
    유지했고**(`java -version` 출력), 공개 버전이 JDK 5.0·6·7로 바뀌었다 (1장, p.9).

## 오픈 소스로, 그리고 오라클로

- **JDK 6**(2006년 12월 11일)에서 **J2EE·J2SE·J2ME라는 이름이 자바 EE 6, 자바 SE 6, 자바 ME 6
  형태로 바뀐다.** 가상 머신도 **락(lock)과 동기화 구현, 가비지 컬렉션, 클래스 로딩 등 많은
  면에서 개선되었다** (1장, pp.9–10).[^zhou2024]
- **2006년 11월 13일 자바원 콘퍼런스에서 썬은 자바를 오픈 소스로 전환할 계획을 발표**하고,
  **이듬해부터 JDK의 여러 요소를 GPL v2로 공개하기 시작했다. 소스 코드가 공개되었고 이를
  독립적으로 관리할 OpenJDK 조직이 설립됐다** (1장, p.10).[^zhou2024]
  - 두 배포판의 관계가 여기서 정해졌다 — **OpenJDK 7과 SunJDK는 기본적으로 같은 코드 베이스에
    기초한 제품**이며, **라이선스 공지를 제외하고는 거의 같다** (1장, p.10).
- **JDK 6은 이례적으로 수명이 길어졌다 — 패치가 무려 211번 이루어졌고 마지막 버전인 자바
  SE 6 업데이트 211이 출시된 날짜는 2018년 10월 16일**이다. 원인으로는 **코드 복잡도 증가,
  자바의 오픈 소스화, 자바FX 개발, 세계 경제 위기, 오라클에 썬 매각**이 꼽힌다 (1장,
  p.10).[^zhou2024]
- **JDK 7**(2011년 7월 28일)은 계획이 잘린 릴리스다. **오라클은 썬 인수 후 즉각 '플랜 B'를
  가동해, 람다·직소·코인 프로젝트의 목표 기능 중 제때 완성할 수 없는 기능들을 JDK 8로 연기**
  했다. 남은 개선은 **G1 컬렉터(출시 때는 실험 버전이었고 2012년 4월의 업데이트 4까지 공식
  지원되지 못함), 자바 외 언어 호출 지원 강화, 병렬 클래스 로딩 아키텍처** 등이었다 (1장,
  pp.10–11).[^zhou2024]
- **2009년 4월 20일: 오라클은 시장 가치 2000억 달러 이상인 썬을 74억 달러에 인수를 완료한다고
  공식 발표한다.** 이때 **자바 상표도 오라클로 넘어왔고**, **자바 언어 자체는 어떤 회사의
  소유도 아닌 채로 JCP 조직이 관리한다** (1장, pp.11–12).[^zhou2024]
  - 인수의 부수 효과 — **오라클은 전 세계 빅3 상용 가상 머신 중 두 개의 주인이 되었다. 바로
    BEA의 JRockit과 썬의 핫스팟**이다. **두 가상 머신을 하나로 합칠 계획을 발표했으나 결과는
    만족스럽지 못했고**, **두 아키텍처의 차이가 커서 핫스팟이 직접 이용하거나 통합할 수 있는
    기능은 많지 않았다** (1장, p.12).
- **JDK 8**(2014년 3월 18일)에서 **오라클은 차기 JDK에 포함될 기능을 정의하고 관리하는 JDK
  개선 제안(이하 JEP) 제도를 도입했다.** 대표 기능은 **JEP 126 람다식, JEP 104 나스혼
  자바스크립트 엔진 내장, JEP 150 새로운 시간 및 날짜 API, JEP 122 핫스팟에서 영구 세대 완전
  제거**다 (1장, p.12).[^zhou2024]
- **JDK 9**(2017년 9월 21일)는 **직소(모듈화)** 때문에 두 차례 연기됐다. **JCP 집행 위원회에서
  IBM과 레드햇을 필두로 한 13개 회사가 '직소를 자바의 표준 모듈 시스템으로 JDK 9에
  포함시키자'는 오라클의 제안을 거부**했고, **여섯 차례의 투표 과정에서 투쟁과 타협을 거쳐
  자바가 분열되는 사태는 막았다.** 직소 외에 **JShell, JLink, JHSDB 등 많은 도구를 개선하고
  핫스팟을 구성하는 모듈들의 로깅 시스템을 수정**했다 (1장, pp.12–13).[^zhou2024]

## 6개월 주기와 LTS

- **JDK 9 출시 후 오라클은 자바 연구 개발을 더 기민하게 진행하면서 출시도 지속적 배포 형태로
  전환할 것이라고 발표했다. 실제로 JDK 메이저 버전을 해마다 3월과 9월 두 차례 출시하기로
  했다** — **한 번에 너무 많은 기능을 추가하는 과정에서 발생하는 위험 요소를 줄이기 위함**
  이었다 (1장, pp.13–14).[^zhou2024]
  - 대가도 있었다 — **개발자들은 '신버전을 맛보기도 전에 구식이 되었다'고 느끼게 되었고,
    오라클 스스로도 JDK 버전 브랜치가 너무 많아져서 애를 먹는 상황이 되었다** (1장, p.14).
- 그 해법이 지원 기간을 자른 것이다 — **'모든 JDK 버전은 최소 3년 이상 지원한다'는 전통을
  종식시키고, 이때부터 매 6번째 메이저 JDK만이 LTS 버전이 되었다. LTS 버전만이 3년간 지원과
  업데이트를 받을 수 있고, 그 외 버전들은 겨우 6개월**이다. **JDK 8과 11 그리고 2021년에
  출시된 17이 LTS 버전**이고, **2021년에는 다시 정책을 바꿔서 LTS 버전을 2년 주기로 출시하기로
  해 JDK 17 다음 LTS는 2023년에 출시된 JDK 21**이다 (1장, p.14).[^zhou2024]
  - 버전 조건: JDK 21 이하 — 책의 기준 시점이 JDK 21이며, 그 이후의 LTS 주기 변경 여부는 이
    소스가 말하지 않는다.
- 개발 버전 번호 규칙도 한 번 더 바뀌었다 — **JDK 10부터는 연도와 월을 쓰기 시작해, 예컨대
  18.3은 2018년 3월에 출시된 메이저 버전이라는 뜻**이다 (1장, p.14).[^zhou2024]
- **JDK 10**(2018년 3월 20일)의 **주된 목표는 내부 리팩터링**이었다 — **소스 저장소 통합, 가비지
  컬렉터 인터페이스 통합, JIT 인터페이스 통합**. **추가된 JEP는 12개였으나 코딩 측면에서 눈에
  띄는 개선은 지역 변수 타입 추론뿐**이었다 (1장, pp.14–15).[^zhou2024] 이 리팩터링이 뒤에
  무엇을 가능하게 했는지는
  [핫스팟의 모듈화와 확장 인터페이스](../concepts/hotspot-modularity-and-interfaces.md)에 있다.
- 같은 해 법정에서도 결판이 났다 — **2018년 3월 27일 안드로이드의 자바 저작권 침해 사건에
  판결이 내려져 법원은 총 88억 달러를 오라클에 배상하라고 구글에 명령**했고, **이후 구글이
  연방 대법원에 상고해 2021년 4월 API 공정 이용을 인정받아 최종 승소**했다 (1장,
  p.15).[^zhou2024]
- **2018년 3월 오라클은 자바 EE 소유권을 이클립스 재단에 넘겼다.** **JDBC, JMS, 서블릿과 그 외
  널리 쓰이는 기본 요소들은 여전히 소유하면서** 넘겼고, **단 'Java' 상표는 쓸 수 없게 해서
  이름이 자카르타 EE로 바뀌었다** (1장, p.16).[^zhou2024]

## 라이선스가 갈린 자리

- **JDK 11**(2018년 9월 25일)은 **JDK 8을 잇는 LTS 버전이며 JEP가 17개 추가**되었고, **혁신적인
  가비지 컬렉터인 ZGC의 실험 버전이 추가**되었다 (1장, p.16).[^zhou2024]
- 같은 릴리스에서 라이선스가 정리됐다 — **오라클은 남아 있던 상용 기능을 모두 오픈 소스로
  공개하여 OpenJDK 11과 오라클 JDK 11의 코드 및 기능이 완전히 같아졌다.** 대상은 **JMC, JFR,
  NMT, AppCDS, ZGC 등**이며, 그전에는 **가상 머신 실행 시 `-XX:+UnlockCommercialFeatures`를
  추가해야 활성화**되던 것들이었다 (1장, p.16).[^zhou2024]
- 두 배포판의 실제 차이는 코드가 아니라 **지원 조건**이다 (1장, pp.16–17):[^zhou2024]

  | 배포판 | 라이선스 | 무엇이 무료인가 | 업데이트 지원 |
  |---|---|---|---|
  | OpenJDK | GPLv2+CE | 개발·테스트·프로덕션 모두 무료 | 오라클의 직접 지원은 6개월로 제한 |
  | 오라클 JDK | OTN | 개인 용도는 제약 없음. 프로덕션 상업 활용은 유료 | 3년 |

  - 그래서 **'자바가 유료화됐다'는 말은 일부만 사실이다. 유료화는 비즈니스 사용자에게만
    해당하며 비즈니스 사용자는 JDK를 지속해서 업그레이드하거나 유료 지원 서비스를 구매하는 것
    중에서 선택해야 한다** (1장, p.17).
  - **유료 지원 서비스를 오라클만 제공하는 것은 아니다** — **어줄(Azul)의 ZingJDK와 이클립스
    테무린(Eclipse Temurin)도 유료 지원 서비스를 제공한다** (1장, p.17).
- **2019년 2월 오라클은 직전 버전의 OpenJDK 유지 보수를 중단했고, OpenJDK 8과 OpenJDK 11의
  유지 보수 관리 권한이 레드햇으로 이양되었다.** 저자의 평은 — **새롭고 실험적인 기능은 최신
  자바에서만 지원되며 옛 버전에서는 동작하지 않을 것이기 때문에, 기술 개발 측면에서의 리더가
  오라클이라는 사실은 변하지 않을 것**이다 (1장, p.17).[^zhou2024]

## JDK 12 이후의 판올림

- **JDK 12**(2019년 3월 19일)의 가장 큰 기능은 **셰넌도어 가비지 컬렉터**였다 — **레드햇이 개발을
  주도한, 오라클 외부에서 개발된 첫 번째 가비지 컬렉터**다. **오라클은 조건부 컴파일을 이용해
  오라클 JDK 12에서 셰넌도어의 코드를 걷어 냈고, 그래서 셰넌도어는 오직 OpenJDK에서만 이용할
  수 있는 유일한 기능이 되었다** (1장, p.17).[^zhou2024]
- 이후 판올림의 굵은 줄기는 이렇다 (1장, pp.17–18):[^zhou2024]

  | JDK | 날짜 | 주요 변경 |
  |---|---|---|
  | 13 | 2019-09-17 | 소켓 API 재구현, 텍스트 블록 미리 보기 |
  | 14 | 2020-03-17 | 새 `switch` 문 정식 표준, 맥OS·윈도우에서 ZGC 지원 시작, **CMS 가비지 컬렉터가 모든 플랫폼에서 제거**, 솔라리스·스팍 지원 중단 |
  | 15 | 2020-09-16 | **ZGC와 셰넌도어가 '실험 버전' 딱지를 뗌**, 텍스트 블록 정식, 데이터그램 소켓 API 재구현, 편향 락(biased lock) 비활성화 및 폐기 대상 지정(JDK 18에서 완전 제거) |
  | 16 | 2021-03-16 | 메타스페이스 관리 방식 개선, `instanceof` 패턴 매칭, 레코드 클래스, 소스 코드 관리를 머큐리얼에서 깃(깃허브)으로 이전 |
  | 17 (LTS) | 2021-09-14 | 봉인된 클래스, 의사 난수 생성기 개선, JDK 11 대비 JEP 70개 이상 추가, **실험 버전 AOT 컴파일러 삭제** |
  | 18 | 2022-03-22 | UTF-8이 기본, 메서드 핸들을 이용한 리플렉션 재구현, 종료자(`finalize()`) 폐기 대상 지정 |
  | 19 | 2022-09-20 | 외부 함수(foreign function) 및 메모리 API, 가상 스레드, 구조화된 동시성(structured concurrency)을 미리 보기로 |
  | 20 | 2023-03-21 | JEP 6개가 모두 미리 보기·인큐베이터라 정식 기능에는 변화 없음 |
  | 21 (LTS) | 2023-09-19 | JDK 17 대비 JEP 37개 추가. **세대 구분 ZGC와 가상 스레드 도입**, x86용 32비트 윈도우 지원 폐기 대상 지정 |

- 저자는 오라클 인수를 **자바 개발 역사에서 분명한 분기점**으로 본다 — **썬이 이끈 첫 10년 동안
  자바는 확실한 성공을 거두었지만 느린 진화와 낡은 커뮤니티 의사 결정 프로세스라는 문제가
  떠올랐고, 오라클이 지배하게 된 후로는 경쟁이 촉발되어 자바 개발 속도가 썬 시절보다 확연하게
  빨라졌다** (1장, p.19).[^zhou2024]

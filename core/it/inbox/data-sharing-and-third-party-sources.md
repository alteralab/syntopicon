하나의 질문: **데이터를 파일로 넘기지 않고 "공유"한다는 것은 기술적으로 무엇을 뜻하며, 그것이
왜 조직 구조까지 바꾸는가.**

## 공유의 핵심은 멀티테넌시다

- 정의 — **클라우드 데이터 공유(data sharing)의 핵심 개념은 멀티테넌트 시스템이 테넌트 사이의
  데이터 공유를 위한 보안 정책을 지원한다는 것이다. 구체적으로, 세밀한 권한 시스템을 가진 어떤
  공용 클라우드 객체 저장 시스템이든 데이터 공유의 플랫폼이 될 수 있다. 인기 있는 클라우드
  데이터 웨어하우스 플랫폼도 데이터 공유 능력을 지원한다** (5장, p.176).[^reis2022]
- 다운로드와의 차이 — **물론 데이터는 다운로드나 이메일 교환으로도 공유될 수 있지만 멀티테넌트
  시스템이 그 과정을 훨씬 쉽게 만든다** (5장, p.176).[^reis2022]
  - 그 멀티테넌시라는 성질 자체는
    [클라우드 네이티브 아키텍처](../concepts/cloud-native-architecture.md)가 다룬다.
- 알갱이도 세밀해졌다 — **많은 현대 공유 플랫폼(특히 클라우드 데이터 웨어하우스)은 행·열·민감
  데이터 필터링을 지원한다** (5장, p.176).[^reis2022]

## 데이터 마켓플레이스

- **데이터 공유는 여러 인기 클라우드와 데이터 플랫폼에서 이용 가능한 데이터
  마켓플레이스(data marketplace)라는 개념도 매끄럽게 한다. 데이터 마켓플레이스는 데이터
  상거래를 위한 중앙집중식 위치를 제공하며, 거기서 데이터 제공자는 자기 제공물을 광고하고
  데이터에 대한 네트워크 접근을 관리하는 세부를 걱정하지 않고 판매할 수 있다** (5장,
  p.176).[^reis2022]

## 조직 안에서의 공유 — 탈중앙화의 전제

- 파이프라인도 단순해진다 — **데이터 공유는 조직 안의 데이터 파이프라인도 매끄럽게 할 수
  있다. 데이터 공유는 조직의 단위들이 자기 데이터를 관리하고 그것을 다른 단위와 선택적으로
  공유하면서도 개별 단위가 자기 컴퓨트와 질의 비용을 따로 관리하도록 허용한다. 이는 데이터
  탈중앙화를 촉진한다** (5장, p.177).[^reis2022]
- 그 결과 열리는 것 — **이는 데이터 메시 같은 탈중앙 데이터 관리 패턴을 촉진한다** (5장,
  p.177).[^reis2022] 그 패턴의 전문은 [데이터 메시](../concepts/data-mesh.md)에 있다.
- 저자들의 원칙과 정합한다 — **데이터 공유와 데이터 메시는 공통 아키텍처 구성 요소라는 우리
  철학과 밀접하게 부합한다. 가장 신나고 정교한 기술을 껴안기보다 데이터와 전문성의 단순하고
  효율적인 교환을 허용하는 공통 구성 요소를 고르라** (5장, p.177).[^reis2022] 그 원칙의
  자리는 [좋은 데이터 아키텍처의 아홉 원칙](../concepts/good-data-architecture-principles.md)이다.

## 서드파티 데이터 소스

- 왜 늘어나는가 — **기술의 소비자화는 본질적으로 모든 회사가 이제 기술 회사라는 뜻이다. 그
  결과 이 회사들 — 그리고 점점 정부 기관들 — 은 자기 데이터를 고객과 사용자에게, 서비스의
  일부로든 별도 구독으로든 이용 가능하게 만들고 싶어 한다** (5장, p.177).[^reis2022]
- 실물 셋 — **예컨대 미국 노동통계국은 미국 노동 시장에 관한 다양한 통계를 발행한다. 미국
  항공우주국(NASA)은 연구 이니셔티브에서 나온 다양한 데이터를 발행한다. 페이스북은 자기 플랫폼에
  광고하는 기업과 데이터를 공유한다** (5장, p.177).[^reis2022]
- 동기는 플라이휠이다 — **왜 회사들이 자기 데이터를 이용 가능하게 만들고 싶어 하는가? 데이터는
  끈적이고, 사용자가 자기 애플리케이션에 데이터를 통합하고 확장하도록 허용함으로써 플라이휠이
  만들어진다. 더 큰 사용자 채택과 사용은 더 많은 데이터를 뜻하고, 이는 사용자가 자기
  애플리케이션과 데이터 시스템에 더 많은 데이터를 통합할 수 있다는 뜻이다. 부작용은 이제 거의
  무한한 서드파티 데이터 소스가 있다는 것이다** (5장, p.177).[^reis2022]
- 접근 경로 셋 — **직접적인 서드파티 데이터 접근은 흔히 API를 통해, 클라우드 플랫폼의 데이터
  공유를 통해, 또는 데이터 다운로드를 통해 이뤄진다. API는 흔히 깊은 통합 능력을 제공해 고객이
  데이터를 끌어오고 밀어 넣도록 허용한다** (5장, p.177).[^reis2022]
- 그래서 생기는 흔한 워크플로 — **예컨대 많은 CRM이 사용자가 자기 시스템·애플리케이션에 통합할
  수 있는 API를 제공한다. CRM에서 데이터를 가져와 고객 스코어링 모델로 CRM 데이터를 섞고,
  그다음 리버스 ETL로 그 데이터를 CRM으로 되돌려 영업사원이 더 자격 있는 리드에 연락하게 하는
  워크플로를 흔히 본다** (5장, p.177).[^reis2022] 그 되돌리는 경로가
  [수명 주기의 서빙 단계](../concepts/serving-in-the-lifecycle.md)의 리버스 ETL이다.

## 저장 쪽에서 다시 본 데이터 공유

같은 저자들이 6장에서 데이터 공유를 **저장의 큰 흐름** 중 하나로 다시 든다. 5장이 원천 시스템의
접근 경로로 다뤘다면 여기서는 저장 아키텍처의 고려사항이다.

- 무엇을 허용하는가 — **데이터 공유는 조직과 개인이 특정 데이터와 신중히 정의된 권한을 특정
  주체와 공유하도록 허용한다. 데이터 공유는 데이터 과학자가 조직 안의 협업자와 샌드박스의 데이터를
  공유하도록 허용한다. 조직을 가로질러서는 데이터 공유가 파트너 기업 사이의 협업을 촉진한다.
  예컨대 애드테크 회사가 광고 데이터를 고객과 공유할 수 있다** (6장, p.219).[^reis2022]
- 클라우드가 쉽게 만들었지만 새 문제도 만들었다 — **클라우드 멀티테넌트 환경은 조직 간 협업을 훨씬
  쉽게 만든다. 그러나 그것은 새 보안 도전도 제시한다. 조직은 우발적 노출이나 의도적 유출을 막기
  위해 누가 누구와 데이터를 공유할 수 있는지를 지배하는 정책을 신중히 통제해야 한다** (6장,
  p.219).[^reis2022]
- 저장의 큰 흐름 중 하나로 세어진다 — **컴퓨트와 저장의 분리는 이제 클라우드 데이터 시스템에서
  대체로 달성된 사실이다. 그리고 데이터 공유는 업무가 데이터 기술을 채택하면서 점점 중요해지는
  고려사항이다** (6장, p.218).[^reis2022]

## 서빙 쪽에서 세 번째로 본 데이터 공유

같은 저자들이 9장에서 데이터 공유를 **분석·ML에 데이터를 서빙하는 네 방식** 중 하나로 다시 든다
(나머지 셋은 파일·데이터베이스·질의 엔진이다 — [데이터를 서빙하는 방식](../concepts/data-serving-methods.md)).

- 범위의 재확인 — **더 큰 조직 안의 조직이나 단위 사이의 어떤 데이터 교환도 데이터 공유로 볼 수
  있다. 그럼에도 우리가 뜻하는 것은 구체적으로 클라우드 환경의 대규모 멀티테넌트 저장 시스템을 통한
  공유다** (9장, p.355).[^reis2022]
- 서빙이 무엇으로 바뀌는가 — **데이터 공유는 일반적으로 데이터 서빙을 보안과 접근 통제의 문제로
  바꾼다** (9장, p.355).[^reis2022] 파이프라인을 짜는 문제가 권한을 짜는 문제로 대체된다는 뜻이며,
  이 페이지 첫 절의 멀티테넌시가 그 전제다.
- 질의를 누가 도는가 — **실제 질의는 이제 데이터를 소싱하는 엔지니어가 아니라 데이터 소비자(분석가와
  데이터 과학자)가 다룬다. 조직 안의 데이터 메시에서 서빙하든, 공중에 데이터를 제공하든, 파트너
  기업에 서빙하든, 데이터 공유는 설득력 있는 서빙 모델이다** (9장, p.355).[^reis2022]
- 플랫폼의 기본 기능이 됐다 — **데이터 공유는 점점 Snowflake·Redshift·BigQuery 같은 주요 데이터
  플랫폼의 핵심 기능이 되어 회사들이 서로 안전하고 안심하게 데이터를 공유하게 한다** (9장,
  p.355).[^reis2022]
- 서빙 단계의 보안 저류가 같은 것을 처방한다 — **데이터 공유를 워크플로에 쓰는 것도 제안인데, 이는
  당신과 당신의 데이터를 소비하는 사람들 사이에 읽기 전용의 세밀한 통제를 허용한다** (9장,
  p.361).[^reis2022]

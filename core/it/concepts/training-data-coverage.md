하나의 질문: **훈련 데이터가 무엇을 덮어야 하고, 그 배합은 어떻게 정하는가.**

## 커버리지는 다양성을 요구한다

- 절이 여는 규정 — **모델의 훈련 데이터는 그 모델이 풀기를 기대하는 문제의 범위를 덮어야 한다.
  실제 사용자는 흔히 넓은 범위의 문제를 가지며 그 문제를 표현하는 방식도 크게 다를 수 있다.
  애플리케이션의 다양한 사용 패턴을 포착한 데이터를 갖는 것이 모델이 잘 작동하는 데 핵심이다.
  커버리지는 충분한 데이터 다양성(data diversity)을 요구하며, 그래서 많은 이가 이 속성을 데이터
  다양성이라 부른다** (8장, pp.369–370).[^huyen2025]
- 실물 — **예컨대 어떤 사용자는 참조가 풍부한 상세 지시를 구성하는 반면 다른 사용자는 짧은 지시를
  선호한다면, 파인 튜닝 데이터는 상세한 지시와 짧은 지시를 모두 포함해야 한다. 사용자 질의에 통상
  오타가 있다면 오타가 있는 예제를 포함해야 한다. 애플리케이션이 여러 프로그래밍 언어와 함께
  작동한다면 훈련 데이터는 사용자가 신경 쓰는 프로그래밍 언어를 포함해야 한다** (8장,
  p.370).[^huyen2025]

## 다양성의 축은 애플리케이션마다 다르다

- **서로 다른 애플리케이션은 서로 다른 다양성 차원을 갖는다. 예컨대 프랑스어-영어 도구는 언어
  다양성이 필요 없지만 주제·길이·화법의 다양성에서는 이득을 볼 수 있다. 반면 전 세계 고객에게
  제품을 추천하는 챗봇은 도메인 다양성이 반드시 필요하지는 않지만 언어적·문화적 다양성이 중요할
  것이다** (8장, p.370).[^huyen2025]
- 범용 쪽 — **챗봇 같은 범용 유스케이스에서는 파인 튜닝 데이터가 다양해서 넓은 범위의 주제와 화법을
  대표해야 한다. Ding et al.(2023)은 채팅 언어 모델의 성능을 개선하는 가장 직접적인 방법이 훈련
  과정에 쓰이는 데이터의 품질과 다양성을 높이는 것이라고 믿는다** (8장, p.370).[^huyen2025]
- 축을 나눠 설계한 실물 — **Nemotron(Adler et al., 2024)을 개발하며 NVIDIA 연구자들은 과제 다양성·
  주제 다양성·지시 다양성을 가진 데이터셋을 만드는 데 초점을 맞췄는데, 지시 다양성에는 서로 다른 출력
  형식을 위한 지시, 서로 다른 출력 길이를 가진 지시, 열린 답과 예/아니오 답 양쪽을 위한 지시가
  포함된다** (8장, p.370).[^huyen2025]

## 더 넣어서 나빠지는 경우

- 반례 — **"The Data Addition Dilemma"(Shen et al., 2024)는 어떤 경우에는 더 이질적인 데이터를
  추가하는 것이 더 나쁜 성능으로 이어질 수 있음을 시연했다** (8장, p.370).[^huyen2025]
- 그럼에도 다양성이 성능의 주된 동인이라는 쪽 — **메타는 Llama 3가 모델 구조 면에서는 이전 Llama
  버전에서 크게 벗어나지 않는다고 공유했다** (8장, p.370). 저자가 Llama 3 논문에서 그대로 따온
  구절이다 (8장, p.370):[^huyen2025]

  > Llama 3's performance gains are "primarily driven by improvements in data quality and diversity
  > as well as by increased training scale."


## Llama 3의 훈련 단계별 데이터 배합

- 왜 이 표를 보는가 — **Llama 3 논문은 사전 훈련·지도 파인 튜닝·선호 파인 튜닝 세 훈련 단계 전체에
  걸쳐 데이터 커버리지에 대한 풍부한 세부를 담고 있다. 이 장이 사후 훈련 데이터에 초점을 맞추지만,
  같은 모델의 모든 훈련 단계에 걸친 데이터 배합(data mix)을 보는 것은 각 단계의 고려 사항을 비교하고
  부각하는 데 유용하다** (8장, p.370).[^huyen2025]
- **세 단계 모두에서 일관된 다양성 축 하나가 도메인 다양성인데, 다양하다는 것이 정확히 무엇을
  뜻하는지는 다르다** (8장, p.370, Table 8-1):[^huyen2025]

  | | Pre-training | Supervised finetuning | Preference finetuning |
  |---|---|---|---|
  | General knowledge (English) | 50% | 52.66% | 81.99% |
  | Math and reasoning | 25% | 21.19% | 5.89% |
  | Coding | 17% | 14.89% | 6.93% |
  | Multilingual | 8% | 3.01% | 5.19% |
  | Exam-like | X | 8.14% | X |
  | Long context | X | 0.11% | X |

  - 표의 한계 — **이 표는 높은 층위의 도메인만 보여 주며 수학의 하위 범주인 "geometry" 같은 더 세밀한
    주제는 포함하지 않는다. 사후 훈련 데이터는 표에 나오지 않는 다른 다양성 축도 갖는데, 토큰 수
    (맥락과 응답 양쪽)와 턴 수 같은 것이다. Llama 3는 사후 훈련에 합성 데이터를 쓰므로, 또 다른
    차원은 사람이 생성한 데이터 대 AI가 생성한 데이터의 비율이다** (8장, p.370).[^huyen2025]
- 저자가 표에서 읽는 것 — **사전 훈련과 지도 파인 튜닝 동안 수학·추론·코드 토큰을 합친 수가 훈련
  데이터의 거의 절반을 차지한다는 점이 흥미롭다. 인터넷 데이터의 몇 퍼센트가 수학과 코드인지 정확히
  알지는 못하지만 50%보다 한참 아래일 것이라고 믿는다** (8장, p.371).[^huyen2025]
- 어닐링 — **Llama 3 저자들은 소량의 고품질 코드·수학 데이터로 모델을 어닐링(annealing)하는 것,
  곧 점점 작아지는 학습률과 점점 많아지는 코드·수학 데이터로 모델을 훈련하는 것이 핵심 벤치마크에서
  모델 성능을 끌어올릴 수 있다고 공유했다. 이는 고품질 코드와 수학 데이터가 자연어 텍스트보다 모델의
  추론 능력을 높이는 데 더 효과적이라는 통념을 확인해 준다** (8장, p.371).[^huyen2025]
- 선호 단계만 다른 이유 — **선호 파인 튜닝 중 코드와 수학 데이터의 비율은 훨씬 작은데(합쳐서
  12.82%), 목표가 사용자 선호의 실제 분포를 반영하는 것이기 때문일 가능성이 높다** (8장,
  p.371).[^huyen2025]

## 배합을 어떻게 정하는가

- **이것이 질문을 부른다: 올바른 데이터 배합을 어떻게 정하는가? 단순한 접근은 실제 애플리케이션
  사용을 정확히 반영하는 데이터 배합을 고르는 것이다. 최적 데이터 배합을 찾으려고 실험을 쓸 수도
  있다. 예컨대 메타는 74쪽 "Scaling extrapolation"에서 논한 것과 비슷한 스케일링 법칙 실험을
  수행했다. 각 후보 데이터 배합에 대해 그들은 그 배합으로 작은 모델 여럿을 훈련하고 그것으로 그
  배합에서의 큰 모델 성능을 예측했다. 최종 모델 배합은 실험 결과에서 도출된 최선 추정 배합이다**
  (8장, p.371).[^huyen2025] 그 외삽 기법 자체는
  [스케일링 법칙](../concepts/scaling-laws.md)에 있다.

## 품질과 다양성을 갈라 재기

- **데이터 다양성과 품질의 영향을 평가하려고 Zhou et al.(2023)은 흥미로운 실험을 수행했는데, 같은
  크기(예제 2,000개)이면서 서로 다른 특성을 가진 세 데이터셋으로 70억 파라미터 언어 모델을 훈련한
  것이다. 첫째는 고품질이지만 다양하지 않다. 둘째는 다양하지만 저품질이다. 셋째는 다양하면서
  고품질이다** (8장, p.371).[^huyen2025]
- 도판에 인쇄된 세 값이다. 세로축은 생성 품질(Generation Quality) (8장, p.372, Figure
  8-1):[^huyen2025]

  | 데이터셋 | 특성 | 생성 품질 |
  |---|---|---|
  | wikiHow | High-quality, not diverse | 3.49 |
  | Unfiltered Stack Exchange | Low-quality, diverse | 3.33 |
  | Filtered Stack Exchange | High-quality, diverse | 3.83 |

  - 도판 설명이 붙이는 결론 — **고품질이면서 다양한 데이터셋으로 파인 튜닝된 70억 파라미터 모델이
    다양하기만 하거나 고품질이기만 한 데이터셋으로 파인 튜닝된 같은 모델을 능가한다** (8장, p.372,
    Figure 8-1).[^huyen2025]
- 수량 쪽에서도 다양성이 따로 값을 한다 — 파인 튜닝 과제 수를 9개에서 282개로 늘렸을 때의 성능
  변화는 [훈련 데이터 수량](../concepts/training-data-quantity.md)에 있다.

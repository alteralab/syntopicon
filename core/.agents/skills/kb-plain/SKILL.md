# kb-plain

사람이 읽는 산출물의 쓰기 규칙이다. 다 쓴 글을 고치는 교정이 아니라 쓰기 전에
정하는 제약이고, 그래서 이름이 style이 아니라 plain(쉬운 언어)이다. 사람이 읽다
막히면 산출물이 실패한 것이다.

적용 대상은 에이전트가 사람에게 제시하는 텍스트다.

- 리뷰 양식(kb-ingest의 templates): 필수
- kb-query의 답변: 호출에 `--plain` 옵션이 있을 때
- 브리핑과 보고: 권장

KB 본문 페이지는 대상이 아니다. 그쪽 규약은 core/PLAN.md §2와
schema/vocabulary.yaml이 관할한다.

## 규칙

1. 금지 기호. 엠대시(—)와 가운뎃점(·)은 0건이다. 쉼표, 마침표, 괄호, 줄바꿈으로
   바꾼다. 예외는 원문 그대로의 인용(blockquote, code)뿐이다.
2. 기호 압축 금지. `=`, `→` 같은 기호로 문장을 줄이지 않는다. 완결 문장이나
   불릿으로 쓴다.
3. 말을 지어내지 않는다. lexicon.txt의 비승인 어휘는 옆에 적힌 대체어로 쓴다.
   자기 도구의 어휘(클러스터, 코퍼스, 간선 같은 것)는 소스에 없으면 쉬운 말로
   푼다. 예를 들면 "리니지 간선 662개"가 아니라 "모델이 모델을 읽는 참조 662건".
4. 표시 텍스트는 명사구다. 제목, 표 머리글, 라벨에 의문형 종결을 쓰지 않는다.

## 검사

```sh
uv run tools/plaincheck.py <파일>      # 인자가 없으면 stdin을 읽는다
```

검사기가 잡는 것은 규칙 1의 금지 기호, 규칙 2의 화살표(→), 규칙 3의 error
어휘다. 위반이 있으면 exit 1. code fence, inline code, blockquote는 인용으로
보고 건너뛴다. warn 어휘는 경고만 하고 통과시킨다. 규칙 2의 일반 기호 압축과
규칙 4의 명사구 여부는 판단 영역이라 검사기 밖이다.

## 출처와 증보

humanwrite 스킬(전역 설치)의 쓰기 규칙에서 2026-08-10에 발췌해 내재화했다.
humanwrite가 사라져도 이 문서와 lexicon.txt만으로 완결된다. 근거의 격은 검증된
문헌이 아니라 house style과 실측 관찰이다. 비승인 어휘를 승인 대체어와 함께
두는 형식은 ASD-STE100(Simplified Technical English)의 방식이다.

lexicon.txt에 어휘를 더할 때는 어디서 관찰했는지 주석으로 남긴다. 지어낸 말을
발견한 즉시 더하는 것이 맞고, 추측으로 미리 등재하는 것은 금지다.

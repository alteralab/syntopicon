하나의 질문: **어떤 데이터가 필요한지를 정하는 것은 무엇인가.**

## 데이터가 답이 되는 자리

- 절이 여는 전제 — **AI 모델의 모든 문제가 데이터로 풀리는 것은 아니지만, 데이터는 흔히 해법의
  핵심적 부분이다. 올바른 데이터는 모델을 더 유능하고 더 안전하며 더 긴 맥락을 다룰 수 있게 만들 수
  있다. 반대로 나쁜 데이터는 모델의 편향과 환각을 늘릴 수 있다. 데이터의 실수는 모델을 해치고 자원을
  낭비할 수 있다** (8장, p.365).[^huyen2025]
- 누가 하는 일인가 — **데이터 큐레이션(data curation)은 모델이 어떻게 배우는지와 그것을 도울 어떤
  자원이 있는지를 이해할 것을 요구하는 과학이다. 데이터셋 제작자는 애플리케이션 개발자·모델 개발자와
  긴밀히 일해야 한다. 작은 팀에서는 같은 사람일 수 있다 — 모델을 훈련할 책임을 지는 사람이 그것을 위한
  데이터를 확보할 책임도 진다. 그러나 데이터 수요가 큰 조직은 흔히 전문화된 역할을 고용한다** (8장,
  p.365).[^huyen2025]
  - 각주가 그 이유 하나를 든다 — **데이터를 많이 쓴다면 데이터 규정 준수(data compliance)를 보장하는
    일만으로도 전업이 될 수 있다** (8장, p.365 각주 2).[^huyen2025]

## 훈련 방식이 데이터 형식을 정한다

- **어떤 데이터가 필요한지는 당신의 과제와 모델에게 무엇을 가르치고 싶은지에 달려 있다** (8장,
  p.365).[^huyen2025] 저자가 든 대응이다 (8장, p.365):[^huyen2025]

  | 훈련 방식 | 필요한 데이터 형식 |
  |---|---|
  | 자기지도 파인 튜닝(self-supervised finetuning) | sequences of data |
  | 지시 파인 튜닝(instruction finetuning) | (instruction, response) |
  | 선호 파인 튜닝(preference finetuning) | (instruction, winning response, losing response) |
  | 보상 모델(reward model) 훈련 | 선호 파인 튜닝과 같은 형식, 또는 예제마다 점수가 주석된 ((instruction, response), score) |

- 형식보다 앞서는 기준 — **훈련 데이터는 모델이 배우기를 원하는 행동을 보여야 한다. 고품질 데이터
  주석을 확보하는 것은 언제나 어렵지만, 사고 사슬(chain-of-thought, CoT) 추론과 도구 사용 같은 복잡한
  행동을 모델에게 가르치고 싶다면 더욱 어렵다** (8장, p.365).[^huyen2025]

## 사고 사슬 — 최종 답만으로는 못 가르친다

- **5장에서 논한 대로 CoT 프롬프팅은 최종 답을 내놓기 전에 문제를 단계별로 풀어 나가도록 모델을
  민다. 단계별 응답을 생성하도록 모델을 가르치려면 훈련 데이터가 CoT 응답을 포함해야 한다.
  "Scaling Instruction-Finetuned Language Models"(Chun et al., 2024)는 단계별 응답을 파인 튜닝
  데이터에 넣는 것이 여러 크기의 모델의 CoT 과제 성능을 크게 높이며, 어떤 과제에서는 정확도가 거의
  두 배가 됨을 보인다** (8장, pp.365–366).[^huyen2025]
  - #hypothesis 같은 제목의 논문을 이 장은 뒤(p.376)에서 **Chung et al., 2022**로 적는다. 두 표기가
    같은 논문을 가리키는 것으로 보이나 책 안에 확인 근거가 없어 양쪽을 인쇄된 대로 옮겼다 (8장,
    pp.366, 376).[^huyen2025]
- 왜 CoT 데이터가 드문가 — **다단계 응답을 생성하는 일은 지루하고 시간이 많이 걸린다. 수학 문제를
  단계별로 푸는 법을 설명하는 것은 최종 답만 주는 것보다 훨씬 어렵다** (8장, p.366).[^huyen2025]
  저자가 대비로 든 두 예제이며, 둘 다 Chun et al.(2024)의 것이다 (8장, p.366):[^huyen2025]

  ```text
  Instruction: Please answer the following question. What is the boiling point of Nitrogen?
  Response (without CoT): -320.4F

  CoT instruction: Answer the following question by reasoning step-by-step. The cafeteria had 23
  apples. If they used 20 for lunch and bought 6 more, how many apples do they have?
  Response (with CoT): The cafeteria had 23 apples originally. They used 20 to make lunch. So they
  had 23 - 20 = 3. They bought 6 more apples, so they have 3 + 6 = 9.
  ```

- 그 결과 — **그래서 CoT 데이터셋은 다른 지시 데이터셋에 비해 덜 흔하다** (8장,
  p.366).[^huyen2025]

## 도구 사용 — 사람의 방식이 최선이 아니다

- 왜 가르쳐야 하는가 — **모델이 사전 훈련 중에 확보하는 방대한 지식을 생각하면 많은 모델이 어떤
  도구를 쓰는지 직관적으로 알 수도 있다. 그러나 모델의 도구 사용 능력은 도구 사용 예제를 보여 주면
  개선될 수 있다. 도구 사용 데이터를 만드는 데 도메인 전문가를 쓰는 것이 흔하며, 여기서 각 프롬프트는
  도구 사용을 요구하는 과제이고 그 응답은 그 과제를 수행하는 데 필요한 행동들이다** (8장,
  p.366).[^huyen2025]
- 전문가에게 물어보는 것의 한계 — **인간 전문가에게 자기가 하는 일을 설명해 달라고 하면 어떤 단계를
  빠뜨릴 수 있는데, 기억이 부실해서이거나 그 단계가 중요하지 않다고 생각해서다. 정확성을 확보하려면
  사람이 이 과제를 수행하는 것을 관찰하는 것이 흔히 필요하다** (8장, p.366).[^huyen2025]
- 관찰해도 남는 문제 (8장, p.366):[^huyen2025]

  > However, what's efficient for humans might not be efficient for AI, and vice versa. As a
  > result, human annotations might not be ideal for AI agents.

  **예컨대 사람은 웹 인터페이스를 선호할 수 있지만 모델에게는 API를 쓰는 것이 더 쉽다. 무언가를
  검색하려면 사람은 먼저 브라우저를 열고 질의를 복사해 검색창에 붙여 넣고 각 결과를 클릭한다. 반면
  모델은 그냥 질의를 담은 요청을 검색 API에 보내 모든 결과를 한 번에 처리할 수 있다. 이 이유로 많은
  이가 도구 사용 데이터를 생성하는 데 시뮬레이션과 다른 합성 기법에 의존한다** (8장,
  p.366).[^huyen2025] 그 시뮬레이션은
  [전통적 데이터 합성 기법](../concepts/traditional-data-synthesis.md)에 있다.
- 형식도 특별해진다 — **도구 사용 데이터는 특별한 형식을 요구할 수도 있다. 전형적 대화 데이터에서
  사용자와 AI는 턴을 주고받으며 각 턴은 메시지 하나를 담는다. 그러나 도구 사용에서는 AI가 한 턴에
  여러 메시지를 생성해야 할 수 있고 각 메시지는 다른 위치로 보내진다. 예컨대 한 메시지는 코드
  인터프리터로, 다른 메시지는 사용자에게(자기가 무엇을 하는지 알리려고) 보낼 수 있다. 이를 지원하려고
  Llama 3 저자들(Dubey et al., 2024)은 각 메시지의 출처와 목적지를 지정하는 메시지 헤더와 사람 턴과
  AI 턴이 어디서 시작하는지를 지정하는 특수 종료 토큰으로 이뤄진 다중 메시지 채팅 형식을 설계했다**
  (8장, p.367).[^huyen2025]

## 단일 턴과 다중 턴

- **대화 인터페이스를 가진 애플리케이션을 위해 데이터를 큐레이션할 때는 단일 턴(single-turn)
  데이터가 필요한지, 다중 턴(multi-turn) 데이터가 필요한지, 아니면 둘 다인지를 고려해야 한다. 단일
  턴 데이터는 모델이 개별 지시에 응답하도록 훈련하는 데 도움이 된다. 반면 다중 턴 데이터는 모델에게
  과제를 푸는 법을 가르친다 — 많은 실제 과제가 주고받기를 포함한다. 예컨대 질의가 주어지면 모델은
  과제에 착수하기 전에 먼저 사용자의 의도를 명확히 해야 할 수 있다. 모델의 응답 뒤에 사용자는 다음
  단계를 위해 정정이나 추가 정보를 줄 수 있다** (8장, p.367).[^huyen2025]
- 대가 — **단일 턴 데이터는 더 단순하고 따라서 얻기 쉽다. 다중 턴 데이터는 흔히 목적에 맞게 만들어진
  시나리오나 더 관여도 높은 상호작용을 포착할 것을 요구한다** (8장, p.367).[^huyen2025]

## 빼는 것도 큐레이션이다

- **데이터 큐레이션은 모델이 새 행동을 배우도록 돕는 새 데이터를 만드는 것만이 아니라 모델이 나쁜
  행동을 잊도록(unlearn) 돕기 위해 기존 데이터를 제거하는 것이기도 하다** (8장,
  p.367).[^huyen2025]
- 저자가 든 실물 — **ChatGPT 같은 챗봇을 담당하는데 챗봇이 좀 거만해서 사용자를 짜증나게 하고 그들의
  토큰을 낭비한다는 사용자 불만을 듣는다고 하자. 예컨대 사용자가 어떤 진술이 사실적으로 옳은지
  검증해 달라고 하면 챗봇은 "그 진술은 옳지만 문체는 더 나아질 수 있습니다"라고 답한다. 그러고는
  요청하지도 않은 진술 재작성을 이어서 내놓는다. 조사해 보니 훈련 데이터에 요청하지 않은 제안을 담은
  주석 예제가 여럿 있음을 발견한다. 이 예제들을 훈련 데이터에서 제거하라는 요청과, 요청하지 않은
  재작성 없이 사실 확인을 시연하는 새 예제를 확보하라는 또 다른 요청을 넣는다** (8장,
  p.367).[^huyen2025]

## 세 기준

- **애플리케이션마다 서로 다른 특성의 데이터를 요구할 수 있다. 서로 다른 훈련 단계도 서로 다른
  데이터를 요구한다. 그러나 높은 층위에서 데이터 큐레이션은 세 기준을 따른다: 데이터 품질(data
  quality)·데이터 커버리지(data coverage)·데이터 수량(data quantity)** (8장,
  p.367).[^huyen2025]
- 저자가 붙인 비유 — **모델 훈련을 요리로 생각하면 모델에 들어가는 데이터는 재료다. 데이터 품질은
  재료의 품질과 같다 — 재료가 상했으면 좋은 음식을 만들 수 없다. 데이터 커버리지는 재료의 올바른
  배합을 갖는 것과 같다(예컨대 설탕이 너무 많거나 너무 적으면 안 된다). 데이터 수량은 재료를 얼마나
  가져야 하는가에 관한 것이다** (8장, p.367).[^huyen2025]
- 2장이 같은 세 가지를 다른 이름 배열로 부른다 — **양·품질·다양성이 훈련 데이터의 세 황금 목표다**
  (2장, p.70).[^huyen2025] 커버리지가 요구하는 것이 다양성이므로 두 목록은 겹친다 (8장,
  p.370).[^huyen2025]

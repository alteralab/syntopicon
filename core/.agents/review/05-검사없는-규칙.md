# 검사 없는 규칙

점검 계획(`04-계획.md`) 1단계의 산출물이다. 규칙과 검사를 나란히 놓고 빈칸을 찾는다.
아무것도 고치지 않았고, 저장소에는 이 파일 하나만 더해졌다.

조사 날짜는 2026-08-12이다. 모든 판정은 코드를 열어 확인했거나 실제로 규칙을
어겨서 확인했다. 확인하지 못한 것은 5절에 따로 적었다.

## 1. 요약

| 항목 | 수 |
|---|---|
| 뽑은 규칙 | 132 |
| 막힘(validate가 커밋을 막는다) | 38 |
| 보고(lint가 리포트한다) | 29 |
| 사람(리뷰 양식이 묻는다) | 10 |
| **없음** | **55** |

규칙 넷 중 하나 남짓(42퍼센트)이 아무 검사도 받지 않는다.

그보다 큰 발견이 셋 있다. 셋 다 실제로 깨뜨려 확인한 것이다.

1. **목차 형식 검사가 낡았다.** `PLAN.md` 2.6은 2026-08-11에 목차 정본을 링크 불릿
   목록으로 바꿨는데, `lint.py`의 `_has_toc`는 폐기된 인라인 문단형을 여전히 목차로
   인정한다. 폐기 형식으로 쓴 115줄 페이지가 검출 0건으로 통과했다.
2. **반입 트레일러 검사가 형식을 보지 않는다.** `lint.py`의 `ingest-trailer`는
   문자열이 있는지만 본다. 소스를 추가한 커밋 10건 모두 문자열은 갖고 있어 리포트가
   깨끗한데, `git interpret-trailers --parse`로 실제 트레일러가 되는 것은 5건뿐이다.
   절반이 조회되지 않는 상태로 통과하고 있다.
3. **citekey 구조 규칙에 검사가 없다.** `schema/common.yaml`의 주석은 구조 규칙을
   "파이썬 관계 규칙 층이 검사한다"고 적었지만 검사하는 코드가 없다. 저자도 연도도
   없는 `nostructurekey.md`가 validate를 통과했다.

## 3. 검사에 쓰인 것의 목록

대조표의 오른쪽 칸이 무엇을 가리키는지 밝힌다.

  그것은 저장소 상태를 바꾸는 일이라 하지 않았다.
- **overlap의 실제 동작.** 임베딩 벡터가 있어야 돌아간다. 벡터 저장소를 건드리지
  않으려고 실행하지 않았다.
- **리뷰 양식의 실효.** 사람이 채우는 것이라 실행해 볼 대상이 아니다. 채워진 양식이
  저장소에 남지 않아 과거에 실제로 지켜졌는지도 확인할 방법이 없었다. 이것 자체가
  `사람` 등급 열 건의 공통 약점이다.
- **실제 커밋 차단.** 훅 스크립트를 직접 돌려 종료 코드로 확인했고, 커밋을 시도해
  보지는 않았다. git 인덱스를 건드리지 않으려는 이유다.
- **evals 시나리오의 덮는 범위.** 스킬 규칙을 얼마나 검증하는지는 이번 범위 밖이라
  보지 않았다. `사람` 등급과 스킬 쪽 `없음` 열두 건의 판정이 이것으로 바뀔 수 있다.
- **PLAN의 나머지 절.** 과업이 지정한 절(2, 2.6, 3, 4.4)과 스킬, 스키마 주석만
  뽑았다. 4.1 검색 스택, 4.2 승급 사다리, 4.5 멀티 KB, 5 백업, 6 운영 캘린더의
  규칙은 뽑지 않았다.

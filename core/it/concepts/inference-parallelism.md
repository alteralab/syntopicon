## 두 계열과 한 특수 계열

- **가속기는 병렬 처리를 위해 설계되고 병렬화 전략은 고성능 컴퓨팅의 척추다. 많은 새 병렬화 전략이
  개발되고 있다. 이 절은 참고를 위해 그중 몇 가지만 다룬다. 모든 모델에 걸쳐 적용될 수 있는 병렬화
  전략의 두 계열은 데이터 병렬화와 모델 병렬화다. LLM에 특별히 적용되는 전략 계열은 컨텍스트 병렬화와
  시퀀스 병렬화다. 최적화 기법 하나가 여러 병렬화 전략을 수반할 수 있다** (9장,
  p.444).[^huyen2025]

## 복제 병렬화

- **복제 병렬화(replica parallelism)는 구현하기가 가장 단순한 전략이다. 그것은 그저 서빙하려는 모델의
  복제본을 여럿 만든다. 복제본이 많을수록 더 많은 요청을 동시에 다룰 수 있지만, 잠재적으로 더 많은
  칩을 쓰는 대가를 치른다. 서로 다른 크기의 모델을 서로 다른 칩에 맞춰 넣으려는 것은 빈 패킹
  (bin-packing) 문제이고, 모델과 복제본과 칩이 많아질수록 복잡해질 수 있다** (9장,
  p.445).[^huyen2025]
  - 각주 — **훈련 중에는 같은 기법을 데이터 병렬화(data parallelism)라고 부른다** (9장, p.445 각주
    27).[^huyen2025]

## 빈 패킹 문제가 되는 두 상황

- 저자가 든 설정 — **서로 다른 크기(예: 8B·13B·34B·70B 파라미터)의 모델이 섞여 있고 서로 다른 메모리
  능력(예: 24 GB·40 GB·48 GB·80 GB)의 GPU에 접근할 수 있다고 하자. 단순화를 위해 모든 모델이 같은
  정밀도인 8비트라고 가정한다** (9장, p.445):[^huyen2025]
  - **칩의 수가 고정되어 있으면 지표를 최대화하도록 각 모델에 복제본을 몇 개 만들지, 각 복제본에 어떤
    GPU를 쓸지 정해야 한다. 예컨대 40 GB GPU 하나에 13B 모델 셋을 두어야 하는가, 아니면 이 GPU를
    34B 모델 하나를 위해 예약해야 하는가?**
  - **모델 복제본의 수가 고정되어 있으면 비용을 최소화하도록 어떤 칩을 확보할지 정해야 한다. 그러나
    이 상황은 드물게 일어난다.**

## 모델 병렬화 — 텐서 병렬화

- 언제 필요한가 — **흔히 모델이 너무 커서 기계 하나에 들어가지 않는다. 모델 병렬화(model
  parallelism)는 같은 모델을 여러 기계에 걸쳐 쪼개는 관행을 가리킨다. 모델 병렬화에서는 모델을 칩에
  맞춰 넣는 것이 훨씬 더 복잡한 문제가 될 수 있다** (9장, p.445).[^huyen2025]
- **모델을 쪼개는 방법은 여럿이다. 추론에 가장 흔한 접근은 텐서 병렬화(tensor parallelism)이고,
  연산자 내 병렬화(intra-operator parallelism)라고도 알려져 있다. 추론은 행렬 곱 같은 다차원 텐서에
  대한 일련의 연산자를 수반한다. 이 접근에서는 한 연산자에 관여하는 텐서가 여러 기기에 걸쳐 분할되어,
  사실상 이 연산자를 병렬로 실행될 더 작은 조각으로 쪼개 계산을 빠르게 한다. 예컨대 두 행렬을 곱할 때
  행렬 하나를 열 방향으로 쪼갤 수 있다** (9장, p.445, Figure 9-18).[^huyen2025]
- 두 가지 이득 — **텐서 병렬화는 두 가지 이득을 제공한다. 첫째, 기계 하나에 들어가지 않는 큰 모델을
  서빙하는 것을 가능하게 한다. 둘째, 지연을 줄인다. 그러나 지연 이득은 추가 통신 오버헤드 때문에 줄
  수 있다** (9장, p.445).[^huyen2025]

## 파이프라인 병렬화

- **모델을 쪼개는 또 다른 방법은 파이프라인 병렬화(pipeline parallelism)인데, 이는 모델의 계산을
  뚜렷이 구별되는 단계로 나누고 각 단계를 서로 다른 기기에 배정하는 것을 수반한다. 데이터가 모델을
  흘러가면서 각 단계는 한 부분을 처리하고 다른 단계들은 뒤따르는 부분을 처리해, 겹치는 계산을 가능하게
  한다** (9장, p.446).[^huyen2025] 도판 설명 — **파이프라인 병렬화는 모델 분할이 병렬로 실행되게
  한다** (9장, p.446, Figure 9-19 설명).[^huyen2025]
- 마이크로 배치 — **Figure 9-19는 배치가 더 작은 마이크로 배치로 쪼개질 수 있음을 보인다. 마이크로
  배치가 한 기계에서 처리된 뒤 그 출력은 다음 기계의 모델 다음 부분으로 넘겨진다** (9장,
  p.446).[^huyen2025]
- 대가와 그래서 갈리는 선택 — **파이프라인 병렬화가 큰 모델을 여러 기계에서 서빙할 수 있게 하지만,
  그것은 파이프라인 단계 사이의 추가 통신 때문에 각 요청의 총지연을 늘린다. 따라서 엄격한 지연 요건을
  가진 애플리케이션에는 파이프라인 병렬화가 통상 회피되고 복제 병렬화가 선호된다. 그러나 파이프라인
  병렬화는 처리량을 늘리는 데 도움이 될 수 있으므로 훈련에서는 흔히 쓰인다** (9장,
  p.447).[^huyen2025]

## 컨텍스트 병렬화와 시퀀스 병렬화

- **덜 흔하지만 기법의 다양성을 보이려고 잠깐 언급할 만한 두 기법이 컨텍스트 병렬화(context
  parallelism)와 시퀀스 병렬화(sequence parallelism)다. 둘 다 긴 입력 시퀀스 처리를 더 효율적으로
  만들려고 개발되었다** (9장, p.447).[^huyen2025]
  - 원문의 이 문장은 `They were both developed to make long input sequence processing more
    efficient, including context parallelism and sequence parallelism.`으로 인쇄되어 두 이름이 한
    문장 안에서 되풀이된다 — 조판 잔여물로 보이나 책 안에 확인할 근거가 없다. #hypothesis
- 둘의 차이 (9장, p.447):[^huyen2025]
  - **컨텍스트 병렬화에서는 입력 시퀀스 자체가 서로 다른 기기에 걸쳐 쪼개져 따로 처리된다. 예컨대
    입력의 앞 절반은 기계 1에서, 뒤 절반은 기계 2에서 처리된다.**
  - **시퀀스 병렬화에서는 입력 전체에 필요한 연산자가 기계에 걸쳐 쪼개진다. 예컨대 입력이 어텐션과
    순방향 계산을 둘 다 요구하면 어텐션은 기계 1에서, 순방향은 기계 2에서 처리될 수 있다.**

이 페이지의 질문: **자바 가상 머신의 명령어는 어떤 제약 아래 설계되었고, 그 제약이 명령어의
종류와 자바 언어의 동작에 무엇을 남겼는가.**

## 1바이트가 정하는 것

- 명령어의 정의부터 보자 — **자바 가상 머신의 명령어는 특정 작업을 뜻하는 바이트 길이의 숫자인
  연산 코드(opcode)와 해당 작업에 필요한 0개 이상의 피연산자로 이루어진다. 명령어 대부분이
  피연산자 없이 연산 코드 하나로 구성되며, 피연산자는 피연산자 스택에 저장된다** (6장,
  p.339).[^zhou2024]
- 제약은 둘이고 둘 다 대가가 있다 — **연산 코드 길이가 1바이트(0~255)로 제한되기 때문에 최대
  256개의 연산 코드만 표현할 수 있다. 또한 클래스 파일 구조에서는 컴파일된 코드에 들어 있는
  피연산자의 길이 정렬(length alignment)을 허용하지 않는다. 따라서 1바이트가 넘는 데이터를 처리할
  때는 가상 머신이 런타임에 해당 바이트들을 특정 구조로 재구성해야 한다** (6장,
  p.339).[^zhou2024] 예컨대 부호 없는 16비트 정수는 두 바이트를 `(byte1 << 8) | byte2` 꼴로
  합쳐 만들며, **이러한 작업 때문에 바이트코드를 해석하고 실행하는 속도가 조금 느려진다.**
- 그 대가를 치르고 얻는 것이 형식의 크기다 — **피연산자 길이 정렬을 포기하면 수많은 패딩과 공백을
  없앨 수 있다. 또한 연산 코드들이 바이트 하나로 표현되기 때문에 컴파일된 결과물이 짧고 간결하다.
  최소한의 데이터로 높은 전송 효율을 추구하는 이 설계는 자바 언어가 목표하던 시장이 주로
  네트워크와 스마트 가전이었다는 기술적 배경에서 유래되어 지금까지 이어지고 있다** (6장,
  p.339).[^zhou2024]
  - 정렬 규칙에 예외가 둘 있다 — **바이트코드 명령어 스트림은 기본적으로 1바이트 단위로 정렬된다.
    단, `tableswitch`와 `lookupswitch` 명령어는 예외다. 이 두 명령어는 피연산자가 특수하기
    때문에(4바이트 단위로 구분) 패딩용 빈 공간을 확보해야 한다** (6장, p.339, 각주 16).

## 기본 실행 모델

- 예외 처리를 뺀 해석 실행의 뼈대는 네 줄이면 끝난다. **간단한 모델이지만 매우 효과적이고
  정확하게 동작한다** (6장, p.339):[^zhou2024]

  ```text
  do {
      PC 레지스터의 값을 자동으로 계산한다.
      바이트코드 스트림에서 PC 레지스터가 가리키는 위치의 연산 코드를 가져온다.
      (피연산자가 필요한 바이트코드라면) 바이트코드 스트림에서 피연산자를 가져온다.
      연산 코드가 정의하는 동작을 수행한다.
  } while(바이트코드 스트림 길이 > 0);
  ```

## 타입을 이름 앞 글자에 넣는다

- 대부분의 명령어가 타입을 자기 이름에 담고 있다 — **자바 가상 머신 명령어 집합을 보면 대다수
  명령어 자체에 해당 연산에 필요한 데이터의 타입 정보가 포함되어 있다. 예컨대 `iload` 명령어는
  지역 변수 테이블에서 피연산자 스택으로 `int` 타입 데이터를, `fload` 명령어는 `float` 타입
  데이터를 읽어 들인다. 이 두 명령어의 동작은 가상 머신 내부에서는 똑같은 코드 조각으로 구현할 수
  있지만 클래스 파일에는 별도의 연산 코드로 기록되어야 한다** (6장, p.340).[^zhou2024]
- 접두 문자는 이렇게 대응한다 — **`i`는 `int` 타입 데이터 연산을 뜻하고, `l`은 `long` 타입,
  `s`는 `short`, `b`는 `byte`, `f`는 `float`, `d`는 `double`, `a`는 참조 타입의 연산을 뜻한다**
  (6장, p.340).[^zhou2024]
  - 예외도 있다 — **`arraylength` 명령어의 피연산자는 배열 타입 객체여야 하지만 특정한 문자로
    시작하지 않는다.** 그리고 **무조건 점프 명령어인 `goto`와 같이 데이터 타입과 무관한 명령어도
    있다** (6장, p.340).
- 1바이트 제약이 여기서 다시 작동한다 — **겨우 1바이트에 불과한 연산 코드에 데이터 타입 정보까지
  포함시키려면 명령어 종류를 설계하는 데 신중을 기해야 했다. 자바 가상 머신의 런타임 데이터
  타입을 전부 구분해 지원하려 했다면 1바이트로는 도저히 표현할 수 없었을 것이다. 그래서 자주
  쓰이는 연산과 데이터 타입 조합에만 전용 명령어를 배정했다. 그래서 전용 명령어가 없는 타입은 별도
  지시문을 이용해서 지원되는 타입으로 변환해 사용한다** (6장, p.340).[^zhou2024]
- 그 결과가 자바 언어 동작에 그대로 남아 있다 — **`byte`, `char`, `short` 전용 명령어는 거의
  없으며 `boolean` 타입 전용 명령어는 하나도 없다. 그래서 컴파일러는 컴파일타임이나 런타임에
  `byte`와 `short` 데이터는 `int` 타입으로 부호 확장(sign extension)한다. `boolean`과 `char`
  데이터는 역시 `int` 타입으로 제로 확장하여 해당하는 `int` 전용 명령어로 실행한다** (6장,
  p.340).[^zhou2024]
  - 배열도 마찬가지다 — **`boolean`, `byte`, `short`, `char` 타입 배열을 처리할 때도 대응하는
    `int` 타입 바이트코드 명령어를 사용하도록 변환한다. 즉, 이 네 가지 데이터 타입 관련 연산은
    실제로는 해당 `int` 타입 연산 코드를 사용하여 수행된다** (6장, p.340).
- 어느 타입에 전용 연산 코드가 있는지는 명령어 이름 앞 문자 `T`를 갈아 끼워 읽는 표로 정리되어
  있다 (6장, p.341, 표 6-10 발췌):[^zhou2024]

  | 연산 코드 | byte | short | int | long | float | double | char | 참조 |
  |---|---|---|---|---|---|---|---|---|
  | `Tipush` | `bipush` | `sipush` | | | | | | |
  | `Tconst` | | | `iconst` | `lconst` | `fconst` | `dconst` | | `aconst` |
  | `Tload` | | | `iload` | `lload` | `fload` | `dload` | | `aload` |
  | `Tstore` | | | `istore` | `lstore` | `fstore` | `dstore` | | `astore` |
  | `Tinc` | | | `iinc` | | | | | |
  | `Taload` | `baload` | `saload` | `iaload` | `laload` | `faload` | `daload` | `caload` | `aaload` |
  | `Tadd` | | | `iadd` | `ladd` | `fadd` | `dadd` | | |
  | `Tshl` | | | `ishl` | `lshl` | | | | |
  | `Treturn` | | | `ireturn` | `lreturn` | `freturn` | `dreturn` | | `areturn` |

  - **비어 있는 칸은 가상 머신이 해당 데이터 타입 전용 연산 코드를 지원하지 않는다는 뜻이다**
    (6장, p.340).
- 이름 뒤에 홑화살괄호가 붙는 표기도 하나 있다 — **`iload_<n>`은 `iload_0`, `iload_1`,
  `iload_2`, `iload_3`을 총칭한다. 명령어족들은 모두 피연산자가 하나뿐인 기본 명령어(예:
  `iload`)의 특수 형태다. 이러한 특수 명령어들은 피연산자를 따로 가져올 필요가 없다. 필요한
  피연산자가 명령어 자체에 암묵적으로 포함되어 있기 때문이다** (6장, p.342).[^zhou2024] 이것을
  **명령어족(instruction family)** 이라 부르며, **`iload_0`는 피연산자가 0인 `iload` 명령어와
  의미가 완벽하게 일치한다.**

## 아홉 가지 범주

- 저자는 연산 코드를 하나씩 설명하는 대신 아홉 범주로 나눈다 (6장, pp.341–350):[^zhou2024]
  - **로드와 스토어** — **스택 프레임의 지역 변수 테이블과 피연산자 스택 사이에서 데이터를 주고받는
    데 쓰인다.** 지역 변수를 스택으로 읽는 `Tload` 계열, 스택 값을 지역 변수에 저장하는 `Tstore`
    계열, 상수를 스택으로 읽는 `bipush`·`sipush`·`ldc`·`ldc_w`·`ldc2_w`·`aconst_null`·`Tconst`
    계열, 그리고 **더 넓은 인덱스를 사용하여 더 많은 지역 변수에 접근하거나 더 큰 피연산자에
    접근하기** 위한 `wide`가 있다 (6장, p.342).
  - **산술** — 아래 절에서 따로 본다.
  - **형 변환** — 아래 절에서 따로 본다.
  - **객체 생성과 접근** — **클래스 인스턴스와 배열도 객체다. 하지만 자바 가상 머신은 이 두 가지
    객체의 생성과 조작에 서로 다른 바이트코드 명령어를 사용한다.** 인스턴스 생성 `new`, 배열 생성
    `newarray`·`anewarray`·`multianewarray`, 필드 접근 `getfield`·`putfield`·`getstatic`·
    `putstatic`, 배열 원소 읽기·쓰기, 배열 길이 `arraylength`, 타입 확인 `instanceof`·`checkcast`
    (6장, p.346).
  - **피연산자 스택 관리** — 꺼내기 `pop`·`pop2`, 복제 `dup` 계열, 맨 위 두 값 치환 `swap` (6장,
    p.346).
  - **제어 전이** — **프로그램의 실행 흐름을 조건에 따라 또는 무조건적으로 지정한 위치의 명령어로
    이동시킨다.** 개념적으로는 **PC 레지스터의 값을 조건부로 또는 무조건적으로 변경**하는 것이다.
    조건 분기 `if` 계열, 복합 조건 분기 `tableswitch`·`lookupswitch`, 무조건 분기 `goto` 계열
    (6장, pp.346–347).
    - 여기서도 `int`가 중심이다 — **`boolean`, `byte`, `char`, `short` 타입 조건 분기에는 모두
      `int` 타입용 명령어를 사용하고 `long`, `float`, `double` 타입의 조건 분기에는 각 타입 전용의
      비교 연산 명령어를 먼저 실행한다.** 그 비교 명령어가 **결괏값으로 `int` 타입 값을 피연산자
      스택에 넣어 두면, 이어서 `int` 타입용 조건 분기 연산을 수행하여 전체 분기를 마무리하는
      형태**다. 그래서 **자바 가상 머신에서 `int` 타입용 조건 분기 명령어가 가장 풍부하고
      강력하다** (6장, p.347).
  - **메서드 호출과 반환** — **메서드 호출 명령어는 다음 5개가 전부다** (6장, pp.347–348).
    - **`invokevirtual`: 객체의 인스턴스 메서드를 호출하며, 객체의 실제 타입에 따라 디스패치(가상
      메서드 디스패치)한다. 자바 언어에서 가장 많이 쓰이는 메서드 디스패치 방식이다.**
    - **`invokeinterface`: 인터페이스 메서드를 호출하며, 런타임에 이 인터페이스 메서드를 구현한
      객체를 검색하여 적절한 메서드를 찾는다.**
    - **`invokespecial`: 인스턴스 초기화 메서드, `private` 메서드, 부모 클래스의 메서드를 포함하여
      특수 처리가 필요한 일부 인스턴스 메서드를 호출한다.**
    - **`invokestatic`: 클래스 메서드(`static` 메서드)를 호출한다.**
    - **`invokedynamic`: 런타임에 호출 사이트 한정자가 참조하는 메서드를 동적으로 찾아 호출한다.
      앞의 4개 호출 명령어의 디스패치 로직은 사용자가 변경할 수 없는 반면, `invokedynamic`의
      디스패치 로직은 자바 가상 머신 실행 시 사용자가 설정할 수 있다.**
    - 반환 쪽만 타입에 매인다 — **메서드 호출 명령어 자체는 데이터 타입과 무관하다. 단지 메서드
      반환 명령어만 반환값의 타입에 따라 구분되어 있다.** `ireturn`은 **반환값이 `boolean`,
      `byte`, `char`, `short`, `int`일 때** 쓰이고, `void`·인스턴스 초기화 메서드·클래스 초기화
      메서드에는 `return`이 쓰인다 (6장, p.348).
  - **예외 처리** — **자바 프로그램에서 `throw` 문으로 예외를 명시적으로 던지는 작업은 `athrow`
    명령어로 구현된다.** 그리고 **자바 가상 머신은 예외 처리(`catch` 문)를 바이트코드 명령어 대신
    예외 테이블을 이용해 구현한다** (6장, p.348).
  - **동기화** — 아래 절에서 따로 본다.

## 산술 명령어와 예외를 던지는 조건

- 동작 형태는 스택 기반이다 — **산술 명령어들은 피연산자 스택의 값 두 개를 이용해 특정한 산술
  연산을 수행하고, 결괏값을 다시 피연산자 스택의 맨 위에 저장한다. 이 명령어들은 대체로 정수
  데이터를 다루는 부류와 부동 소수점 데이터를 다루는 부류로 구분할 수 있다** (6장,
  p.343).[^zhou2024]
- 정수 쪽에서 명세가 정한 것과 정하지 않은 것이 갈린다 — **《자바 가상 머신 명세》에는 정수
  데이터가 오버플로되었을 때 어떤 결과를 내야 하는지가 명시되어 있지 않다. 한편 정수 데이터의
  나누기(`idiv`와 `ldiv`)와 나머지(`irem`과 `lrem`) 연산 시 나누는 값이 0이면
  `ArithmeticException`을 던져야 한다는 점은 규정해 놓았다. 이 외의 다른 정수 산술 시나리오에서는
  런타임 예외를 던지지 않아야 한다** (6장, p.343).[^zhou2024]
- 부동 소수점 쪽은 외부 표준을 그대로 받는다 — **《자바 가상 머신 명세》는 가상 머신이 부동 소수점
  수를 처리할 때 IEEE 754 명세가 지정한 동작과 제한 사항을 엄격히 준수하도록 했다. 즉, 자바 가상
  머신은 IEEE 754가 정의한 비정규화된 부동 소수점 수(denormalized floating-point number)와 점진적
  언더플로(gradual underflow) 연산 규칙을 완벽하게 지원해야 한다** (6장, p.344).[^zhou2024]
  - 반올림 규칙 둘이 이름을 갖고 있다 — 연산 결과는 **표현 가능한 두 값이 '수학적으로 정확한 값'과
    차이가 똑같다면 최하위 비트가 0인 값을 우선**하는 **'가까운 값으로 반올림(round to
    nearest)'** 을 쓰고, **부동 소수점 수를 정수로 변환할 때는 '0에 가까운 값으로 반올림(round
    toward zero)'한다**(양수면 내림, 음수면 올림) (6장, p.344).
  - 예외를 던지지 않는다는 점이 정수 쪽과 다르다 — **자바 가상 머신은 부동 소수점 연산을 수행할 때
    런타임 예외를 던지지 않는다**(여기서 말하는 것은 자바 언어 수준의 예외이며 **IEEE 754의 부동
    소수점 예외는 연산 시그널이라고 한다**). **연산이 오버플로되면 부호 있는 무한대로 표현하며,
    연산 결과에 대한 명확한 수학적 정의가 없다면 NaN(숫자가 아님) 값으로 표현한다. 참고로
    피연산자가 NaN이면 어떤 산술 연산이든 결과는 NaN이 된다** (6장, p.344).
  - 비교도 두 방식으로 갈린다 — **자바 가상 머신은 `long` 타입 값을 비교할 때는 부호 있는 비교
    방식을 사용하고, 부동 소수점 값을 비교하는 `dcmpg`, `dcmpl`, `fcmpg`, `fcmpl` 연산자들은
    IEEE 754가 정의한 시그널(예외)을 보내지 않는 비교(nonsignaling comparison)를 수행한다** (6장,
    p.344).

## 형 변환 명령어

- 넓어지는 쪽은 공짜다 — **데이터 타입의 표현 범위가 넓어지는 경우는 변환 명령어를 명시하지 않아도
  자바 가상 머신이 알아서 수행해 준다. 이 변환에서는 정보를 잃을 게 없으니 항상 안전하다** (6장,
  p.344).[^zhou2024] `int`→`long`, `float`→`double`, `long`→`float`·`double`이 그렇다.
- 좁아지는 쪽은 명시해야 하고 값이 변할 수 있다 — **반대로 표현 범위가 축소될 때는 형 변환
  명령어를 반드시 명시해야 한다(`i2b`, `i2c`, `i2s`, `l2i`, `f2i`, `f2l`, `d2i`, `d2l`, `d2f`
  등). 축소 변환 시에는 결과의 부호나 단위가 바뀌거나 수치 정밀도가 떨어질 가능성이 있다** (6장,
  p.345).[^zhou2024]
  - 부호가 뒤집히는 기제까지 적혀 있다 — **`int`나 `long` 타입을 크기가 N바이트인 정수 타입 T로
    축소한다면, 변환 과정에서 N바이트를 넘어서는 내용은 단순히 버려진다.** 그래서 **원래 타입의
    최상위 비트가 부호를 뜻하는데, 변환 과정에서 상위 비트들이 버려지면서 하위 N바이트 중 첫 번째
    비트가 부호로 해석**된다 (6장, p.345).
  - 부동 소수점을 정수로 줄일 때의 규칙은 셋이다 — **부동 소수점 값이 NaN이면 변환 결과는 `int`
    또는 `long` 타입의 값 0이다.** 그렇지 않으면 **'0에 가까운 값으로 반올림' 규칙을 따라 정숫값을
    구하고**, 그 값이 대상 타입의 표현 범위를 벗어나면 **부호가 양수면 대상 타입이 표현할 수 있는
    가장 큰 값, 음수면 가장 작은 값**이 된다 (6장, p.345).
- 그럼에도 예외는 없다 — **데이터 타입을 축소 변환하면 오버플로, 언더플로, 정밀도 손실이 발생할 수
  있다. 하지만 《자바 가상 머신 명세》는 숫자 타입의 축소 변환 명령어가 런타임 예외를 던질 수
  없다고 규정하고 있다** (6장, p.345).[^zhou2024]

## 동기화는 두 갈래로 구현된다

- 지원 범위와 공통 기제가 먼저다 — **자바 가상 머신은 메서드 수준 동기화와 메서드 안의 명령어 블록
  동기화를 지원한다. 두 구조의 동기화 모두 구현에는 모니터(보통 락이라고 부름)를 이용한다** (6장,
  p.348).[^zhou2024]
- 메서드 수준에는 전용 명령어가 없다 — **메서드 수준 동기화는 바이트코드 명령어가 아니라 메서드
  호출과 반환 명령어로 구현된다. 가상 머신은 메서드 테이블에 있는 `ACC_SYNCHRONIZED` 접근 플래그를
  확인하여 동기화된 메서드인지 알 수 있다** (6장, p.348).[^zhou2024]
  - 절차는 이렇다 — **메서드가 호출되면 호출 명령어는 우선 해당 메서드의 `ACC_SYNCHRONIZED` 접근
    플래그가 설정되어 있는지 확인한다. 설정되어 있다면 실행 스레드가 메서드 본문으로 진입하기 전에
    모니터를 획득해야 한다. 본문 실행을 마치면 정상 완료 여부와 관계없이 모니터를 해제한다. 한
    스레드가 메서드를 실행하는 동안 다른 스레드는 동일한 모니터를 얻을 수 없다** (6장, p.348).
  - 예외 경로도 정의되어 있다 — **동기화된 메서드를 실행하는 도중 예외가 발생했는데, 메서드 안에서
    직접 처리할 수 없다면 예외를 외부로 던진다. 이때 해당 스레드가 보유한 모니터가 자동으로
    해제된다** (6장, pp.348–349).
- 블록 동기화에는 전용 명령어 둘이 있다 — **`synchronized` 문을 지원하기 위해 자바 가상 머신은
  `monitorenter`와 `monitorexit` 명령어를 준비했다. `synchronized` 키워드의 요구 사항을 올바르게
  구현하려면 javac 컴파일러와 자바 가상 머신이 잘 협력해야 한다** (6장, p.349).[^zhou2024]
- 협력의 내용은 짝 맞추기다 — **메서드가 어떻게 종료되는지와 상관없이 컴파일러는 `monitorenter`
  명령어 각각에 대응하는 `monitorexit` 명령어가 실행되도록 보장해야 한다** (6장,
  p.349).[^zhou2024] 컴파일된 결과를 보면 그 보장이 어떻게 구현되는지 보인다 (6장, p.349,
  코드 6-6):

  ```text
  Method void onlyMe(Foo)
      0: aload_1               // 객체 f를 스택에 푸시
      1: dup                   // 스택의 최상위 원소(f의 참조)를 복사
      2: astore_2              // 스택의 최상위 원소를 지역 변수 테이블의 변수 슬롯 2에 저장
      3: monitorenter          // 스택 최상위 원소(f)를 락으로 사용하여 동기화 시작
      4: aload_0               // 변수 슬롯 0의 원소(this 포인터)를 스택에 푸시
      5: invokevirtual #5      // doSomething() 메서드 호출
      8: aload_2               // 변수 슬롯 2의 원소(f)를 스택에 푸시
      9: monitorexit           // 동기화 끝
     10: goto 18               // 메서드 정상 종료(18행 return 명령어로 점프)
     13: astore_3              // 이 단계는 예외 발생 시 시작
     14: aload_2               // 변수 슬롯 2의 원소(f)를 스택에 푸시
     15: monitorexit           // 동기화 끝
     16: aload_3               // 변수 슬롯 3의 원소(예외 객체)를 스택에 푸시
     17: athrow                // onlyMe() 메서드의 호출자로 예외 객체 던짐
     18: return                // 메서드 반환
  ```

  - 예외 테이블이 그 보장을 완성한다 — **컴파일러는 메서드가 비정상 종료되더라도 `monitorenter`와
    `monitorexit` 명령어가 여전히 올바르게 짝지어져 실행되도록 예외 처리 로직을 자동으로 구성한다.
    예외 테이블을 보면 어떤 예외가 발생해도 처리할 수 있도록 만들어졌음을 알 수 있다**(`type` 열의
    `any`). **그래야 어떠한 경우에도 `monitorexit` 명령어를 빠뜨리는 일이 없기 때문**이다 (6장,
    pp.349–350).

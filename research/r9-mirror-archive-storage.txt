## 판정 요약 (500GB·20년, 2026-08-08 실측)

**1. S3 신상품 실체**: 둘 다 docs-mirror에 부적합 확정. S3 Tables는 Apache Iceberg 테이블 전용(분석 워크로드) — table bucket에는 테이블만 저장 가능, 파일·git 보관 불가. S3 Express One Zone(directory buckets)은 단일 AZ 저지연 스토리지로 $0.110/GB-월 = Standard의 4.8배·Deep Archive의 111배 — 아카이브와 정반대 용도.

**4. 20년 운용 리스크**: AWS는 해지 후 90일 post-closure(이전 조사 "30일"은 정정 — 30일은 재개설 시 미납 지불 기한), 90일 후 콘텐츠 영구 삭제. Backblaze ToS는 미납 시 삭제 유예 일수를 **명시하지 않음**("may delete your data") — 어떤 관리형도 결제 실패에 계약상 안전판이 약하므로 관리형은 3-2-1의 오프사이트 1벌이어야 하고 유일 사본이면 안 된다. 완화책: 멀티 결제수단 등록, 연 단위 결제 캘린더 점검(기존 2–3주 주기 유지비 안에 수렴), 자격증명·복구 절차를 패스워드 매니저+가족 접근 가능 문서로 이중화(벤더 공식 승계 프로그램은 확인 실패 — unresolved). 두 벤더 병행 비용: **Deep Archive + B2 = 월 $3.97, 20년 ≈ $953**(권장 조합) / B2 + Scaleway Glacier ≈ 20년 $1,165 / B2 + R2 IA = 20년 $2,034.

**5. 적재 방식**: rclone은 성숙하나 git working tree의 파일 단위 sync는 부적합 — mtime이 오브젝트 메타데이터라 갱신에 copy/재업로드 유발, symlink·권한 미보존, git gc의 packfile 재작성 시 대량 재업로드, 비원자적 sync. **git bundle(전량 1회 + 증분) 또는 restic repo(이미 core 레이어에 계획된 스택 재사용)** 형태의 대형 불변 오브젝트로 변환해 올려야 하며, 이 방식이어야 Deep Archive의 180일 최소 보존·40KB/오브젝트 오버헤드·48h 복원과도 정합한다.

**권고안**: 주 계층 = restic repo 또는 git bundle을 S3 Deep Archive에(20년 $119, 단 복원 RTO 최대 48h+egress 비용 유의), 부 계층 = B2에 동일 산출물(즉시 접근·3x 무료 egress로 검증 리스토어 무료, 20년 $834). 합계 20년 ≈ $953로 예산 내이며 벤더 이중화 충족. Hetzner BX11은 restic 네이티브 타깃으로서 유력한 B2 대체 후보지만 현행가 미실측(unresolved) 상태로 결정 보류.

## 결론 먼저: docs-mirror에 객체 스토리지 자가 호스팅은 기각. "bare git mirror + 아무 디스크 + SSH/restic"이 정답이다.

### 1. MinIO 이후 오픈소스 객체 스토리지 3종 실측 (GitHub API, 2026-08-08)

| 항목 | Garage | SeaweedFS | Ceph |
|---|---|---|---|
| 라이선스 | AGPL-3.0 | Apache-2.0 | LGPL 혼합 |
| 최신판 | v2.3.0 (2026-04-16) | 4.41 (2026-08-06) | v21 Tentacle |
| 12개월 커밋 | 393 | 2,901 | 8,195 |
| bus factor | 1인+공적펀딩(NGI/NLnet 연 0.5–3 FTE) 의존 | 창시자 1인이 커밋 절대다수(10,128 vs 2위 531) | 커뮤니티 건전 |
| 1인 1노드 적합성 | 설계가 geo-distributed 3노드·RF=3 전제. v2.3에 --single-node 모드가 생겼으나 설계 목적과 불일치 | 단일 노드 가능·활발하나 1인 유지 리스크 | OSD당 RAM 4GB+·다노드 전제 — 명백한 과잉 |

셋 다 "죽은 프로젝트"는 아니지만, 20년 지평의 1인 운영에서 Garage는 펀딩 의존, SeaweedFS는 1인 의존이라는 지속성 리스크를 안고 있고, Ceph는 규모 과잉이 공식 하드웨어 문서로 확정된다. 그리고 결정적으로 — **이 데이터에는 S3 API 자체가 불필요하다(아래 3).**

### 2. NAS 실측
- **Synology**: 2025-04 서드파티 HDD 제한 → 반발·판매 타격 → **2025-10-07 DSM 7.3에서 철회**(비검증 드라이브 설치·스토리지 풀 생성 재허용, 단 M.2 풀/캐시는 여전히 HCL 강제). 정책이 18개월 새 두 번 뒤집힌 것 자체가 20년 지평의 신뢰 리스크. 공식 릴리스노트 원문은 JS 렌더로 미확인(보도 5건 교차확인).
- **QNAP TS-464**(4-bay, N5095, 8GB): 드라이브 검증 강제 없음.
- **TrueNAS Community Edition 25.10**: 무료, ZFS(scrub·checksum·스냅샷·replication), 최소 8GB RAM·2코어·16GB SSD 부트, ECC 권장이나 필수 아님. 미니PC 조합 시 가장 유연.
- 디스크 실가: 신품 NAS/엔터프라이즈급 바닥 **$28–30/TB** (IronWolf Pro 16TB $450, Exos 12TB $350). Backblaze 2025 AFR 1.36%(344,196드라이브).
- 20년이면 HDD 수명 6.75년(기존 확정) 기준 **디스크 3세대 + 본체 약 2세대** 교체. NAS 경로 20년 TCO ≈ **$3,000–4,500 + 상시 노동**(scrub 확인·DSM/OS 업데이트·고장 대응) — 500GB 데이터에는 유지비 예산(2–3주당 30–45분)을 core 백업과 나눠 써야 하는 부담이 가장 큰 비용이다.

### 3. 핵심 질문의 답 — 객체 스토리지는 필요 없다 (근거 확정)
콘텐츠의 90%+가 git repo다. git이 이미 스토리지 시스템의 3요소를 내장한다:
- **프로토콜**: SSH remote는 인증·암호화·압축 전송을 제공 (Pro Git: "access over SSH is secure — all data transfer is encrypted and authenticated... making the data as compact as possible").
- **무결성**: `git fsck` = "Verifies the connectivity and validity of the objects in the database" — 콘텐츠 주소화(SHA)라 bit rot이 검출된다.
- **증분**: `git clone --mirror`는 모든 refs를 미러하고 `git remote update` 한 번으로 증분 동기화 (공식 git-clone 문서 명시).

S3 API가 주는 것(HTTP API·멀티테넌시·버저닝)은 1인 git 미러에서 소비자가 없다. 오히려 S3 위에 git을 얹으면 비표준 헬퍼가 필요해 복잡도만 는다. **"아무 디스크 위의 bare repo"가 기술적으로 완전한 중앙 사본이며, NAS를 쓰더라도 그 역할은 '단순 SSH 서버 + bare mirror 디렉토리'면 충분하다** — Garage/SeaweedFS/Ceph/MinIO 대체재 논의 전체가 이 층위에서 소거된다. 나머지 10%(크롤 산출물)는 일반 파일이므로 동일 디스크에 restic/rsync로 처리.

### 4. 외장 디스크 2개 로테이션 (최저기술 대안)
20년 TCO ≈ **$900–1,100**(8TB급 2개 × 3세대, $28–30/TB 실가), 전기 0, 랜섬웨어·전기 사고에 오프라인 면역. AFR 1.36% 기준 2–3주 로테이션 주기 내 두 디스크 동시 고장 확률은 무시 가능. 주의점 1개: Backblaze 데이터는 상시가동 기준이라 cold 보관 HDD의 장기 신뢰성 1차 데이터는 없음 — 로테이션(주기적 통전+fsck)이 이 공백을 실질적으로 메운다.

### 5. 자가 호스팅 임계 실측
- **B2 $6.95/TB/월**(2026 현행, 종전 $6에서 인상), 3x 저장량 무료 egress, 최소 보존 없음 → 500GB = **월 $3.48, 20년 ≈ $834, 노동 ≈ 0**.
- rsync.net $12/월(800GB 최소, git-annex 명시 지원). Hetzner Storage Box(1–20TB, SSH/borg/restic, 트래픽 무제한)는 정확 요금 미확인.
- 손익분기: NAS 고정비($150–225/년 상각+전기)가 B2($83.4/TB/년)를 넘어서는 지점은 **상시 2–3TB부터(노동비 제외)**. 프라이버시 축은 공개 문서 미러라 소거, 회선 축도 500GB≈반나절 업로드라 소거. **500GB 가정에서는 관리형이 압도하고, 가정 (a)의 500GB에 실제 도달해도 겨우 임계 하단이다.**

### 권고안
1. **지금**: docs-mirror의 bare mirror(`git clone --mirror`)를 **외장 HDD 2개 로테이션**(1차 사본, ~$300 초기)에 두고, `git remote update` + `git fsck`를 로테이션 루틴에 포함.
2. **원격 사본**: core restic 타깃과 **동일 B2 버킷 계정**에 rclone/restic으로 bare repo 디렉토리 통째 백업(월 $3.48) — 신규 인프라 0. upstream 소멸 가정 (b)의 대비는 이 3-2-1로 완성된다.
3. **NAS는 조건부**: core restic 타깃을 어차피 NAS로 정하게 되면 docs-mirror bare repo도 같은 상자에 얹되(TrueNAS CE + 미니PC가 서드파티 제한·비용 면에서 우위), docs-mirror만을 위해 NAS를 사지는 말 것. 객체 스토리지 데몬(Garage 등)은 어떤 경로에서도 설치하지 않는다.

KEY: git-native-preservation
--- SUMMARY ---
docs-mirror(90%+가 git repo)의 보존 축 6개를 1차 소스로 실측했다. 결론: (1) GitHub fork는 public upstream 삭제·private 전환 모두에서 살아남는 공식 보장이 있는 0원 보험이다 — 단 public 한정, 자동 sync 없음(주기 sync 필요, 대신 upstream rewrite 비전파라는 보존상 장점), 가시성 변경 불가. (2) Software Heritage save-code-now API(`POST /api/1/origin/save/git/url/...`)로 임의 공개 저장소 등록이 실제로 되며 GitHub/GitLab URL은 자동 accepted, Vault의 git-bare cooking(`/api/1/vault/git-bare/(swhid)/`)으로 clone 가능한 bare repo 복원까지 왕복이 성립한다(단 본 사이트가 봇 차단이라 rate limit·처리시간 수치는 미확정). (3) restic-git packfile 중복제거 붕괴는 공식 포럼에서 실증 확인 — 완화는 재clone 금지·fetch 증분·gc.auto=0(공식 문서 확인). (4) git bundle은 verify 내장·증분 지원·단일 불변 파일이라 '시점 스냅샷 보존' 요구에 정확히 부합하며 객체 스토리지 계층에 적합. (5) bare mirror + remote update는 prune을 켜지 않는 한 upstream에서 삭제된 branch가 로컬에 잔존한다는 것이 git 공식 문서로 확정 — 보존 미러에서는 prune 금지. (6) 크롤 산출물 쪽은 Wayback SPN2 API(S3 키 인증, 30k/일)로 렌더링본 시점 보존 요청이 가능하다. 종합하면 'fork(0원 1차 보험) + SWH 등록(공공 2차 보험) + 로컬 bare mirror(gc.auto=0, no-prune) + 주기 bundle을 restic/객체 스토리지에(시점 동결)'의 4겹 구성이 모두 공식 근거 위에서 성립한다.

[LB] fork 보험의 한계 (1): private upstream이 삭제되면 private fork도 함께 삭제된다("Deleting a private repository will delete all forks of the repository"). 한계 (2): fork의 가시성은 독립 변경 불가 — "You cannot change the visibility of a fork by itself." 즉 fork 보험은 public 저장소(벤더 docs repo는 대부분 public)에만 성립하고, fork를 private으로 바꿔 숨길 수 없다.
     src: https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/working-with-forks/about-forks (2026-08-08)
[LB] fork 보험의 한계 (3): fork는 자동 sync되지 않는다 — 공식 syncing-a-fork 문서상 UI 'Sync fork'/gh CLI/git fetch upstream 중 하나로 수동 동기화해야 하며, fork 시점 이후의 upstream 커밋은 사용자가 주기적으로 sync하지 않으면 fork에 없다. 역으로 이 성질 때문에 upstream의 이력 rewrite(force-push)도 fork에 자동 전파되지 않는다 — fork는 마지막 sync 시점의 이력을 그대로 보존한다. 다만 fork network 내 객체 공유 caveat("Commits pushed to any repository in a network can be accessible from other repositories in that network")가 있어 network 수준에서 객체가 노출/잔존할 수 있다.

--- SUMMARY ---
핫 로컬 캐시 + 콜드 보존 계층 설계를 1차 소스 실측으로 확정했다. (1) 계층 수는 대체 불가능성에 차등: 3-2-1-1-0(Veeam)의 개인 번역은 docs-mirror에 core보다 얇은 계층을 주되 '0원 보험'을 깔아두는 것. (2) 콜드 경제 실측: Deep Archive $0.00099/GB-월(180일 최소)로 500GB×20년=$118.80, 전량 복원은 Bulk 48h ~$37/Standard 12h ~$46 — B2($6.95/TB, 20년 $834, 복원 무료·즉시)의 1/7, Wasabi($7.99/TB+1TB 최소과금+90일 최소+egress 공정사용 조건 → 20년 $1,918)는 탈락. '거의 안 꺼내는 시점 스냅샷' 최적 계층 = Deep Archive 확정. (3) 구조적 제약 발견: restic은 cold storage 백엔드 불가(issue #3202, 2020~open)라 Glacier에는 self-contained 파일만 갈 수 있고, git bundle이 정확히 그 형태다 — revision range 증분 + verify + 직접 clone 지원. git 이력의 append-mostly 특성상 'full 1개+월간 증분 체인'이 모든 과거 시점을 중복 없이 보존하므로 GFS식 full 다중화가 불필요(체인 손상 대비 수년 주기 re-baseline만). (4) core 타깃 공유: restic 태그+--group-by로 한 repo 안에서 mirrors/core 보존 정책 분리가 공식 지원되고, B2는 API 무료·최소기간 없음이라 한계 비용은 순수 저장량뿐. (5) 권고: 현행 5–30GB에서는 ⓐ GitHub fork(upstream 삭제 시 fork가 새 upstream으로 승격 — 공식 확인) + ⓒ core restic/B2 repo에 mirror 태그로 통합(연 $2.50, 노동 0 추가). ~100GB 돌파 시 ⓑ 월간 git bundle→Deep Archive 체인을 추가하고 restic 쪽은 유한 보존으로 전환. ⓓ NAS는 오프사이트가 아니라 단독 부적격, ⓔ 상시 동기화 풀 미러는 보존 보장 대비 운영비 과잉. 이 구성은 2–3주당 30–45분 유지비 예산 안에 든다.

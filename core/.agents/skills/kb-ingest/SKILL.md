# kb-ingest

**신규 페이지 생성이 아니라 기존 페이지 갱신이 본체다.** 소스 하나가 신규 포함
10–15개 페이지를 건드리는 것이 정상이고, 새 페이지 하나 만들고 끝내는 것이 가장
흔한 실패다 — 같은 개념이 여러 페이지에 흩어져 몇 달 뒤 overlap lint로 돌아온다.

단계마다 **누가 하는 일인지**가 정해져 있다. 스크립트가 할 일을 손으로 하지 않는다.

## 저장소 위치 확정 (cwd 독립 — 최초 1회)

이 스킬의 `uv run tools/…` 명령은 전부 core 저장소 루트 기준이다. cwd가 core가
아니면(다른 프로젝트에서 호출) 먼저:

```sh
cd "$(dirname "$(dirname "$(dirname "$(realpath "${CLAUDE_SKILL_DIR:-$HOME/.claude/skills/kb-ingest}")")")")"
```

## 0. KB 스코프 게이트 [스크립트]

`--kb`는 필수다. 대상 KB가 없으면 **여기서 멈춘다.**

```
uv run tools/validate.py       # KB 목록이 출력된다
```

KB가 없으면 "KB가 없습니다. kb-new를 먼저 실행하십시오"라고 말하고 끝낸다.
임의 위치에 파일을 흘리지 않고, 묻지 않고 KB를 만들지도 않는다.

## 1. 소스 큐레이션 [인간]

넣을 가치의 판단은 사용자 몫이다. 확인할 것 하나: **원서와 번역서가 둘 다 있으면
원서를 들인다.** 번역서는 확립 역어의 참조원으로만 쓴다.

**논문인데 사용자가 지목하지 않았으면 `/paper-search`로 후보를 뽑는다** — 자격 판정
기준은 그 스킬이 갖는다. 고르는 것은 여전히 사용자이고, 고른 뒤 2단계로 온다.

**Medium 글은 `/medium-dl`로 원문을 먼저 확보한다** — 취득이 끝나면 `_unread`에
파일로 있으므로 2단계부터는 로컬 파일과 같은 흐름이다(`--url`이 아니라 파일로 —
Medium은 Cloudflare가 비브라우저 요청을 막아 snapshot.py가 직접 못 받는다).

입력은 두 모드다: **원서만** 제공되거나, **원서 + 번역서**가 함께 제공된다.

**⚠ 한글 파일명은 `ls | grep`·`find -iname`으로 찾지 마라 — 있는 파일도 없다고 나온다.**
macOS가 파일명을 NFD(자모 분리)로 저장하는데 프롬프트에서 온 패턴은 NFC라 바이트가
안 맞는다. 조회(`stat`)는 정규화를 무시해 통과하지만 `readdir` 출력은 NFD 그대로다.
**존재 확인은 `[ -f "<전체 경로>" ]`로 한다.** 2026-08-12 실측: `ls | grep 카프카`가
0건을 내자 "번역서가 사라졌다"고 판단해 한 장을 역어 참조 없이 반입했다 — 298MB
파일이 그 자리에 있었다. **도구가 못 찾은 것과 없는 것은 다르다.**

번역서가 함께 오면 4단계에서 같은 구간을 대조해 역어를 참조하되 —

- claim·각주·직인용·스냅샷·citekey는 **원서에만** 건다. 번역서는 소스가 아니라
  참조원이므로 소스 메타를 만들지 않고, 원서 소스 메타에 참조원 표기 한 줄만 남긴다.
- 역어 채택은 건별 판단이다. 참조원은 정본이 아니다 — 실측 사례: "합산 가능"은
  채택감, "점진적 스냅샷"(accumulating)·"Referention Integrity"(오식)는 기각감,
  dimensional/multidimensional을 다 "다차원"으로 뭉갠 것은 원문 구분 소실.
- 큰 스캔 PDF는 장 단위로 분할해 시각 판독한다(추출 텍스트 레이어는 OCR 잡음이
  섞이므로 기계 추출로 읽지 않는다).

## 2. 스냅샷 [스크립트] — 소급 불가능

파이프라인에서 되돌릴 수 없는 유일한 단계라 맨 앞에 있다. 원문을 먼저 고정한다.

**이미 들인 소스를 다시 읽을 때는 `it/archive/<citekey>/`를 본다 — 원본 경로가 아니다.**
같은 책의 다른 장을 반입할 때가 그렇다. 아카이브가 존재하는 이유가 이것이고,
번역서도 함께 들어 있으면 거기 있다. 2026-08-12 실측: 반입 지시에 `~/Downloads`
경로를 적었더니 그 파일을 못 찾아 한 장이 역어 참조 없이 들어갔다 — 같은 번역서가
`it/archive/shapira2021/`에 298MB로 멀쩡히 있었다. **원본은 옮겨지고 사라지지만
아카이브는 그러라고 두는 것이다.**

**아직 안 읽은 원본은 `it/archive/_unread/`에 둔다.** 계약이 없는 자리이고, 반입할 때
꺼내 `snapshot.py`에 넘기면 `<citekey>/`로 승격된다. 밑줄 접두를 쓰는 이유는 citekey
문법이 밑줄로 시작할 수 없어서다 — **밑줄 = 우리 것, 나머지 = 원문**이고, 다이제스트
계산도 이 규칙으로 우리 파일을 뺀다.

### 재개점은 `_progress.yaml`이 정본이다

`it/archive/<citekey>/_progress.yaml`이 **어디까지 읽었는지**를 답한다. 소스 메타의
산문은 정본이 아니다 — "이번 런 범위"는 쓰는 시점의 말이라 다음 런이 오면 거짓이 되고,
실제로 **아홉 런 뒤처져** 있었다(2026-08-12 실측: 메타는 "2장과 6장"이라 적고 있었고
실제로는 1~14장 전부였다. 그 상태로 재개하면 이미 있는 것을 다시 넣는다).

```yaml
citekey: shapira2021
unit: page              # page | chapter | url | whole — 소스가 나뉘는 단위
total: "1-419"
covered: ["1-419"]      # 읽고 반입까지 끝난 범위
skipped:                # 읽었으나 옮기지 않은 것 — **각주로는 보이지 않는다**
  - range: "378"
    why: "요약이라 claim 아님"
next: null              # 재개점. 완주면 null
```

- **쪽이 기본 단위다.** 장은 경계가 해석에 열려 있다(13장에 요약 p.378이 드는가?).
  실측: 에이전트가 13장 중간에 죽었을 때 재개를 "pp.339–366까지, pp.366–378 남음"으로
  이어받았지 장으로는 표현되지 않았다. 논문은 `whole`, 웹 문서는 `url`.
- **`covered`와 `skipped`가 같은 단위여야 산수가 된다** — 남은 것 = 전체 − 둘.
- **`skipped`가 각주 파생이 못 하는 부분이다.** 각주는 *쓴 것*만 알므로, 읽고 안 옮긴
  것과 안 읽은 것이 구분되지 않는다. 그것을 적지 않으면 다음 세션이 다시 읽는다.
- **런이 끝날 때 갱신한다.** 커밋과 같은 단계다(9단계 참조).

```
uv run tools/snapshot.py --kb <kb> --citekey <citekey> <파일…>
uv run tools/snapshot.py --kb <kb> --citekey <citekey> --url <URL>
```

출력된 `snapshot` / `snapshot_sha256` / `accessed` 세 줄을 3단계 소스 메타에 그대로 넣는다.

**PDF면 스냅샷이 텍스트 레이어 판정도 출력한다**(`--group ingest`로 실행 시 —
pdf-inspector). 그 판정을 `_progress.yaml` 머리말에 옮겨 적어라: image_based나
OCR 필요 판정이면 "직인용은 훼손 없는 구간만·식별자 실표기 복원"이 그 소스의
표준 지침이 되고(zhou2024 실측 규약), 파싱 거부면 변환판 의심이라 쪽 오프셋
실측을 건너뛸 수 없다(thomas2020 실측).

## 3. 소스 메타 [LLM 제안 + 스크립트 발급]

citekey는 손으로 짓지 않는다 — 발급은 O_EXCL이어야 하고, 규칙은 결정적이다.

```
uv run tools/citekey.py --kb <kb> --author <성> --year <연도> [--slug <말>] --type <CSL타입>
```

만들어진 씨앗 파일에 CSL 필드를 채운다. 필드명은 CSL 원어 그대로
(`ISBN`/`DOI`/`URL`/`accessed`/`event-title`/`collection-title`/`authority`).
**날짜와 번호는 반드시 따옴표 문자열** — arXiv ID는 따옴표가 없으면 부동소수점이 된다.

## 4. 지식 추출 [LLM] — 본체

먼저 **닿을 페이지를 찾는다.** 새로 만들기 전에 갱신할 곳을 찾는 것이 순서다.

```
uv run --group index tools/ksearch.py "<개념>"
uv run tools/edges.py neighbors <관련페이지> --depth 2
```

쓰는 규칙:

- claim은 **각주 달린 불릿**. `[^citekey]` + 각주 텍스트에 locator(페이지·절).
- **한국어로 재서술**하되 개념 첫 등장에 원어 병기 — 영속성(persistence).
  확립 용어(TTA·국어원) 우선, 미확립이면 원어 유지.
- **정의·정리·수치는 번역하지 말고 원문 직인용**(인용 블록). 의미는 원문이,
  해설은 한국어가 담당한다.
- 비전 읽기가 콘텐츠 필터 오탐에 반복 차단되면 그 구간은
  `uv run --group ingest tools/pdftext.py <pdf> <시작쪽> <끝쪽>` 추출본으로
  우회한다(도판 누락은 각주에 기록).
- **코드는 소스에 있는 것만.** 짧은 조각은 인라인 백틱, 복사해 쓸 것은 펜스로
  개념당 하나까지(SCHEMA.md §3). **지어내지 않는다** — 소스에 없는 코드는 예제가
  아니라 발명한 claim이고, 코드는 그럴듯해 보여서 산문보다 위험하다. 문맥
  의존부를 깎는 것은 허용이되 없는 줄을 보태 "완성"시키지 않는다.
- 불확실한 것은 `#hypothesis`, 근거가 얇으면 `#speculation`. 그 둘이 어휘의 전부다.
- **반입 진행 상태를 페이지 본문에 적지 않는다** — "~장은 아직 반입되지 않았다"는
  다음 런이 돌면 거짓이 된다(SCHEMA 본문 절 실측). 진행은 `_progress.yaml`에만,
  페이지에는 실재하는 링크만.
- 새 페이지를 만들면 **허브에 연결**한다(고아 페이지 방지). 슬러그는 영어 번역,
  소문자 kebab, 숫자 시작 금지.
- 맞는 허브가 없어 새로 만들 때: **이름 범위 = 지금 넣는 내용 범위**(SCHEMA.md §5).
  넓은 이름을 미리 잡아 두지 않는다 — 범위가 자라면 형제 허브가 생기는 구조다.

## 5. inbox 격리 [구조]

기계 산출물은 전부 `<kb>/inbox/`에 착지한다. `concepts/`·`synthesis/` 직행은 없다.
`status: draft`를 단다.

**기존 페이지 갱신도 같은 경로다** — 갱신된 전체 페이지를 **같은 슬러그**로
`inbox/`에 착지시킨다(개정판). concepts의 원본은 그대로 두고, 리뷰어는 두 파일의
diff로 무엇이 변했는지 본다. 승인 시 `tools/merge.py`가 원본을 대치한다.
concepts + inbox의 같은 슬러그 쌍은 validate가 개정 대기로 인정한다.

사용자가 "내가 종합한 거니 synthesis에 바로 넣어달라"고 해도 마찬가지다 —
`synthesis/`의 경계 기준은 **작성 주체와 리뷰**이지 내용의 종합성이 아니다.

## 7. 커밋 [규약]

1런 = 1커밋. 트레일러 두 줄이 필수다.

```
<kb>: <소스 요지> ingest

왜 들였는지 1–3문장. 변경 파일 나열 금지 — diff가 담당한다.

Ingest-Source: <citekey>
Ingest-Run: <런ID>
```

**트레일러 블록은 본문과 빈 줄 하나로 떼되, 블록 안에서는 빈 줄을 넣지 않는다.**
git은 마지막 문단만 트레일러로 보고, 그 문단이 전부 `키: 값` 꼴이어야 한다. 둘 다
실패 사례가 있다 (2026-08-10 실측):

- `Co-Authored-By`를 빈 줄 뒤에 붙임 → 앞 문단의 `Ingest-*`가 본문으로 강등(9커밋)
- 빈 줄을 아예 없앰 → 산문이 섞인 문단이라 블록 자체가 인식 안 됨

문자열 검사인 lint는 둘 다 통과시키므로 가려진다. 확인은
`git log --format=%B -1 | git interpret-trailers --parse`로 한다 — 이벤트 저널이
트레일러이므로 형식이 곧 조회 가능성이다.

실패해도 손해는 inbox 잔류뿐이다 — 본 코퍼스는 6단계까지 불변이었다.

**다중 소스 세션에서는 런별로 착지 즉시 커밋한다** — 두 런의 파일을 한 워킹
트리에 섞으면 사후 분리에서 실수가 난다(2026-08-07 실측: 34파일이 한 커밋에
섞여 revert로 복구). 커밋·푸시 같은 상태 변경 명령은 체인으로 잇지 말고
단계별로 결과를 확인한다.

## 8. 리뷰 [인간 + 에이전트 브리핑]

맨눈 diff 리뷰 금지. 에이전트가 **리뷰 템플릿을 채워 제시**하고, 사람은 "사람이
답할 것"에만 항목별로 답한다 (누락은 의지가 아니라 절차로 막는다 — WHO 수술
체크리스트 실증).

템플릿이 항목의 정본이다 (`templates/`):

- inbox의 diff가 **concepts 대상**이면 `templates/review-concepts.md`
- **synthesis 대상**(판단 서술이나 허브 초안)이면 `templates/review-synthesis.md`
  — 기준의 격이 다르다: concepts는 무해성과 구조만 빠르게, synthesis는 내용
  동의까지 (승인 = 저작 주체의 이전)

채울 때 지킬 것: 발견은 "고쳐놨다"가 아니라 목록으로 (수정 여부도 사람 결정),
글은 kb-plain 규칙 (기호 최소, 쉬운 낱말 — 사람이 읽다 막히면 양식 실패.
정본은 `../kb-plain/SKILL.md`, 검사는 `uv run tools/plaincheck.py`).

리뷰 기준은 여전히 **무해성·구조**다. 내용의 전수 정확성 검증은 concepts에서
금지 (review-on-read 이연, 기준을 넓히면 처리량이 0으로 수렴한다) — synthesis만
예외다.

## 9. 승급·재색인·커밋 [자동] — 한 덩어리다

한 덩어리는 코드다 — promote가 merge, reindex, qmd 색인(update·embed·cleanup),
lint를 순서대로 돌리고 런 계측을 stats.sqlite에 남긴다. 중간이 실패하면 남은
단계를 밝히고 멈춘다.

```
uv run --group index tools/promote.py --kb <kb>
# it/archive/<citekey>/_progress.yaml 갱신 — covered·skipped·next
git add -A <kb>/ && git commit          # 트레일러: Ingest-Run
```

**`_progress.yaml` 갱신을 빼먹으면 다음 세션이 이미 넣은 것을 다시 넣는다.** 이 파일이
재개점의 정본이고 소스 메타 산문은 아니다(4단계 참조). git 밖이라 커밋에는 안 담기지만
같은 단계에서 손대야 잊지 않는다.

**커밋까지가 승급이다.** 승급하고 커밋을 미루면 다음 런 산출물과 한 워킹 트리에
섞이고 사후에 갈라야 한다 — 2026-08-12에 **두 런 연속** 그랬고(5장·11장) 둘 다 다음
런 에이전트가 잡았다. 겹친 허브 파일은 파일 단위로 갈리지 않아 뒤 커밋으로 넘겼다.
**다음 런을 띄우기 전에 워킹 트리가 비어 있는지 본다.**

옛 벡터의 정리(qmd cleanup)가 필요한 이유와 실측은 promote.py가 소유한다 —
거를 수 있는 손 절차였을 때 세 번 샜고, 지금은 사슬에 박혀 있다.

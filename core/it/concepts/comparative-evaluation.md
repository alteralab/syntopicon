하나의 질문: **어느 모델이 가장 좋은지를 점수 없이, 서로 붙여 보는 것만으로 정할 수 있는가.**

## 점수가 아니라 순위가 필요할 때

- 왜 평가하는가 — **흔히 모델을 평가하는 것은 그 점수에 관심이 있어서가 아니라 어느 모델이 자기에게
  최선인지 알고 싶어서다. 당신이 원하는 것은 이 모델들의 순위다. 점별 평가(pointwise evaluation)나
  비교 평가(comparative evaluation) 중 하나로 모델의 순위를 매길 수 있다** (3장,
  pp.148–149).[^huyen2025]
- 점별 평가 — **점별 평가에서는 각 모델을 독립적으로 평가한 뒤 그 점수로 순위를 매긴다. 예컨대 어느
  무용수가 가장 좋은지 알아내려면 각 무용수를 개별적으로 평가해 점수를 주고 가장 높은 점수를 받은
  무용수를 고른다** (3장, pp.148–149).[^huyen2025]
  - 각주 — **리커트 척도(Likert scale)를 쓰는 것 같은 방식이다** (3장, p.148 각주 22).[^huyen2025]
- 비교 평가 — **비교 평가에서는 모델을 서로 견주어 평가하고 비교 결과에서 순위를 계산한다. 같은 무용
  대회에 대해, 모든 후보에게 나란히 춤추게 하고 심사위원에게 어느 후보의 춤이 가장 마음에 드는지 물어
  가장 많은 심사위원이 선호한 무용수를 고를 수 있다** (3장, p.149).[^huyen2025]

## 왜 비교가 더 쉬운가

- **품질이 주관적인 응답에는 비교 평가가 통상 점별 평가보다 하기 쉽다. 예컨대 두 노래 중 어느 쪽이
  더 나은지 말하는 것이 각 노래에 구체적 점수를 주는 것보다 쉽다** (3장, p.149).[^huyen2025] 이는
  선호 데이터를 모을 때 레이블러에게 점수 대신 비교를 시키는 이유와 같다 —
  [선호 파인 튜닝](../concepts/preference-finetuning.md)이 그 자리다.

## AI에서의 계보

- **AI에서 비교 평가는 2021년 Anthropic이 서로 다른 모델의 순위를 매기는 데 처음 썼다. 이는 커뮤니티의
  쌍 모델 비교에서 계산된 점수로 모델의 순위를 매기는 인기 있는 LMSYS의 Chatbot Arena 리더보드를
  움직이는 방식이기도 하다** (3장, p.149).[^huyen2025]
- 제공자들의 프로덕션 — **많은 모델 제공자가 프로덕션에서 자기 모델을 평가하는 데 비교 평가를 쓴다.
  ChatGPT는 때때로 사용자에게 두 출력을 나란히 비교해 달라고 요청한다. 이 출력들은 서로 다른 모델이
  생성했을 수도, 같은 모델이 다른 샘플링 변수로 생성했을 수도 있다** (3장, p.149,
  Figure 3-10).[^huyen2025]
- 절차 — **각 요청에 대해 응답할 모델 둘 이상이 선택된다. 사람이거나 AI일 수 있는 평가자가 승자를
  고른다. 많은 개발자가 무승부를 허용하는데, 초안이 똑같이 좋거나 똑같이 나쁠 때 승자가 무작위로
  뽑히는 것을 피하기 위해서다** (3장, p.149).[^huyen2025]

## 선호로 답해서는 안 되는 질문

- 저자가 강조하는 경계 (3장, p.150):[^huyen2025]

  > A very important thing to keep in mind is that *not all questions should be answered by
  > preference*.

- 왜 그런가 — **많은 질문은 대신 정확성으로 답해져야 한다. 모델에게 "휴대폰 전자파와 뇌종양 사이에
  연관이 있는가?"라고 묻는데 모델이 "예"와 "아니오" 두 선택지를 제시하며 당신에게 고르라고 하는 것을
  상상해 보라. 선호 기반 투표는 잘못된 신호로 이어질 수 있고, 그 신호로 모델을 훈련하면 어긋난 행동을
  낳을 수 있다** (3장, p.150).[^huyen2025]
- 사용자를 좌절시킨다 — **사용자에게 고르라고 요청하는 것은 사용자 좌절을 일으킬 수도 있다. 답을 몰라서
  모델에게 수학 문제를 물었는데 모델이 서로 다른 두 답을 주면서 선호하는 것을 고르라고 하는 상황을
  상상해 보라. 올바른 답을 알았다면 애초에 모델에게 묻지 않았을 것이다** (3장, p.150).[^huyen2025]
- 통하는 자리 — **사용자로부터 비교 피드백을 모을 때 한 가지 난제는 어떤 질문이 선호 투표로 정해질 수
  있고 어떤 질문이 그래서는 안 되는지 판정하는 것이다. 선호 기반 투표는 투표자가 그 주제에 대해 잘 알
  때만 통한다. 이 접근은 일반적으로 AI가 인턴이나 조수 역할을 하며 사용자가 할 줄 아는 일을 빠르게 하도록
  돕는 애플리케이션에서 통하지, 사용자가 자기가 할 줄 모르는 일을 AI에게 시키는 자리에서는 통하지
  않는다** (3장, p.150).[^huyen2025]

## A/B 테스트와 다르다

- **비교 평가는 A/B 테스트와 혼동해서는 안 된다. A/B 테스트에서는 사용자가 한 번에 후보 모델 하나의
  출력을 본다. 비교 평가에서는 사용자가 여러 모델의 출력을 동시에 본다** (3장, p.150).[^huyen2025]

## 매치와 승률

- 매치 — **각 비교를 매치(match)라고 부른다. 이 과정은 일련의 비교를 낳는다** (3장, p.150, Table
  3-5):[^huyen2025]

  | Match # | Model A | Model B | Winner |
  |---|---|---|---|
  | 1 | Model 1 | Model 2 | Model 1 |
  | 2 | Model 3 | Model 10 | Model 10 |
  | 3 | Model 7 | Model 4 | Model 4 |
  | … | | | |

- 승률 — **모델 A가 모델 B보다 선호될 확률이 B에 대한 A의 승률(win rate)이다. A와 B 사이의 모든 매치를
  보고 A가 이긴 비율을 계산해 이 승률을 계산할 수 있다** (3장, p.150).[^huyen2025]
- 모델이 늘면 어려워진다 — **모델이 둘뿐이라면 순위를 매기는 것은 간단하다. 더 자주 이기는 모델이 더
  높은 순위다. 모델이 많을수록 순위 매기기는 더 어려워진다** (3장, p.150).[^huyen2025] 저자가 든
  다섯 모델의 실증적 쌍별 승률이다. **A >> B 열은 A가 B보다 선호되는 사건을 나타낸다** (3장, p.151,
  Table 3-6):[^huyen2025]

  | 모델 쌍 # | Model A | Model B | 매치 수 | A >> B |
  |---|---|---|---|---|
  | 1 | Model 1 | Model 2 | 1000 | 90% |
  | 2 | Model 1 | Model 3 | 1000 | 40% |
  | 3 | Model 1 | Model 4 | 1000 | 15% |
  | 4 | Model 1 | Model 5 | 1000 | 10% |
  | 5 | Model 2 | Model 3 | 1000 | 60% |
  | 6 | Model 2 | Model 4 | 1000 | 80% |
  | 7 | Model 2 | Model 5 | 1000 | 80% |
  | 8 | Model 3 | Model 4 | 1000 | 70% |
  | 9 | Model 3 | Model 5 | 1000 | 10% |
  | 10 | Model 4 | Model 5 | 1000 | 20% |

  **데이터만 보아서는 이 다섯 모델의 순위가 어떻게 매겨져야 하는지 명백하지 않다** (3장,
  p.150).[^huyen2025]

## 평점 알고리즘

- 무엇이 하는 일인가 — **비교 신호가 주어지면 평점 알고리즘(rating algorithm)이 모델의 순위를 계산하는
  데 쓰인다. 통상 이 알고리즘은 먼저 비교 신호에서 각 모델의 점수를 계산한 뒤 그 점수로 모델의 순위를
  매긴다** (3장, p.151).[^huyen2025]
- 다른 분야에서 빌려 왔다 — **비교 평가는 AI에서는 새롭지만 다른 산업에서는 거의 한 세기 동안 있어
  왔다. 특히 스포츠와 비디오 게임에서 인기가 있다. 이 다른 도메인에서 개발된 많은 평점 알고리즘이 AI
  모델 평가에 적응될 수 있으며 Elo·Bradley–Terry·TrueSkill이 그 예다. LMSYS의 Chatbot Arena는 원래
  모델 순위를 계산하는 데 Elo를 썼으나 나중에 Bradley–Terry 알고리즘으로 바꾸었는데, Elo가 평가자와
  프롬프트의 순서에 민감하다는 것을 발견했기 때문이다** (3장, p.151).[^huyen2025]
  - 각주가 남긴 잔재 — **Chatbot Arena가 Elo 평점 알고리즘 쓰기를 멈추었음에도 그 개발자들은 한동안
    자기 모델 평점을 계속 "Elo 점수"라고 불렀다. 그들은 Bradley–Terry 점수를 Elo 점수처럼 보이도록
    스케일링했다. 그 스케일링은 꽤 복잡하다. 각 점수에 400(Elo에 쓰이는 척도)을 곱하고 1,000(초기 Elo
    점수)을 더한다. 그런 다음 모델 Llama-13b가 800점을 갖도록 이 점수를 다시 스케일링한다** (3장,
    p.151 각주 23).[^huyen2025]

## 순위의 옳음은 예측력이다

- 정의 (3장, p.151):[^huyen2025]

  > A ranking is correct if, for any model pair, the higher-ranked model is more likely to win in
  > a match against the lower-ranked model.

  **모델 A가 모델 B보다 높은 순위라면 사용자는 절반이 넘는 시간 동안 B보다 A를 선호해야 한다** (3장,
  p.151).[^huyen2025]
- 그래서 예측 문제다 — **이 렌즈로 보면 모델 순위 매기기는 예측 문제다. 우리는 과거 매치 결과에서 순위를
  계산하고 그것으로 미래 매치 결과를 예측한다. 서로 다른 순위 알고리즘은 서로 다른 순위를 낼 수 있고,
  올바른 순위가 무엇인지에 대한 정답은 없다. 순위의 품질은 그것이 미래 매치 결과를 예측하는 데 얼마나
  좋은가로 정해진다. Chatbot Arena의 순위에 대한 저자의 분석은, 최소한 충분한 매치를 가진 모델 쌍에
  대해서는 생성된 순위가 좋음을 보인다. 분석은 책의 GitHub 저장소에 있다** (3장, p.151).[^huyen2025]

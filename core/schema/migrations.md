# 스키마 변경 로그

append-only. `schema/*.yaml`이 **현재** 스키마이고, 이 파일이 **해석**을 제공한다.
파일마다 `schema_version`을 적지 않는 이유가 여기 있다 — 콘텐츠 파일은 재작성되지
않으므로 그 필드는 시간이 지나면 거짓말을 한다. 대신 git 커밋 날짜 + 이 로그가
"이 파일이 쓰이던 시점의 스키마"를 복원한다(PLAN §2.7).

## 호환 정책 — BACKWARD_TRANSITIVE

1. **additive만.** 새 optional 필드는 안전하다. 의미론 변경은 O(N)이므로 금지.
2. **in-place 개명 금지.** 새 키를 추가하고, 아래 로그에 구→신 매핑을 남기고,
   필요하면 backfill한다. 기존 키를 조용히 바꾸지 않는다.
3. **은퇴 키 이름은 영구 결번.** 재사용하면 과거 파일의 같은 이름이 다른 의미가 된다.
4. **변경 전 `tools/affected` 실행**(PLAN §6 운영 캘린더 "수시"). 영향 범위는 기억이
   아니라 조회가 답한다.

집행: `tools/validate`가 아래 결번 대장을 읽어 현재 스키마와 신규 파일에 결번 키가
등장하지 않는지 대조한다. 산문 규칙이 지켜진다고 가정하지 않는다.

## 결번 대장

`tools/validate`가 파싱하는 표다(markdown-it-py AST — 열 순서 고정). 비어 있어도 표는 남긴다.

## 로그

### 2026-08-05 — 초기 스키마

첫 파일 작성 전 동결 코어(PLAN §2.7)를 기계화했다. 구→신 매핑 없음(선행 상태 없음).

- `layout.yaml` — 저장소 경계 정본: 공유 자산 화이트리스트 / KB 골격·디렉터리↔type
  정합 / 색인 포함·제외 패턴.
- `common.yaml` — 공유 `$defs`. 크로스 파일 `$ref`는 상대 `$id`로 해결(jsonschema
  4.26.0 + referencing 0.37.0 실측).
- `concept.yaml` · `synthesis.yaml` · `redirect.yaml` · `guide.yaml` · `source.yaml` —
  계층(=PLAN §2.3 "파일 종류")당 스키마 1개.
- `vocabulary.yaml` — 본문 epistemic 폐쇄 어휘. JSON Schema 아님, 소비자는 lint.
- `user-dict.yaml` — Kiwi 사용자 사전. 항목은 비어 있다(파편화 검출이 채운다).

기록해 둘 판단 3가지:

1. **소스 계층을 CSL 타입 10개 파일로 쪼개지 않았다.** CSL 공식 `csl-data.json`이
   45개 타입을 단일 스키마 + `type` enum으로 다루고 타입별 required 차등을 선언하지
   않는다(전역 `required: [type, id]`). PLAN §2.2가 enum을 차용한 출처의 관행을 따랐다.
2. **`issued`를 스칼라 문자열로 고정했다.** CSL 원형은 `{date-parts: [[2017]]}` 객체다.
   PLAN §2.1의 "날짜 값은 따옴표 문자열" 규약과 한 표현으로 맞췄고, CSL 스펙 설명문
   자체가 EDTF 문자열을 preferred로 명시한다. Zotero/pandoc 상호운용 시 변환이 필요하다
   — 다만 `snapshot`·`snapshot_sha256` 확장 필드가 이미 CSL 밖이라 변환은 어차피 발생한다.
3. **`number`를 문자열 전용으로 좁혔다.** CSL은 `string|number`지만 따옴표 없는 arXiv ID
   `2405.14831`이 YAML에서 float로 파싱돼 식별자가 조용히 손상된다. 스키마가 그 실수를
   fail-loud로 잡게 했다.
4. **`redirect.superseded_by`가 citekey 형태도 받는다.** `sources/`의 스텁은 슬러그가
   아니라 citekey를 가리키는데 citekey는 `-2` 숫자 접미를 허용한다(동일 저자·연도 충돌).
   슬러그 문법만 받으면 그런 소스는 rename 자체가 불가능해진다. 디렉터리별 정밀도는
   validate의 관계 규칙이 맡는다. (rename 구현 중 발견 — 콘텐츠 0개 시점이라 무비용 수정.)

### 2026-08-10 — 본문 규약 성문 (계약 감사)

`schema/*.yaml` 변경 없음 — frontmatter가 아니라 **본문 구조 규약**의 성문이라
소비자는 validate가 아니라 kb-lint다(vocabulary.yaml과 같은 관할). 전수 감사
(PLAN §8 "계약 감사" 원장)에서 관례로만 존재하던 형식들이 검사와 표류하고
있음이 실측돼(toc-missing 13건 전건 오검출) 계약으로 승격했다.

- **TOC 형식 정본** = `**목차**: …` 인라인 문단 (PLAN §2.6). 불릿 목록형 인정.
- **허브·overview 링크 불릿 문법** = `- [제목](경로) — 한 줄 설명` (PLAN §2.6).
  본문 YAML 온톨로지 블록은 불채택(PLAN §6 — LLM 실측 12시행 동률 + 링크 그래프
  불인식).
- **claim 검사 단위** = 하위 열거 불릿은 부모 불릿의 각주를 상속 (PLAN §2.1).
- **locator 형식** = 각주 라벨 직전 괄호, 문장 구두점 개재 허용 (PLAN §4.4-4).
  검사는 괄호 존재까지만.
- 매트릭스의 본문 "문자집합" 검사는 정의 규약 부재로 삭제 — 파일명 문자집합은
  validate가 계속 담당.

### 2026-08-10 — contradicts 의미 한정 (스키마 변경 없음)

필드 자체는 그대로다. `concept.yaml`의 `contradicts` 정의에 **적용 대상 한정**을
주석으로 명시했다: 사실 주장의 충돌(최대 하나만 참)만 대상이고, 방법론이나 설계
트레이드오프는 대상이 아니다.

발단은 첫 실사용의 오용이다(런 2026-08-10-03). Kimball의 적재 전 정제와 Kleppmann의
스시 원칙을 `contradicts`로 걸었는데, 이것은 상황이 고르는 트레이드오프이지 하나가
참인 문제가 아니다. 다른 한 쌍(원시 데이터 전량 보관 대 데이터 최소화)은 대상마저
달랐다 — 감사용 업무 데이터와 GDPR이 규율하는 개인 데이터.

기존 필드의 의미론이 이 한정을 이미 함축하고 있었다: PLAN §2.1이 해소 시 "대체된
주장"을 기록하라고 요구하는데, 대체가 일어나지 않는 쌍은 큐에 영구 상주해 큐를
죽인다. 그래서 의미 변경이 아니라 성문이고 BACKWARD_TRANSITIVE 를 건드리지 않는다.

트레이드오프의 행선지는 synthesis 다 — 판단의 계층이 "언제 어느 쪽인가"를 담당한다.
concepts 는 양쪽 주장을 각주와 함께 병기만 한다.

### 2026-08-11 — 수식 표기 성문 (스키마 변경 없음)

`schema/*.yaml` 무변경. frontmatter가 아니라 **본문 표기 규약**이라 소비자는 kb-lint다
(vocabulary.yaml·TOC 형식과 같은 관할).

논문 반입(첫 논문 = Raft)에서 수식이 처음 들어왔는데 규약이 없었다. 리서치와 로컬
실측으로 세 자리를 갈랐다(SCHEMA.md §3):

- **문장 속 기호** = 유니코드 + 이름 병기(필수). 병기가 필수인 이유는 형태소 레그가
  기호를 버리기 때문이다 — 실측: `a ≪ b 이고` → 토큰 `a`, `b`. `≪`만이 아니라
  `α`·`ℝ`도 사라진다(POS 필터가 SL/SH/SN만 통과). `x²`는 통짜라 `x`로 못 찾는다.
- **여러 줄·백슬래시** = ` ```math ` 펜스. 본문에 그냥 쓰면 CommonMark §2.4가
  백슬래시를 먹는다(15표본 중 8개 손상). **인용 블록은 보호하지 못한다** — 컨테이너
  블록이라 인라인 파싱이 그대로 적용된다. 펜스는 순정 CommonMark라 방언 무변경.
- **`$…$` 금지** + lint 검출. 어느 스펙에도 없다(CommonMark·GFM 스펙·cmark-gfm 부재).

lint 판별은 pandoc MANUAL의 세 조건(여는 `$` 오른쪽 비공백, 닫는 `$` 왼쪽 비공백,
닫는 `$` 오른쪽 비숫자)을 그대로 쓴다. 이 저장소는 이미 `$`를 통화로 쓰고 있어
(`snapshot-fact-tables`·`slowly-changing-dimension`) 판별이 필요했고, 실측에서
전 코퍼스 오탐 0건이다.

부수 규약: NFC 고정·NFKC 금지(UTR#25 §2.2 "should never be used with mathematical
texts" — NFKC가 `𝔼→E`, `ℝ→R`, `²→2`로 의미를 파괴), 표 안은 `\|`/`‖`, 2D 레이아웃은
표현하지 않고 archive 스냅샷에 맡긴다.

### 2026-08-11 — `stale_after` 적용 범위 명문화 (의미 불변, 오용 차단)

필드 정의는 그대로다(PLAN §2 "유효성" = 유효 기간의 끝, 공표된 날짜만). 바뀐 것은
**어디에 달면 안 되는지**를 스키마 주석에 적은 것이다.

- **버전으로 갈리는 지식에는 달지 않는다.** "Kafka 3.9 이하에서는 이렇다"는 날짜가
  지나도 거짓이 되지 않는다 — 3.x를 운영하는 동안 계속 참이므로 유효 기간의 끝이
  존재하지 않는다. 새 버전이 나온 날은 지식이 거짓이 된 날이 아니라 **경계가 어디인지
  확인된 날**이고, 그 경계는 `버전 조건`이 담는다.
- 실오용 3건(`zookeeper-and-kraft`·`brokers-and-clusters`·`low-latency-collectors`,
  전부 `2025-03-18`)이 이 판정으로 걷혔다. 셋 다 릴리스일을 만료일로 적은 것이었고,
  날짜가 지난 채 재검토 큐에 영구 상주하고 있었다.
- 유효한 자리는 그대로다: 날짜가 지나면 **어느 버전 관점에서도** 거짓이 되는 것
  (벤더 EOL·지원 종료 공표). 그런 날짜가 없으면 비운다 — 부재 = 만료 없음.

외부 정합(2026-08-11 조사): 산문 인라인 버전 표기는 Google 스타일 가이드·HashiCorp·
Kubernetes가 모두 억제 대상으로 명시(사유 일치 — "흩어지면 갱신 불가"). 프론트매터
버전 스코프 키는 **빌드 리졸버가 있는 저장소에만** 존재하고 순수 md 저장소는 전수
부재(GitLab 핸드북·Basecamp·Oxide RFD·kubernetes/community). 만료 배너는 실측으로
무시되며(영국 DBT 사용자 조사) 긍정형 "마지막 검증일·다음 예정일"이 신뢰를 얻는다.

### 2026-08-12 — 코드 표기 성문 (인라인 색인 / 펜스 색인 제외)

코드 규약이 아예 없어서 첫 저작자의 습관이 규약 노릇을 하고 있었다. 실측 결과
개념 페이지 89개 중 펜스 **0건**, 인라인 백틱 **549건**이었다. 금지 조항이 있어서가
아니라 첫 소스가 코드 없는 DW 서적이라 그 모양이 굳은 것이다(수식 때와 같은 부류).

- **인라인 백틱 = 색인.** 문장의 일부이므로 claim과 같이 다룬다. `-XX:+PrintGCDetails`
  는 `XX`·`PrintGCDetails`로 색인된다(기호 탈락은 수식과 동형).
- **펜스 = 색인 제외, 원문 보존.** `mdfile.fences`(AST)로 빼내고 `raw`에는
  남긴다. HTML 블록 처리와 대칭이되 **원문에서는 지우지 않는다**는 점만 다르다.
- **출처 필수.** 펜스는 반입한 소스에 실제로 있는 코드여야 하고 각주 달린 claim
  아래에서 각주를 상속한다. 지어낸 코드는 예제가 아니라 발명한 claim이다 — 산문
  claim에 각주를 의무화한 것과 같은 이유다. 깎는 편집은 허용, 없는 줄을 보태는 것은
  금지(깎았으면 각주에 명시).
- **개수는 개념당 하나.** few-shot 실증(5–25 구간 최고점, many-shot 역설) + 벤더
  지침(3–5) + O'Reilly Media "significant portion" 예외가 전부 선별을 가리킨다.
- **펜스 앞 산문 한 줄 필수** + 버전 조건 대상.

기각한 대안: **FTS5 컬럼 분리 + 가중치**(`bm25(morph,…,1.0,0.1)`). SQLite 공식 문서에
있는 기제이고 처음 세운 안이었으나 **실측에서 효과 0**이었다 — 길이 정규화의 `D`가
컬럼별이 아니라 행 전체 토큰 수라, 컬럼을 나눠도 분모가 그대로다. 코드 전용 FTS
테이블도 지금은 불채택(소비자 0 — `rg`·qmd가 이미 담당). 자세한 실측은 PLAN §8.

부칙(같은 날): 위 "출처 필수"를 산문 권고에서 **lint 검사**로 올렸다(`code-unsourced`,
warn). 판정 근거는 AST의 불릿 각주 스택이며, 각주 상속 규칙(§2.1)을 claim 검사와
**같은 순회**에서 읽는다 — 따로 걸으면 상속 규칙이 둘로 갈린다. 기계가 보는 것은
**소속뿐**이다: 펜스가 각주 단 불릿 안에 있는가. 그 코드가 정말 그 소스에서 왔는지,
깎기만 했는지는 기계 밖이고 승급 리뷰가 담당한다. 펜스 0건인 지금 켜서 소급 정리를
없앴다.

부칙 2 (2026-08-12): **펜스는 복사해서 돌아가야 한다**를 §3에 명시했다. 발단은 13장
반입의 실물이다 — 책의 예제를 원문 그대로 옮겼더니 루트 프롬프트 `#`가 `sh` 펜스에서
주석이 되어 **명령 전체가 죽었고**, 지면 폭 때문에 접힌 둘째 줄은 이음 문자가 없어
별개 명령이 됐다. 원문 충실성은 지켰으나 펜스의 정의를 어긴 것이다. 따라서 프롬프트
제거와 줄 잇기는 **깎기로 보아 허용**하고(이음 문자 `\`는 접힌 줄을 되돌리는 표기이지
보태기가 아니다), **출력 예시는 `text` 펜스로 갈라** 명령 펜스가 복사 가능하게 둔다.
12장 반입이 이미 같은 처리를 하고 있었으므로 성문이 관행을 뒤따른 것이다.
